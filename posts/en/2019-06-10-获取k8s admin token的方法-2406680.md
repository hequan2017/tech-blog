> **About this post**
>
> Logging in to the Kubernetes Dashboard or calling the API requires a highly privileged token. This post shows how to create a ServiceAccount named dashboard-admin, bind it to the cluster-admin role, and then extract the token from the automatically generated Secret. Three steps: create the YAML and apply it, find the corresponding Secret name, and run describe to view the token content.

> **Technical notes**
>
> ① The apiVersion of the ClusterRoleBinding in this post was lost during content collection; it should be `rbac.authorization.k8s.io/v1beta1` (that version was removed in Kubernetes 1.22; use `rbac.authorization.k8s.io/v1` today). ② Since Kubernetes 1.24, ServiceAccounts no longer automatically create token Secrets; you need to manually create a Secret of type `kubernetes.io/service-account-token`, or use `kubectl create token dashboard-admin -n kube-system` to obtain a short-lived token. ③ Binding cluster-admin grants extremely broad privileges; in production, grant permissions following the principle of least privilege.

---

### 1. Create first

```shell
vim k8s-admin.yaml
```

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: dashboard-admin
  namespace: kube-system
---
kind: ClusterRoleBinding
apiVersion: rbac.authorization.k8s.io/v1beta1  # Note: the apiGroup here was lost during collection of the original; for K8s 1.22+, use rbac.authorization.k8s.io/v1 instead
metadata:
  name: dashboard-admin
subjects:
  - kind: ServiceAccount
    name: dashboard-admin
    namespace: kube-system
roleRef:
  kind: ClusterRole
  name: cluster-admin
  apiGroup: rbac.authorization.k8s.io  # Note: lost during collection of the original; this value should be added back
```

```shell
kubectl apply -f k8s-admin.yaml
```

### 2. Get the name

```shell
kubectl get secret -n kube-system
NAME                                             TYPE                                  DATA   AGE
dashboard-admin-token-dhhmc                      kubernetes.io/service-account-token   3      69s
```
