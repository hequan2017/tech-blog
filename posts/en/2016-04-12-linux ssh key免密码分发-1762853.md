> **About this post**
>
> This post is a hands-on demonstration of SSH key-based passwordless login and
> data distribution: after creating the hequan user, it uses ssh-keygen to
> generate a DSA key, then ssh-copy-id to distribute the public key to the
> target machine and verify passwordless ssh / scp; it then covers scp -rp for
> copying files and directories in both directions, tuning slow connections by
> turning off UseDNS and GSSAPIAuthentication, and a shell script for batch
> distribution. Finally it solves the permission problem of batch distribution
> with three options: authorizing sudo cp via visudo, adding the suid bit to
> rsync, and using root directly.

> **Technical notes**
>
> - The environment in this post is CentOS 6. DSA keys (ssh-dss) have been
>   disabled by default since OpenSSH 7.0; nowadays generate keys with
>   `ssh-keygen -t rsa` or `-t ed25519` instead.
> - `passwd --stdin` is only supported on RHEL/CentOS; Debian/Ubuntu needs
>   `chpasswd`. Batch public-key distribution is now usually done together with
>   tools such as sshpass or ansible.
> - Adding the suid bit to rsync is a stopgap; excessively broad permissions
>   are a security risk. In production, prefer fine-grained sudoers
>   authorization (option 2, the one recommended in this post).

## 1. Requirements and Preparation

The specific requirement: under the same user **hequan**, machine A distributes data to machine B from local, and no password prompt appears during the process.

Create the user:

```shell
# useradd hequan
# id hequan
# echo 123456 | passwd --stdin hequan
# su - hequan
```

A note on the key algorithms: RSA supports both encryption and digital signatures; DSA can only be used for digital signatures.

## 2. Creating the Key Pair

```shell
[hequan@A ~]$ ssh-keygen -t dsa       # RSA is generated by default without -t
```

```text
Generating public/private dsa key pair.
Enter file in which to save the key (/home/hequan/.ssh/id_dsa):
Created directory '/home/hequan/.ssh'.
Enter passphrase (empty for no passphrase):
```

Look at the generated keys (keep the private key, distribute the public key):

```shell
[hequan@A ~]$ ll -l .ssh/
总用量 8
-rw------- 1 hequan hequan 668 3月  28 04:07 id_dsa          # private key, keep it
-rw-r--r-- 1 hequan hequan 598 3月  28 04:07 id_dsa.pub      # public key, distribute it

[hequan@A ~]$ ll -ld .ssh/
drwx------ 2 hequan hequan 4096 3月  28 04:07 .ssh/
```

## 3. Distributing the Public Key and Verifying

Format: `ssh-copy-id [-i [identity_file]] [user@]machine`

```shell
[hequan@A ~]$ ssh-copy-id -i .ssh/id_dsa.pub hequan@192.168.10.11   # distribute
Are you sure you want to continue connecting (yes/no)? yes
```

```text
  .ssh/authorized_keys
to make sure we haven't added extra keys that you weren't expecting.
```

On machine B, confirm that the public key has been written:

```shell
[hequan@B ~]$ ll -l .ssh/
-rw------- 1 hequan hequan 598 4月   4 04:49 authorized_keys
```

Verify the passwordless login:

```shell
[hequan@A ~]$ ssh hequan@192.168.10.11      # no password needed
[hequan@B ~]$
```

## 4. Distributing Files and Directories with scp

Test sending a file:

```shell
[hequan@A ~]$ echo hequan > hequan.txt
[hequan@A ~]$ scp hequan.txt hequan@192.168.10.11:~
```

Copying directories in both directions:

```shell
[hequan@A ~]$ scp -rp /etc/ hequan@192.168.10.11:~             # send the directory to ~
[hequan@A ~]$ scp -rp hequan@192.168.10.11:~/etc/ /tmp/        # copy B's /etc/ to local /tmp
```

## 5. Tuning Slow Connections

If ssh is particularly slow during testing, change the following parameters:

```shell
# vi /etc/ssh/sshd_config
```

```ini
UseDNS no
GSSAPIAuthentication no
```

```shell
# /etc/init.d/sshd restart
```

## 6. Summary of Passwordless Login

- Passwordless authentication is **one-way**;
- It is **user-based**; try not to cross users;
- Slow connections (see the fix above);
- In batch distribution, the password must still be entered once the first time, and the first connection requires confirmation (expect can solve this).

Debugging command:

```shell
[root@A ~]# ssh -v root@192.168.10.11     # -v debugs the entire connection process
```

## 7. Batch Distribution Test Script

```shell
#!/bin/sh
if [ $# -ne 1 ]
then
    echo "/bin/sh $0 arg1"
    exit 1
fi
for n in 11
do
    scp -rp $1 hequan@192.168.10.$n:~;
done
```

## 8. The Permission Problem of Batch Distribution

An ordinary user has no permission to write directly to remote system directories; there are three ways to solve this.

Option 1: use root.

Option 2: use visudo (recommended; the original text recommends option 2):

```shell
# visudo
hequan ALL=(ALL) NOPASSWD:/bin/cp

# visudo -c
/etc/sudoers：解析正确
```

When running sudo remotely, watch out for `Defaults requiretty` in the sudoers file (or comment that line out):

```text
# Disable "ssh hostname sudo <cmd>", because it will show the password in clear.
#         You have to run "ssh -t hostname sudo <cmd>".
Defaults    requiretty
```

Usage:

```shell
$ scp -rp quan hequan@192.168.10.11:~                  # first copy quan to the home directory
$ ssh hequan@192.168.10.11 -t sudo /bin/cp ~/quan /tmp # then copy quan to /tmp, using root privileges
```

Option 3: use rsync (add the suid bit so it gets root privileges):

```shell
# chmod u+s `which rsync`       # suid
-rwsr-xr-x 1 root root 415000 10月 31 2013 /usr/bin/rsync
```

```shell
ssh hequan@192.168.10.11 /usr/bin/rsync ~ /yy /tmp
```

Summary: the permission problem of batch distribution — use root, use visudo (recommended), or use rsync.
