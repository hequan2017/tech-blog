## 1. Regular Expressions

### 1.1 Concept

A regular expression, also known as a rule expression. It describes matching rules.

### 1.2 Basic Syntax

```python
import  re  ## import the module
m = re.match("abc","abcdefghi")
x = re.match("abc","bcdefghi")
print(m)
print(x)
print(m.group())
```

```text
<_sre.SRE_Match object; span=(0, 3), match='abc'>    ## object 匹配上了
None   ## 无匹配
abc    ## .group 匹配的内容
```

### 1.3 Matching Formats

- `^`: Matches the beginning of the string
- `$`: Matches the end of the string
- `.`: Matches any character except a newline; when the re.DOTALL flag is specified, it matches any character including a newline.
- `[...]`: Represents a set of characters, listed individually: [amk] matches 'a', 'm', 'k'
- `[^...]`: Characters not in []
- `re*`: Matches 0 or more occurrences of the preceding expression
- `re+`: Matches 1 or more occurrences of the preceding expression
- `re?`: Matches 0 or 1 occurrence of the fragment defined by the preceding regex; non-greedy mode
- `re{n}`: Matches exactly n occurrences of the preceding expression
- `re{n,}`
- `a|b`: Matches a or b
- `(re)`: Matches the expression inside the parentheses; also denotes a group
- `(?imx)`: The regex carries the three optional flags i, m, x, affecting only the region inside the parentheses
- `(?-imx)`: Turns off the imx flags for the regex
- `(?:re)`: Like `(...)`, but does not denote a group
- `(?imx:re)`: Uses the imx optional flags inside the parentheses
- `(?-imx:re)`: Does not use the imx optional flags inside the parentheses
- `(?#...)`: Comment
- `(?=re)`: Positive lookahead delimiter
- `(?!re)`: Negative lookahead delimiter
- `(?>re)`: Independent pattern match
- `\w`: Matches alphanumerics `[A-Za-z0-9_]`
- `\W`: Non-alphanumerics `[^A-Za-z0-9]`
- `\s`: Any whitespace character `[\f\n\r\t\v]`
- `\S`: Any non-whitespace character `[^\f\n\r\t\v]`
- `\d`: Any digit `[0-9]`
- `\D`: Any non-digit `[^0-9]`
- `\A`: Beginning of string
- `\Z`: End of string; matches only up to the end before a trailing newline
- `\z`: End of string
- `\G`: Position where the last match finished
- `\b`: A word boundary
- `\B`: Not a word boundary
- `\n`, `\t`: A newline character, a tab character
- `\1..\9`: The nth group's subexpression
- `\10`: Matches the nth group's subexpression if it has already matched; otherwise it refers to the expression for the octal character code.

### 1.4 The 5 Common Operations

```python
re.match(pattern,string)    ## match from the beginning
re.search(pattern,string)   ## scan the whole string until a match is found
re.split()                  ## split the string into a list, using matches as separators
re.findall()                ## find all matches and return them as a list
re.sub(pattern,repl,string,count,flag)   ## replace matched characters
```

Example:

```python
>>> m = re.split("[0-9]", "alex1rain2jack3helen rachel8")
>>> print(m)
['alex', 'rain', 'jack', 'helen rachel', '']
>>> m = re.findall("[0-9]", "alex1rain2jack3helen rachel8")
>>> print(m)
['1', '2', '3', '8']
>>> m = re.sub("[0-9]","|", "alex1rain2jack3helen rachel8", count=2)
>>> print(m)
alex|rain|jack3helen rachel8
```

Note — the difference between re.match and re.search:

- re.match matches only at the beginning of the string; if the string does not start with the pattern, the match fails.
- re.search scans the whole string until it finds a match.

### 1.5 Character Matching

| Pattern | Matches |
| --- | --- |
| python | python |
| [Pp]thon | Python, python |
| rub[ye] | ruby, rube |
| [aeiou] | Any one of the letters inside the brackets |
| [0-9] | Any digit |
| [a-z] | Any lowercase letter |
| [A-Z] | Any uppercase letter |
| [a-zA-Z0-9] | Any letter or digit |
| [^aeiou] | All characters except aeiou |
| [^0-9] | Characters other than digits |

### 1.6 The compile Format

```python
p = re.compile("^[0-9]")
m = p.match('14534Abc')
```

The difference is that the first approach pre-compiles the pattern to be matched (parses the matching formula), so it does not have to be compiled again when matching; the second shorthand re-compiles the matching formula on every match. So if you need to match all lines starting with a digit in a 50,000-line file, it is recommended to compile the regex first and then match — it will be faster.

```python
match.group('first')
```


## 2. Bubble Sort

Sort an irregular array in ascending order:

```python
data = [10,4,33,21,54,3,8,11,5,22,2,1,17,13,6]
for j in range(1,len(data)):
    for i in range(len(data)-j):   ## -j: after each pass the largest value has reached the end, so compare only the remaining front part.
        if data[i] > data[i+1]:    ## compare 10 and 4
            tmp = data[i+1]        ## tmp=4
            data[i+1] = data[i]    ## 4 becomes 10
            data[i] = tmp          ## 10 becomes 4
print(data)
```

## 3. Time Complexity

**(1) Time frequency** The time consumed by an algorithm's execution cannot, in theory, be computed; it can only be known by running it on a machine. But it is neither possible nor necessary to test every algorithm this way; it suffices to know which algorithm takes more time and which takes less. Moreover, the time an algorithm takes is proportional to the number of times its statements execute: the more times the statements in an algorithm execute, the more time it takes. The number of statement executions in an algorithm is called the statement frequency or time frequency, denoted T(n).

**(2) Time complexity** In the time frequency mentioned above, n is called the scale of the problem; as n keeps changing, the time frequency T(n) keeps changing too. But sometimes we want to know what pattern the change follows. To this end, we introduce the concept of time complexity. In general, the number of times the basic operations in an algorithm are repeated is some function of the problem size n, denoted T(n). If there exists an auxiliary function f(n) such that the limit of **T(n)/f(n)** as n approaches infinity is a nonzero constant, then f(n) is said to be a function of the same order of magnitude as T(n), denoted **T(n)=O(f(n))**, and **O(f(n))** is called the asymptotic time complexity of the algorithm, or simply time complexity.

### 3.1 Exponential Time

It refers to a problem whose required [computation time](https://zh.wikipedia.org/wiki/%E8%A8%88%E7%AE%97%E6%99%82%E9%96%93) *m*(*n*) grows [exponentially](https://zh.wikipedia.org/wiki/%E6%8C%87%E6%95%B8) with the size of the input data (that is, if the amount of input data grows [linearly](https://zh.wikipedia.org/wiki/%E7%B7%9A%E6%80%A7), the time spent will grow exponentially):

```c
for (i = 1; i <= n; i++)
    x++;
for (i = 1; i <= n; i++)
    for (j = 1; j <= n; j++)
        x++;
```

The first for loop has time complexity Ο(n), the second for loop has time complexity Ο(n²), so the whole algorithm has time complexity Ο(n+n²)=Ο(n²).

### 3.2 Constant Time

If for an algorithm its upper bound is independent of the input size, it is said to have **constant time**, denoted O(1) time. One example is accessing a single element in an [array](https://zh.wikipedia.org/wiki/%E6%95%B0%E7%BB%84), because accessing it requires only one [instruction](https://zh.wikipedia.org/wiki/%E6%8C%87%E4%BB%A4). Finding the smallest element in an unordered array, however, is not, because all elements must be traversed to find the minimum; that is a linear-time operation, or O(n) time. But if the number of elements is known in advance and assumed to remain constant, the operation can also be said to have constant time.

### 3.3 Logarithmic Time

An algorithm is said to have logarithmic time if its *T*(*n*) = O(log *n*).

Common algorithms with logarithmic time include operations on [binary trees](https://zh.wikipedia.org/wiki/%E4%BA%8C%E5%8F%89%E6%A0%91) and [binary search](https://zh.wikipedia.org/wiki/%E4%BA%8C%E5%88%86%E6%90%9C%E7%B4%A2).

Algorithms with logarithmic time are very efficient, because each additional input requires less extra computation time.

Recursively halving a string and printing it is a simple example of this class of function. It takes O(log n) time, because we halve the string before each output. This means that if we want to increase the number of outputs, we need to double the length of the string.

### 3.4 Linear Time

If an algorithm's time complexity is O(*n*), the algorithm is said to have linear time, or O(*n*) time. Informally, this means that for sufficiently large inputs, the running time grows linearly with the input. For example, a program that computes the sum of all elements of a list takes time proportional to the length of the list.
