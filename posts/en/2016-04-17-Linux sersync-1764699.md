> **About this post**
>
> This post introduces sersync, a real-time synchronization tool built on
> inotify. It first compares the Rsync+Inotify-tools and Rsync+sersync
> architectures: sersync records the specific names of the files or
> directories that changed, and rsync transfers only the changed parts, which
> is more efficient for large data volumes. It then demonstrates installing
> sersync2.5.4 and the key confxml.xml settings (the localpath watched
> directory, the remote target IP and module name, commonParams, auth
> authentication, and the crontab scheduled full sync), along with autostart
> on boot, a process-guard check script (launched by crontab every 5 minutes),
> and the common -d/-r/-o startup parameters.

> **Technical notes**
>
> sersync2.5.4 (released in 2011) is the last release of the project, which
> has long been unmaintained since; for new environments, consider
> alternatives such as lsyncd. The sersync2 used in this post is a
> precompiled 64-bit binary that works as soon as it is extracted. CentOS 6
> reached EOL in November 2020; on newer systems, commands such as
> `service crond reload` should be replaced with `systemctl reload crond`.

## 1. Introduction to sersync and Architecture Comparison

1. sersync is developed on top of Inotify and is a tool similar to Inotify-tools
2. sersync can record the name of the specific file or directory that changed (including additions, deletions, and modifications) in the watched directory, so when it uses rsync to sync, only the changed file or directory is synced.

What is the difference between the Rsync+Inotify-tools and Rsync+sersync architectures?

### Rsync+Inotify-tools

1. Inotify-tools can only record that the watched directory changed (including additions, deletions, and modifications); it does not record which specific file or directory changed.
2. When syncing, rsync does not know which specific file or directory changed, so it syncs the entire directory every time. When the data volume is large, syncing the whole directory is very time-consuming (rsync has to traverse the entire directory to find and compare files), so the efficiency is low.

### Rsync+sersync

1. sersync can record the name of the specific file or directory that changed (including additions, deletions, and modifications) in the watched directory.
2. When syncing, rsync only syncs the changed file or directory (the data that changes each time is small relative to the entire synced directory, so rsync's traversal and comparison is fast), so the efficiency is high.

Summary: when the data volume of the synced directory is small, Rsync+Inotify-tools is recommended; when the data volume is large (several hundred GB or even over 1 TB) and there are many files, Rsync+sersync is recommended.

## 2. Installation and Configuration

```shell
tar zxvf sersync2.5.4_64bit_binary_stable_final.tar
mv GNU-Linux-x86 /usr/local/sersync     # the original post mistakenly writes "GUN-linux x86"
cd /usr/local/sersync                   # enter the sersync installation directory
cp confxml.xml confxml.xml-bak          # back up the original file
vi confxml.xml                          # edit and change the settings below
```

The settings that need to be changed:

```xml
<localpath watch="local directory">
    <remote ip="destination IP" name="module name"/>
</localpath>

<commonParams params="-artuz"/>

<auth start="true" users="username" passwordfile="password file"/>

<crontab start="true" schedule="600"/>
```

Note: when crontab is set to true, a full sync runs every 600 minutes (schedule, in minutes).

## 3. Run Automatically at Boot

```shell
vi /etc/rc.d/rc.local
```

Add the following line at the end (save and exit with :wq!):

```shell
/usr/local/sersync/sersync2 -d -r -o /usr/local/sersync/confxml.xml
```

## 4. Manual Sync and the Guard Script

Manual sync:

```shell
cd /usr/local/sersync
./sersync2 -r
```

Process guard check script (the original post does not give the script file name; /home/sh/sersync.sh is used as an example below):

```shell
vi /home/sh/sersync.sh
```

```shell
#!/bin/sh
sersync="/usr/local/sersync/sersync2"
confxml="/usr/local/sersync/confxml.xml"
status=$(ps aux | grep 'sersync2' | grep -v 'grep' | wc -l)
if [ $status -eq 0 ];
then
    $sersync -d -r -o $confxml &
else
    exit 0;
fi
```

After saving the script, make it executable and add it to crontab so it is checked every 5 minutes:

```shell
chmod +x /home/sh/sersync.sh
vi /etc/crontab     # edit and add the following line at the end
```

```shell
*/5 * * * * root /home/sh/sersync.sh > /dev/null 2>&1   # run the script every 5 minutes
```

```shell
service crond reload   # reload the service
```

## 5. Common Startup Parameters

Start the sersync daemon on the master server so that sersync runs in the background and real-time sync begins:

```shell
./sersync2 -d
```

Before enabling real-time monitoring, perform a full one-time sync between the master server's directory and the remote target's directory:

```shell
./sersync2 -r
```

Specify a configuration file:

```shell
./sersync2 -o XXXX.xml
```
