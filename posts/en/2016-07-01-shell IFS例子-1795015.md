> **About this post**
>
> This post uses two small scripts to demonstrate the use of IFS (the Internal Field Separator) in Bash: first, it splits `A="aa:bb:cc:dd"` on colons and uses a loop counter to pick out the 4th field, `dd`; then it splits an `/etc/passwd`-style line on colons to extract the username (1st field) and the login shell (7th field), while also demonstrating the proper practice of backing up IFS first and restoring it afterwards.

> **Technical notes**
>
> The IFS mechanism is still effective in Bash 5.x (the mainstream version in 2026), and the code in this post still runs. A more modern approach, however, is to split a line into variables in one shot with `IFS=: read -r a b c d <<< "$line"`, or to extract fields with the parameter expansion `${line%%:*}`, avoiding the side effects of modifying the global IFS; `let i++` can be replaced with the more portable `((i++))`.

---

## 1. What Is IFS

IFS (Internal Field Separator) is the set of separator characters the shell uses for field splitting; by default it consists of space, tab, and newline. Once the `IFS` variable is modified, unquoted variable expansions such as `for B in $A` split the string into fields on the new separator.

The following example splits `aa:bb:cc:dd` on colons; when the loop counter reaches `i=3`, the 4th field, `dd`, is assigned to the variable `b` (the original description in terms of "$0 $1 $2 $3" is inaccurate — what actually happens here is a for loop that takes the values one by one, with the counter `i` used for positioning):

```bash
# Script contents (file 1)
#!/bin/bash
A="aa:bb:cc:dd"
IFS=":"           # Set the field separator to a colon
i=0
for B in $A;      # Expand $A unquoted so it is split on IFS
do
        [ $i -eq 3 ] && b=$B;   # Take the 4th field (0-based index)
        let i++;
done;
echo $b;
```

Output:

```shell
[root@shell test]# sh 1
dd
```

## 2. Parsing an /etc/passwd-Style Line with IFS

The second example is more practical: it splits a line such as `root:x:0:0:root:/root:/bin/bash` on colons and takes the 1st field (the username) and the 7th field (the login shell). Note that the script first saves the old IFS and restores it when done — a good habit that avoids affecting the behavior of the rest of the script:

```bash
#!/bin/bash
#Desc: Illustration of IFS
line="root:x:0:0:root:/root:/bin/bash"
oldIFS=$IFS;      # Back up the original IFS
IFS=":"
count=0
for item in $line;
do
     [ $count -eq 0 ] && user=$item;    # 1st field: username
     [ $count -eq 6 ] && shell=$item;   # 7th field: login shell
     let count++
done;
IFS=$oldIFS       # Restore the original IFS
echo $user\'s shell is $shell;   # Escape the single quote; output: root's shell is /bin/bash
```

## 3. A Modern Alternative (Supplement)

In today's Bash, both examples above can be written more concisely:

```bash
# Split a line on colons into several variables in one shot with read
line="root:x:0:0:root:/root:/bin/bash"
IFS=: read -r user x uid gid gecos home shell <<< "$line"
echo "${user}'s shell is ${shell}"    # Output: root's shell is /bin/bash
```

This style changes IFS only for the single `read` command, so it does not pollute the global environment.
