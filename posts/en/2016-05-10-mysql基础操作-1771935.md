> **About this post**
>
> This post is a quick reference for everyday MySQL operations: starting and
> stopping the service (/etc/init.d/mysqld, manual startup with mysqld_safe,
> why you should not force the database down with kill -9, graceful shutdown
> with mysqladmin); how to log in and customize the prompt (temporarily, or
> permanently via /etc/my.cnf); the help command; setting and changing the
> root password (three ways — mysqladmin, update mysql.user, and set password,
> plus flush privileges); and finally the recovery procedure after forgetting
> the root password (--skip-grant-tables to bypass the grant tables, and
> specifying --defaults-file for multi-instance setups), with security notes
> on skip-networking and bind-address.

> **Technical notes**
>
> Since MySQL 5.7, the `password` column of the mysql.user table has been
> renamed to `authentication_string`, and MySQL 8.0 removed the `password()`
> function, so `update mysql.user set password=...` no longer works — use
> `ALTER USER ... IDENTIFIED BY ...` instead; on newer systems, `ss` can be
> used in place of `netstat`.

## 1. Starting and Stopping

```shell
/etc/init.d/mysqld start
netstat -lntup | grep 3306
ps -ef | grep mysql | grep -v grep
```

```text
root       1946      1  0 01:51 pts/1    00:00:00 /bin/sh /application/mysql/bin/mysqld_safe --datadir=/application/mysql/data --pid-file=/application/mysql/data/lnmp.com.pid
mysql      2187   1946  0 01:51 pts/1    00:00:00 /application/mysql/bin/mysqld --basedir=/application/mysql --datadir=/application/mysql/data --plugin-dir=/application/mysql/lib/plugin --user=mysql --log-error=/application/mysql/data/lnmp.com.err --pid-file=/application/mysql/data/lnmp.com.pid --socket=/tmp/mysql.sock --port=3306
```

The startup process (visible via `vim /etc/init.d/mysqld`):

```shell
$bindir/mysqld_safe --datadir="$datadir" --pid-file="$mysqld_pid_file_path" $other_args >/dev/null 2>&1 &
```

The startup method suggested at initialization time:

```shell
mysqld_safe --user=mysql &
```

Shutting down:

```shell
/etc/init.d/mysqld stop
ss -lnt | grep 3306
```

```text
LISTEN     0      50                        *:3306
```

Try to avoid shutting the database down abruptly with any of the following:

```shell
killall mysqld
pkill mysqld
killall -9 mysqld    # avoid shutting down the database this rough way
```

Graceful shutdown:

```shell
mysqladmin -uroot -p123456 shutdown
```

## 2. Logging In and the Prompt

```shell
ifconfig    # check whether this is a test or production environment; back up the database first
mysql
mysql -uroot -p
```

Change the prompt (temporary):

```text
mysql> prompt \u@hequanS  \r:\m:\s->
root@hequanS 02:13:09->
```

To make it permanent, write it into `/etc/my.cnf`:

```ini
[mysql]
prompt=\u@hequanS  \r:\m:\s->
```

## 3. Help

```sql
mysql> help
mysql> exit
```

## 4. Setting and Changing Passwords

```shell
mysqladmin -u root password '123456'        # most common; simple and practical
mysqladmin -u root -p'123456' password '123123'
```

```sql
select user,host,password from mysql.user;

-- be sure to specify a condition
update mysql.user set password=password(456) where user='root' and host='localhost';

set password=password('123123');
flush privileges;
```

## 5. Recovering the MySQL root Password

```shell
/etc/init.d/mysqld stop
mysqld_safe --skip-grant-tables --user=mysql &    # skip the grant tables
```

If MySQL was installed from source, the default path is /usr/local/mysql and an error will occur:

```shell
sed -i 's#/usr/local/mysql#/application/mysql#g' /application/mysql/bin/mysqld_safe
```

After logging in, set the new password and flush:

```sql
update user set password=password('newpassword') where user='root' and host='localhost';   -- set the new password
flush privileges;   -- refresh
```

In a new window, test shutting the database down with the new password; if it shuts down successfully, the change worked:

```shell
mysqladmin -uroot -p shutdown
```

For multi-instance setups, specify the configuration file:

```shell
mysqld_safe --defaults-file=/data/3306/my.cnf --skip-grant-tables
```

A safer approach is to skip networking as well:

```shell
mysqld_safe --skip-grant-tables --skip-networking &
```

skip-networking: once this option is enabled, MySQL can no longer be accessed remotely.

For security, if you want only a specific IP to access MySQL, add `bind-address=IP` to the configuration file — provided skip-networking is disabled.
