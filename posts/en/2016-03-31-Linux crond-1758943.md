> **About this post**
>
> This post covers Linux scheduled tasks: it first distinguishes programs from
> processes (foreground/background, daemons, checked with ps -ef and
> netstat -lntup); it implements second-level tasks that crond cannot handle
> with while+sleep scripts; it reviews the system's built-in /etc/cron.*
> directories and the division of labor among logrotate, at, and anacron; it
> explains the crontab minute/hour/day/month/weekday fields, the -u/-l/-e/-r
> options, and the /etc/crontab format; and it closes by summing up production
> writing conventions — output redirection to /dev/null 2>&1, escaping %,
> scripting tasks, running as a designated user, testing before going live —
> plus the sendmail mail backlog problem.

> **Technical notes**
>
> The environment in this post is CentOS 6. On CentOS 7+ service management
> has moved to systemctl (e.g. `systemctl enable --now crond`), and chkconfig
> is kept only for compatibility; in crontab, % is interpreted as a newline,
> so the % in a date format string must be written as \% — a pitfall that
> still trips people up today.

## 1. Programs and Processes

A program is static code; a process is a program the system is executing
right now. Each process has a unique numeric process ID and runs in the
foreground or background:

```shell
# ps -ef | grep sshd
```

System network services run resident in the background (daemons):

```shell
# netstat -lntup | grep sshd          # daemon and ports
```

## 2. Second-Level Scheduled Tasks

crond is precise only to the minute; implement second-level tasks with
while + sleep:

```bash
#!/bin/bash
while true
do
    echo hequan >> /tmp/a.log
    sleep 1
done
```

```shell
# sh xx. &
[1] 1844
# ps -ef | grep xx.
# kill 1844
```

## 3. The System's Own Scheduled Tasks

```shell
# chkconfig --list | grep 3:on
# ll /var/log/messages
# cat /etc/logrotate.conf
# ll /etc/ | grep cron --color=auto
-rw-------.  1 root root    541 11月 23 2013 anacrontab
drwxr-xr-x.  2 root root   4096 3月  27 18:47 cron.d
drwxr-xr-x.  2 root root   4096 3月  27 18:48 cron.daily
-rw-------.  1 root root      0 11月 23 2013 cron.deny
drwxr-xr-x.  2 root root   4096 3月  27 18:47 cron.hourly
drwxr-xr-x.  2 root root   4096 3月  27 18:48 cron.monthly
-rw-r--r--.  1 root root     457 9月  27 2011 crontab
drwxr-xr-x.  2 root root   4096 9月  27 2011 cron.weekly
```

Three scheduling mechanisms:

1. at: runs once (`chkconfig --list atd`)
2. anacron: suits servers that are not powered on 7*24
3. crond: checks every minute for tasks that are due

crond is a background daemon; crontab is the command for setting
scheduled-task rules:

- -u: specify a user
- -l: list
- -e: edit
- -r: remove
- -i: confirm

Scheduled tasks for users are stored under /var/spool/cron/:

```shell
# crontab -e
# cat /var/spool/cron/root
# cat /etc/cron.deny
# crontab -l
/usr/sbin/ntpdate     >>/dev/null 2>&1
```

## 4. crontab Fields and /etc/crontab

```ini
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
HOME=/

# For details see man 4 crontabs
# Example of job definition:
# .---------------- minute (0 - 59)
# |  .------------- hour (0 - 23)
# |  |  .---------- day of month (1 - 31)
# |  |  |  .------- month (1 - 12) OR jan,feb,mar,apr ...
# |  |  |  |  .---- day of week (0 - 6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat
# |  |  |  |  |
# *  *  *  *  * user-name command to be executed
```

minute hour day month weekday command (0 means Sunday). Try not to set both
the day of week and the day of month at the same time.

Common examples:

```text
00 23 * * *                        # every day at 23:00
00 17-19 * * *                     # daily on the hour at 17, 18, 19
*/10 * * * *                       # every 10 minutes
10 1 * * 6,0                       # Sat and Sun at 01:10
00 */1 * * *                       # every hour
00 9,14 * * *   /bin/sh /root/x > /dev/null 2>&1
* * * * *       echo hequan >> /root/hequan.txt
*/1 * * * *     /bin/echo "+" >> /hequan.log
```

Verifying date values:

```shell
# date +%T
14:15:15
# date +%F
2016-03-31
# date +%F%T
2016-03-3115:40:05
# date +%Y%m%d
20160331
```

## 5. Production Writing Conventions

- Professional and standardized
- `/dev/null 2>&1` is equivalent to `1>/dev/null 2>/dev/null`: it sends both
  standard output and standard error to the null device, avoiding junk output
- Success on the command line is the prerequisite for a scheduled task to succeed
- When putting commands into scheduled tasks, the % in time expressions must be
  escaped (% has a special meaning in crontab)
- Use script files for scheduled tasks; do not write long commands inline
- Run the scheduled tasks under a designated user's identity
- Task programs should not print output arbitrarily
- Write comments in scripts (e.g. `#/bin/sh` plus a description); keep paths
  standardized, e.g. /server/scripts
- Test in a test environment first, then deploy to production properly to
  prevent errors
- When a scheduled task runs, it sends mail to the system (sendmail), which is
  temporarily stored in /var/spool/clientmqueue/; on CentOS 6 without sendmail
  installed, suppressing output matters even more

```shell
# rpm -qa | grep sendmail
```

Script example:

```bash
# cat /server/scripts/tar_html.sh
cd /var/www
tar zcvf /tmp/html_$(date +%F).tar.gz ./html/
```

```text
00 */2 * * *  /bin/sh /server/scripts/tar.sh >/dev/null 2>&1
* 00 * * *   /bin/sh /server/scripts/tar_html.sh >/dev/null 2>&1
```

```shell
# tar zcvf /tmp/services_$(date +%F-%H) ./services
# cat /var/log/cron      # scheduled task log
# df -lk
```

## 6. Review Quick Reference

Related files and knowledge points:

- /etc/sysctl.conf: kernel tuning
- /etc/hosts: local name resolution
- /var/log/secure: login security
- Regular expressions: `.` any single character, `*` repeats the preceding
  character N times, `{n,m}` repeats n-m times, `[^t]` anything but t
- `chmod -R 755 xx`, `chown -R root:xx xx`
- umask permission mask: 666-022, 777-022
- `groupadd -g 801 sa`
