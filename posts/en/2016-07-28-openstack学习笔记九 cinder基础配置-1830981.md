> **About this post**
>
> This post is a note on the basic configuration of the Cinder cloud volume service: first install openstack-cinder with yum on an Alibaba Cloud CentOS 7.2 node, register the cinder user/service/endpoint with keystone (both the v1 and v2 versions), initialize the database with openstack-db, copy cinder.conf from the template and configure the database connection, keystone authentication, and RabbitMQ messaging, then start the four services api/backup/scheduler/volume. Next, use pvcreate/vgcreate to create a VG named cinder-volumes on the cloud disk /dev/xvdb as the LVM backend, configure the [lvm] section in cinder.conf to specify volume_group and LVMVolumeDriver, and use cinder create to create a 1GB volume, with the corresponding LV visible in lvs. Finally, it previews the configuration options for the Ceph RBD backend.

> **Technical notes**
>
> CLIs such as `keystone user-create` and `cinder create --display-name` in this post are deprecated; the current equivalents are `openstack user create` and `openstack volume create --size 1 voll`. The cinder v1 API was removed long ago; v2/v3 have been unified under the `openstack volume` command family. The LVM+iSCSI (lioadm) backend still works in test environments, but Ceph RBD is the common choice in production; the option rbd_stone_chunk_size should be rbd_store_chunk_size. Also, the examples use the public IP 115.29.107.17 directly for component authentication; never do this in production.

## 1. Install the Software and Register with Keystone

Cinder is the cloud volume service. Configuration steps: install the packages → register with keystone (user password, service, endpoint) → edit the configuration file.

```shell
yum install openstack-cinder -y
keystone user-create --name cinder --pass hequan
keystone user-role-add --user cinder --role admin --tenant services
keystone service-create --name cinder --type volume --description "Cinder Service"
```

Check the service and create the endpoint:

```shell
keystone service-list
| d1271040fa9144318a836a0b476d1e66 |   cinder   |    volume    |         Cinder Service         |
keystone endpoint-list | grep d1271040fa9144318a836a0b476d1e66
| 8e18c46fc51c4a6287ea740a37537a59 | RegionOne |    http://115.29.107.17:8776/v1/%(tenant_id)s   |    http://115.29.107.17:8776/v1/%(tenant_id)s   | http://115.29.107.17:8776/v1/%(tenant_id)s | d1271040fa9144318a836a0b476d1e66 |

keystone endpoint-create --service-id d1271040fa9144318a836a0b476d1e66 --publicurl 'http://115.29.107.17:8776/v1/%(tenant_id)s' --internalurl 'http://115.29.107.17:8776/v1/%(tenant_id)s' --adminurl 'http://115.29.107.17:8776/v1/%(tenant_id)s'
```

Back up the configuration file, copy it from the template, and initialize the database:

```shell
[root@hequan ~(keystone_admin)]# cd /etc/cinder/
[root@hequan cinder(keystone_admin)]# ls
api-paste.ini  policy.json    rootwrap.d
cinder.conf    rootwrap.conf  volumes
[root@hequan cinder(keystone_admin)]# cp cinder.conf cinder.conf.bak   # backup
[root@hequan ~(keystone_admin)]# cp /usr/share/cinder/cinder-dist.conf /etc/cinder/cinder.conf   # copy the config file
[root@hequan cinder(keystone_admin)]# chown root.cinder cinder.conf    # remember to fix permissions
[root@hequan cinder(keystone_admin)]# openstack-db --init --service cinder --password hequan --rootpw 123456   # create the database
```

## 2. Edit cinder.conf and Start the Services

```ini
[DEFAULT]
logdir = /var/log/cinder
state_path = /var/lib/cinder
lock_path = /var/lib/cinder/tmp
volumes_dir = /etc/cinder/volumes
iscsi_helper = lioadm
rootwrap_config = /etc/cinder/rootwrap.conf
auth_strategy = keystone
[database]
connection = mysql://cinder:hequan@115.29.107.17/cinder
[keystone_authtoken]
admin_tenant_name = services
admin_user = cinder
admin_password = hequan
auth_host = 115.29.107.17
auth_port = 35357
auth_protocol = http
```

The RabbitMQ messaging settings also need to go into cinder.conf (you can refer to the values in keystone.conf):

```shell
[root@hequan cinder(keystone_admin)]# grep ^rabbit /etc/keystone/keystone.conf
rabbit_host = localhost
rabbit_port = 5672
rabbit_hosts = localhost:5672
rabbit_use_ssl = False
rabbit_userid = guest
rabbit_password = guest
rabbit_virtual_host = /
rabbit_ha_queues = False    # write these into the config file above, for inter-component messaging
```

Cinder has four services in total: api is the user interface, backup handles backups, scheduler does scheduling, and volume connects to the backend storage:

```shell
[root@hequan cinder(keystone_admin)]# systemctl list-unit-files | grep cinder
openstack-cinder-api.service                 enabled   # user interface
openstack-cinder-backup.service              enabled   # backup
openstack-cinder-scheduler.service           enabled   # scheduling
openstack-cinder-volume.service              enabled   # backend storage volumes
[root@hequan cinder(keystone_admin)]# systemctl start openstack-cinder-api.service openstack-cinder-backup.service openstack-cinder-scheduler.service openstack-cinder-volume.service
[root@hequan cinder(keystone_admin)]# systemctl enable openstack-cinder-api.service openstack-cinder-backup.service openstack-cinder-scheduler.service openstack-cinder-volume.service
[root@hequan cinder(keystone_admin)]# systemctl is-active openstack-cinder-api.service
active
```

Then create a cinderv2 service and endpoint; the procedure is the same as above, with type volumev2:

```text

| 75a8f5bbf35a42a0bfcd2e6a0d4cea9c | RegionOne |    http://115.29.107.17:8776/v2/%(tenant_id)s   | ... |
```

Verify the service works:


## 3. Configure the LVM Backend and Create a Volume

Create a VG on the cloud disk /dev/xvdb:

```shell
[root@hequan cinder(keystone_admin)]# pvcreate /dev/xvdb
[root@hequan cinder(keystone_admin)]# vgcreate cinder-volumes /dev/xvdb
[root@hequan cinder(keystone_admin)]# vgs
  VG             #PV #LV #SN Attr   VSize  VFree
  cinder-volumes   1   0   0 wz--n- 20.60g 20.60g
```

Append the [lvm] section to cinder.conf to specify the default storage backend:

```ini
[lvm]
iscsi_helper = lioadm
volume_group = cinder-volumes        # this group determines the default storage location
iscsi_ip_address = 115.29.107.17
volume_driver = cinder.volume.drivers.lvm.LVMVolumeDriver   # LVM is the default storage for cloud volumes
volumes_dir = /var/lib/cinder/volumes
iscsi_protocol = iscsi
volume_backend_name = lvm
```

Create a 1GB volume (the newer command is `openstack volume create --size 1 vol1`; the detailed output in the original is omitted):

```shell
[root@hequan cinder(keystone_admin)]# cinder create --display-name vol1 1
[root@hequan cinder(keystone_admin)]# cinder list
+--------------------------------------+-----------+------------------+------+------+-------------+----------+-------------+-------------+
|                  ID                  |   Status  | Migration Status | Name | Size | Volume Type | Bootable | Multiattach | Attached to |
+--------------------------------------+-----------+------------------+------+------+-------------+----------+-------------+-------------+
| 7f778803-41cd-492f-b3b7-baa349b9c3dc | available |        -         | vol1 |  1   |      -      |  false   |    False    |             |
+--------------------------------------+-----------+------------------+------+------+-------------+----------+-------------+-------------+
```

After creation, the corresponding logical volume is visible at the LVM layer:

```shell
[root@hequan cinder(keystone_admin)]# lvs
  LV                                   VG             Attr       LSize
  volume-7f778803-41cd-492f-b3b7-baa349b9c3dc cinder-volumes -wi-a----- 1.00g
[root@hequan cinder(keystone_admin)]# lvscan
  ACTIVE            '/dev/cinder-volumes/volume-7f778803-41cd-492f-b3b7-baa349b9c3dc' [1.00 GiB] inherit
```

If you need to rename the VG, use vgrename and update volume_group in cinder.conf accordingly:

```shell
[root@hequan cinder(keystone_admin)]# vgrename cinder-volumes vg0    # rename
[root@hequan ~]# vgs
  VG   #PV #LV #SN Attr   VSize  VFree
  vg0    1   2   0 wz--n- 20.60g 9.60g
```

## 4. Ceph as Backend Storage (to be tested)

For the details of setting up the Ceph cluster, see the previous glance note. The relevant cinder.conf settings:

```ini
volume_driver = cinder.volume.drivers.rbd.RBDDriver
rbd_pool = cinder                    # Ceph pool name
rbd_ceph_conf = /etc/ceph/ceph.conf
rbd_flatten_volume_from_snapshot = false
rbd_max_clone_depth = 5
rbd_store_chunk_size = 4             # rbd_stone_chunk_size in the original is a typo
rados_connect_timeout = -1
glance_api_version = 2
```

```shell
setfacl -m u:cinder:r-- /etc/ceph/ceph.client.admin.keyring   # make the keyring readable by the cinder user
```
