> **About this post**
>
> This post is the release announcement for the AutoOps 1.8 preview, an open-source ops platform
> built on Django 2.0 and aimed at Linux operations. It provides asset (CMDB) management, batch
> command/script execution, WebSSH, automated MySQL audit/execute/rollback (Inception), code
> repository distribution, technical docs, and permission management. It covers the runtime
> environment (Python 3.6 / CentOS 7.4 / supervisor), complete installation steps (including the
> xadmin and pymysql tweaks), key settings parameters, deployment for development and production
> (uwsgi+nginx), plus nine feature screenshots and the release history.

> **Technical notes**
>
> Timeliness note: Django 2.0 reached end of maintenance in 2019, and the core dependencies
> xadmin and Inception are both no longer maintained (for the Django 3+ admin consider simpleui;
> for SQL auditing see Yearning/Archery). The demo address, chat group, and credentials in this
> post are all 2017-era information and no longer valid. When the original was scraped from the
> repository README, the domain was stripped and several commands were broken up by spaces (cd,
> cp, python, uwsgi, etc.); they have been fixed against the gitee repository
> (gitee.com/hequan2020/autoops) and the links restored. The garbled phrase in the environment
> list ("supervisor for process management") is the original README wording and was left unchanged.

### AutoOps

AutoOps is built on Django 2.0 and aimed mainly at Linux ops engineers.
It manages Linux asset information and MySQL databases, executes commands and
scripts in batch, fetches traffic graphs, and provides web SSH management,
technical docs, and more.

Everyone is welcome to test it; feedback on any issues is appreciated.

#### Installation

Development environment deployment:

1. Download and install the base environment under /opt; if you use another
   directory, just adjust the corresponding settings in supervisor.conf.

```shell
cd /opt
yum install git sshpass redis -y
systemctl enable redis.service
systemctl start redis.service
git clone https://github.com/hequan2017/autoops.git
cd autoops/
pip3 install -r requirements.txt

cd /usr/local/src
wget https://codeload.github.com/sshwsfc/xadmin/zip/django2
unzip django2
cd xadmin-django2/
python setup.py install
```

On the added assets, it is recommended to run `yum install ipmitool dmidecode -y` to gather more information.

2. Install `supervisor`

```shell
chmod +x /opt/autoops/script/inception/bin/*
pip2 install supervisor       ## If pip2 is unavailable, see script/install_pip2.sh
echo_supervisord_conf > /etc/supervisord.conf
mkdir /etc/supervisord.d/
vim /etc/supervisord.conf     ## make the following settings:
```

Relevant settings in /etc/supervisord.conf:

```ini
[inet_http_server]          ## HTTP login credentials
port=0.0.0.0:9001
username=user
password=321

[include]
files = /etc/supervisord.d/*.conf
```

```shell
cp /opt/autoops/script/supervisor.conf /etc/supervisord.d/
```

#### Environment Configuration

- Database: edit the `autoops/settings` file (the original wrote "autops" here; the typo has been
  corrected). Without MySQL, use the sqlite option above; with MySQL, enable it and set the
  connection details. For how to install MySQL, see my blog post
  `http://hequan.blog.51cto.com/5701886/1982428`.

```python
# When MySQL is not available:
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': os.path.join(BASE_DIR, 'db.sqlite3'),
    }
}

# When MySQL is available:
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.mysql',
        'NAME': 'autoops',
        'USER': 'root',
        'PASSWORD': '123456',
        'HOST': '192.168.10.24',
        'PORT': '3306',
    }
}
```

- Custom parameters in autoops/settings:

```python
DEBUG = True                                ## Set to False in production
BROKER_URL = 'redis://127.0.0.1:6379/0'     ## Redis address; usually no change needed
Webssh_ip = '114.115.132.147'               ## Access IP for WebSSH, i.e. this host's public IP; change this
Webssh_port = '9000'                        ## Port; keep the default. If changed, also edit webssh/main.py
                                            #  define('port', default=9000, help='listen port', type=int)
Inception_ip = '127.0.0.1'                  ## Inception address; defaults to localhost, usually no change needed
Inception_port = '6669'                     ## Inception port
inception_remote_system_password = '654321' ## Parameters for the rollback backup (mysql) server;
                                            #  also update the settings in script/inc.cnf
inception_remote_system_user = 'root'
inception_remote_backup_port = '3306'
inception_remote_backup_host = '192.168.10.100'   ## Backup database address
```

- Edit one file,
  `/usr/local/lib/python3.6/site-packages/django/db/backends/mysql/base.py`,
  and comment out the following two lines (35 and 36); if you cannot find them, ignore this step:

```python
if version < (1, 3, 3):
    raise ImproperlyConfigured("mysqlclient 1.3.3 or newer is required; you have %s" % Database.__version__)
```

- Since Inception does not natively support pymysql, the pymysql source must be modified.

Modified connections.py and cursors.py are provided in the script/ folder; just replace the
files. They go under `/usr/local/lib/python3.6/site-packages/pymysql`, replacing
`connections.py` and `cursors.py`. Note: to see exactly what was changed, refer to the
notes in script/.

```shell
cp /opt/autoops/script/connections.py  /usr/local/lib/python3.6/site-packages/pymysql/connections.py
cp /opt/autoops/script/cursors.py      /usr/local/lib/python3.6/site-packages/pymysql/cursors.py
```

- Initialize the database (you may delete db.sqlite3 in the folder first):

```shell
python manage.py makemigrations
python manage.py migrate
python manage.py createsuperuser       ## create an admin user
```

- The port AutoOps listens on is on line 2 of supervisor.conf, default 0.0.0.0:8003.
  If you change the port, stop the uwsgi service in supervisor and start it again.

- Start supervisor for process management:

```shell
/usr/bin/python2.7 /usr/bin/supervisord -c /etc/supervisord.conf
```

To run it at linux boot: `chmod +x /etc/rc.d/rc.local`, and put the command above
into that file.

- Starting: all processes are managed uniformly by supervisor. Open 0.0.0.0:9001 with account
  user and password 321 to reach the process management UI, where you can start/stop uwsgi,
  webssh, celery, Inception, and more.

![Supervisor process management UI, with seven processes including uwsgi/webssh/celery all running](https://gitee.com/hequan2020/autoops/raw/master/static/demo/14.png)

- Log into the admin backend, set up the scheduled host-chart fetch, and configure data
  centers and user groups.

- Set up the scheduled host-information task: first create the execution interval, then create
  the task. After creation, check whether the queue task runs successfully. If not, restart all
  celery services in supervisor.

![django-celery scheduled task configuration page, set to fetch host performance charts every minute](https://gitee.com/hequan2020/autoops/raw/master/static/demo/9.png)

#### Production Environment

- For production deployment and startup, use nginx. You can refer to
  `http://hequan.blog.51cto.com/5701886/1982769`; delete the uwsgi part from supervisor.conf
  and control uwsgi start/stop as follows:

```shell
uwsgi --ini    /opt/autoops/script/uwsgi.ini    # start uwsgi with this config; you can also add this command to the boot file
uwsgi --stop   /opt/autoops/script/uwsgi.pid    # stop uwsgi
uwsgi --reload /opt/autoops/script/uwsgi.pid    # reload
```

- Modify the nginx configuration file as follows. This method also requires starting uwsgi.

```nginx
root  /opt/autoops;

location / {
    include uwsgi_params;
    uwsgi_connect_timeout 30;
    uwsgi_pass unix:/opt/autoops/script/uwsgi.sock;
}

location /static/ {
    alias  /opt/autoops/static/;
    index  index.html index.htm;
}
```
