> **About this post**
>
> This post continues the hands-on MySQL DML work: using a test table with an
> auto-increment primary key to demonstrate several ways to write insert
> (inserting into specified columns, omitting the auto-increment column,
> multi-value batch inserts), plus mysqldump backup and using grep to filter
> out comments when checking the backup file; select with where/and/or
> conditions, limit paging, order by sorting and multi-table joins, using
> explain to tell whether an index is used and create index to optimize;
> update must carry a where clause; the binlog-based incremental recovery
> flow (mysqlbinlog, flush-log, deleting the wrong statements and then
> replaying); the difference between delete and truncate for emptying a
> table; alter to add columns and rename to change table names. The focus is
> on troubleshooting garbled characters: unifying the system i18n, the three
> character-set sections in /etc/my.cnf, the meaning of each variable shown
> by show variables like 'character_set%', and the complete eight-step
> export/import process for converting a latin1 database to GBK while
> keeping the data.

> **Technical notes**
>
> From MySQL 5.5 on, the mysqld section uses `character-set-server` instead
> of 5.1's `default-character-set`; only utf8mb4 is full UTF-8 (it can store
> emoji), and MySQL 8.0 already defaults to utf8mb4. From CentOS 7 on, the
> system locale configuration moved from /etc/sysconfig/i18n to
> /etc/locale.conf.

## 1. insert

Test table:

```sql
create table test(
id int(4) not null AUTO_INCREMENT,
name char(20) not null,
primary key(id)
);
```

```sql
mysql> insert into test(id,name) value(1,'hequan');
mysql> select * from test;
mysql> insert into test(name) value('hequan');           -- id is auto-increment, so inserting name alone is fine
mysql> insert into test value(3,'hequna'),(4,'hequan');  -- no column list, insert in column order
```

Back up the database, then use grep to filter out comments and check the backup:

```shell
mysqldump -uroot -p123456 -B oldboy >/tmp/oldboy_bak.sql
grep -E -v "#|\/|^$|--" /tmp/oldboy_bak.sql
```

## 2. select queries

The basic pattern: select ... from ... where

```sql
mysql> select id,name from test where name='hequan' and/or id=4;
mysql> select id,name from test limit 0,2;          -- start from row 0, fetch 2 rows
mysql> select id,name from test where id>2 and id<4;
mysql> select id,name from test order by id asc/desc;
```

Multi-table query:

```sql
mysql> select student.Sno,student.Sname,course.Cname,SC.Grade from student,course,SC where student.Sno=SC.Sno and course.Cno=SC.Cno order by Sno;
```

Use explain to look at the execution plan and tell whether an index is used:

```sql
mysql> explain select * from test where name='hequan'\G
```

```text
possible_keys: NULL
rows: 2
```

Without an index, possible_keys is NULL. Create an index and look again:

```sql
mysql> create index index_name on test(name);
possible_keys: index_name
rows: 1
```

## 3. update

```sql
mysql> update test set name='xx' where id=4;
```

Restore the data; incremental recovery:

```shell
mysql -uroot -p123456 oldboy < /tmp/oldboy_bak.sql
```

## 4. Incremental recovery (binlog)

Enable it in my.cnf:

```ini
log-bin=mysql-bin
```

The binlog files live in `/application/mysql/data/`, e.g. mysql-bin-hequan.000001.

```shell
mysqlbinlog mysql-bin-hequan.000001

mysqladmin -uroot -p123456 flush-log    # rotate the log, producing mysql-bin-hequan.000002

mysqlbinlog -d oldboy mysql-bin-hequan.000001 > bin.sql
```

Delete the wrong statements from bin.sql, then import it:

```shell
mysql -uroot -p123456 oldboy < bin.sql
```

The binlog only records changes to the database, not queries.

## 5. delete

```sql
mysql> delete from test where id=3;    -- the condition can use > < etc.
mysql> truncate table test;            -- empty the table
```

```sql
mysql> alter table test add sex char(4) after name;   -- add a sex column after name; first puts it at the front instead
mysql> rename table test to test1;
mysql> alter table test1 rename to test;
mysql> drop table test;
```

## 7. Troubleshooting garbled characters

Unify the character set: change /etc/my.cnf in 3 places, then restart the service.

System environment:

```shell
cat /etc/sysconfig/i18n
LANG="zh_CN.UTF-8"
```

On the server side and the client side, vim /etc/my.cnf:

```ini
[client]
default-character-set=utf8

[mysqld]
character-set-server=utf8        # 5.5
# default-character-set=utf8    # 5.1 syntax

[mysql]
default-character-set=utf8
```

```sql
mysql> show variables like 'character_set%';
```

The SecureCRT client also needs to be changed to utf8.

## 9. Changing the character set of existing tables while keeping the original data

Scenario: the character set was not set correctly when the application started; after running for a while you find that it no longer meets your needs and must be adjusted, yet you do not want to throw away the data accumulated in the meantime — so the character set has to be changed. This change cannot be done directly with `alter database character set xxx` or `alter table tablename character set xxx`; neither command updates the character set of existing records — it only takes effect on newly created tables or records.

So how should the character set of existing records be adjusted? The following simulates the process of converting a database with the latin1 character set into a database with the GBK character set:

(1) Export the table structure:

```shell
mysqldump -uroot -p --default-character-set=gbk -d name > createdb.sql
```

Here --default-character-set=gbk sets which character set to connect with, and -d means export the table structure only, without the data.

(2) Manually change the character set in the table definitions inside createdb.sql to the new one:

```shell
sed -i 's#latin1#gbk#g' createdb.sql
```

(3) Make sure records are no longer being updated, then export all records:

```shell
mysqldump -uroot -p --quick --no-create-info --extended-insert --default-character-set=latin1 name > data.sql
```

- --quick: this option is for dumping large tables. It forces mysqldump to retrieve rows from the server one row at a time, instead of retrieving all the rows and buffering them in memory before writing the output
- --extended-insert: uses multi-row insert syntax containing several values lists, which makes the dump file smaller and faster to reload
- --no-create-info: does not write the create table statements that re-create each dumped table
- --default-character-set=latin1: exports all data in the original character set, so that in the exported file all Chinese text stays visible and does not turn into garbage

(4) Open data.sql and change SET NAMES latin1 to SET NAMES gbk.

(5) Create a new database with the new character set:

```sql
create database newdatabasename default charset gbk;
```

(6) Create the tables by running createdb.sql:

```shell
mysql -uroot -p newdatabasename < createdb.sql
```

(7) Import the data by running data.sql:

```shell
mysql -uroot -p newdatabasename < data.sql
```

(8) Before checking, confirm that the local environment has been switched to gbk everywhere; you can test with a temporary change:

```sql
set names gbk;
```
