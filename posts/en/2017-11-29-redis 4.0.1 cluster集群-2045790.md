> **About this post**
>
> This post documents the complete setup of a native Redis 4.0.1 Cluster: two
> machines, each running 3 instances (7000~7002 on 192.168.10.44 as masters,
> 7003~7005 on .45 as slaves), 3 masters and 3 slaves in total. First compile
> and install Redis, then edit redis.conf for each instance (port, bind to the
> local IP, daemonize, cluster-enabled, cluster-config-file, enable AOF), then
> install ruby 2.3.3 via rvm and the redis gem, create the cluster with
> redis-trib.rb create --replicas 1, and finally use redis-cli -c to verify
> slot redirection with cross-node set/get, emphasizing that the surviving
> masters must never fall below half of the total.

> **Technical notes**
>
> 1. CentOS 7 reached end of life (EOL) on June 30, 2024; migrating to Rocky
>    Linux 9 / AlmaLinux 9 or the domestic openEuler is recommended.
> 2. Redis 4.x is no longer maintained; for production, the Redis 6/7 series
>    with ACL and TLS enabled is recommended.
> 3. `redis-trib.rb` has been deprecated since Redis 5.0; newer versions use
>    `redis-cli --cluster create ... --cluster-replicas 1` directly, with no
>    need to install ruby.
> 4. The original mkdir command was missing the `redis_cluster/` path prefix;
>    it has been restored from context (the cp and redis-server startup paths).

## 1. Installation

```bash
cd /opt
wget http://download.redis.io/releases/redis-4.0.1.tar.gz
tar zxf redis-4.0.1.tar.gz
cd redis-4.0.1
make
```

## 2. Cluster Setup (2 machines, 3 master + 3 slave)

### Master nodes (192.168.10.44, ports 7000/7001/7002)

```bash
cd src
cp redis-trib.rb /usr/local/bin/
mkdir redis_cluster
mkdir redis_cluster/7000 redis_cluster/7001 redis_cluster/7002
cp redis.conf redis_cluster/7000
cp redis.conf redis_cluster/7001
cp redis.conf redis_cluster/7002
```

Edit the configuration of each instance:

```ini
port  7000                                //port 7000, 7001, 7002
bind <local-ip>                           //defaults to 127.0.0.1; change it to an IP reachable from the other nodes, otherwise the port cannot be accessed when creating the cluster and cluster creation fails
daemonize    yes                          //run redis in the background
pidfile  /var/run/redis_7000.pid          //pidfile corresponds to 7000, 7001, 7002
cluster-enabled  yes                      //enable cluster; remove the leading #
cluster-config-file  nodes_7000.conf      //cluster config; the file is generated automatically on first startup, 7000, 7001, 7002
cluster-node-timeout  15000               //request timeout; default 15 seconds, adjustable
appendonly  yes                           //enable the AOF log; turn it on if needed — it writes a log entry for every write operation
```

Start the three instances:

```bash
/opt/redis-4.0.1/src/redis-server redis_cluster/7000/redis.conf
/opt/redis-4.0.1/src/redis-server redis_cluster/7001/redis.conf
/opt/redis-4.0.1/src/redis-server redis_cluster/7002/redis.conf
```

### Slave nodes (192.168.10.45, ports 7003/7004/7005)

```bash
mkdir redis_cluster/7003 redis_cluster/7004 redis_cluster/7005
cp redis.conf redis_cluster/7003
cp redis.conf redis_cluster/7004
cp redis.conf redis_cluster/7005
```

Edit the configuration of each instance:

```ini
port  7003                                //port 7003, 7004, 7005
bind <local-ip>                           //defaults to 127.0.0.1; change it to an IP reachable from the other nodes, otherwise the port cannot be accessed when creating the cluster and cluster creation fails
daemonize    yes                          //run redis in the background
pidfile  /var/run/redis_7003.pid          //pidfile corresponds to 7003, 7004, 7005
cluster-enabled  yes                      //enable cluster; remove the leading #
cluster-config-file  nodes_7003.conf      //cluster config; the file is generated automatically on first startup, 7003, 7004, 7005
cluster-node-timeout  15000               //request timeout; default 15 seconds, adjustable

```

Start the three instances:

```bash
/opt/redis-4.0.1/src/redis-server redis_cluster/7003/redis.conf
/opt/redis-4.0.1/src/redis-server redis_cluster/7004/redis.conf
/opt/redis-4.0.1/src/redis-server redis_cluster/7005/redis.conf
```

## 3. Creating the Cluster (run on the master)

redis-trib.rb depends on ruby; install it via rvm first:

```bash
yum -y install ruby ruby-devel rubygems rpm-build  curl
curl -sSL https://rvm.io/mpapis.asc | gpg2 --import -
curl -L get.rvm.io | bash -s stable
source /usr/local/rvm/scripts/rvm
rvm list known
rvm install 2.3.3
rvm use 2.3.3
rvm remove 2.0.0
ruby --version
gem install redis
```

Create the cluster and type `yes` to confirm when prompted:

```bash
/opt/redis-4.0.1/src/redis-trib.rb create --replicas 1 \
  192.168.10.44:7000 192.168.10.44:7001 192.168.10.44:7002 \
  192.168.10.45:7003 192.168.10.45:7004 192.168.10.45:7005
```

## 4. Testing

```bash
/opt/redis-4.0.1/src/redis-cli -h 192.168.10.44 -c -p 7000
192.168.10.44:7000> set hello world
OK
192.168.10.44:7000> keys *
1) "hello"

/opt/redis-4.0.1/src/redis-cli -h 192.168.10.45 -c -p 7005
192.168.10.45:7005> get hello
-> Redirected to slot [866] located at 192.168.10.44:7000
"world"
```

## 5. Notes

At least 3 master nodes are required, otherwise cluster creation fails; and when the number of surviving masters falls below half of the total, the whole cluster can no longer serve requests.
