## 1. What Is Elastic Compute Service (ECS)

Elastic Compute Service (ECS) is a fundamental cloud computing service provided by Alibaba Cloud. Using ECS is as convenient and efficient as using utilities such as water, electricity, and gas. You do not need to purchase hardware in advance; instead, you can create the required number of ECS instances at any time according to your business needs, and as your business grows, expand disk capacity and increase bandwidth on your ECS instances. When you no longer need an ECS instance, you can easily release the resources to save costs.

### Advantages

ECS offers advantages that traditional servers and virtual hosts cannot match:

- **Stability**: Service availability of up to 99.95% and data reliability of up to 99.9999999%. Supports migration on host failure, snapshot backup and rollback, and system performance alerts.
- **Disaster recovery and backup**: Every piece of data has multiple replicas; a damaged replica can be quickly restored within a short time.
- **Security**: Supports security group rules, the Cloud Shield anti-DDoS system, multi-user isolation, and protection against password cracking.
- **Multi-line access**: Optimal routing based on the Border Gateway Protocol (BGP). BGP multi-line data centers provide smooth, balanced nationwide access. Backbone data centers offer large egress bandwidth on dedicated lines.
- **Elastic scaling**: Up to 100 ECS instances can be started or released within 10 minutes; bandwidth can be upgraded online without downtime; CPU and memory can be upgraded offline within 5 minutes.
- **Low cost**: No large upfront investment; buy on demand, pay elastically, and flexibly adapt to business changes.
- **Control**: As an ECS user, you have super administrator privileges and full control over the ECS instance's operating system. You can resolve system issues yourself through the management terminal, and deploy environments, install software, and more.
- **Ease of use**: A rich selection of operating systems and application software; one-click deployment of the same image; environments can be quickly replicated across multiple ECS instances for easy scaling; supports batch creation of ECS instances from custom images and disk snapshots.
- **API**: Manage instances through the ECS API, and use security groups to configure access for one or more ECS instances, making development and usage more convenient.

### Features

ECS provides the following features:

- Create instances in 14 regions, some of which offer multiple availability zones.
- Dozens of instance types for a variety of business scenarios, from "1 core, 1 GB" to "56 cores, 480 GB", meeting a wide range of needs.
- 3 types of data storage disks (basic cloud disk, SSD cloud disk, ultra cloud disk), plus I/O-optimized instances.
- 2 types of IP addresses: public IP and private IP, enabling intranet interconnection and Internet access.
- 2 network types: classic network and VPC, managing your network along different dimensions.
- Supports multiple versions of Windows and Linux operating systems.
- Free Cloud Shield activation and the CloudMonitor service.
- Rich image resources: public images, custom images, shared images, and the image marketplace, letting you deploy operating systems and application software quickly without installation.
- Multiple management methods, including the console, remote terminal, and API, giving you full management permissions.
- Flexible payment options: monthly/annual subscription and pay-as-you-go.

## 2. High Availability, Security, and Elasticity of Cloud Computing

### High availability

Alibaba Cloud provides the following three types of support:

- Products and services that improve availability, including Elastic Compute Service, Server Load Balancer, multi-backup database services, and the Data Transmission Service (DTS).
- Industry partners and ecosystem partners who help you build higher and more stable architectures and ensure service continuity.
- A wide variety of training services, enabling you to achieve high availability across the entire chain, from the business layer down to the underlying infrastructure services.

### Security (VPC)

- **Alibaba Cloud VPC opens up more business possibilities.** With simple configuration, you can interconnect your business environment with data centers around the world, improving business flexibility, stability, and growth potential.
- **Having an existing self-built IDC data center is not a problem.** Alibaba Cloud VPC can extend a dedicated line to your existing IDC data center, forming a hybrid cloud architecture. Alibaba Cloud provides various hybrid cloud solutions and a rich set of network products that together form powerful network capabilities and make your business more flexible. Combined with the Alibaba Cloud ecosystem, you can build unexpected business ecosystems in the cloud.
- **Alibaba Cloud VPC is more stable and secure.**
  - **Stability**: With your business built on a VPC, the underlying network infrastructure keeps evolving, giving you a newer network architecture and newer network features every day, so your business always stays in a stable state. A VPC lets you freely partition, configure, and manage your own network.
  - **Security**: In the face of constant attack traffic on the Internet, a VPC inherently provides traffic isolation and attack isolation. Once your business is built on a VPC, it forms the first line of defense for your business.

### Elasticity

**Compute elasticity**

- **Vertical elasticity, i.e., changing the configuration of a single server.** Under the traditional IDC model, it is difficult to change the configuration of a single server. With Alibaba Cloud, once you have purchased a cloud server or storage capacity, you can freely change your configuration as your business load grows or shrinks. For specific applications of vertical elasticity, see [Upgrading and Downgrading Configurations](https://help.aliyun.com/document_detail/25437.html?spm=5176.doc25367.6.649.FMIUkj).
- **Horizontal elasticity.** For peak periods in gaming applications or live-streaming platforms, under the traditional IDC model you simply cannot prepare resources instantly; cloud computing, however, can help customers get through such peaks in an elastic way. When the peak subsides, you can release the excess resources to reduce business costs. With horizontal scale-out and scale-in, combined with Alibaba Cloud Auto Scaling, you can scale at scheduled times and by scheduled amounts, or scale according to business load. For specific applications of horizontal elasticity, see [Auto Scaling](https://help.aliyun.com/document_detail/25857.html?spm=5176.product25855.6.539.D0ePwz).

**Storage elasticity**

Alibaba Cloud offers strong storage elasticity. As storage demand grows, under a traditional IDC solution you can only keep adding servers, and the number of servers you can add this way is limited. In the cloud computing model, massive storage is provided for you: you can purchase it directly when needed, giving your storage the greatest assurance. For specific applications of storage elasticity, see [Disk Expansion](https://help.aliyun.com/document_detail/35095.html?spm=5176.product25365.6.668.ygZKDu).

**Network elasticity**

Networking in the cloud is also highly flexible. As long as you purchase an Alibaba Cloud VPC, all network configurations can be exactly the same as in an on-premises IDC data center, with even more possibilities. You can achieve interconnection between data centers and security-domain isolation between them, and all network configuration and planning within a VPC is very flexible. For specific applications of network elasticity, see [Virtual Private Cloud](https://help.aliyun.com/product/27706.html).

### Availability zones

An availability zone is a physical area within the same region that has independent power and network infrastructure. ECS instances within the same availability zone have lower network latency.

Within the same region, availability zones are interconnected over the internal network and can isolate faults from each other. Whether to place ECS instances in the same availability zone mainly depends on your requirements for disaster recovery capability and network latency.

- If your application requires high disaster recovery capability, we recommend deploying ECS instances in different availability zones within the same region.
- If your application requires low network latency between instances, we recommend creating ECS instances in the same availability zone.

## 4. Relationship Between ECS and Other Alibaba Cloud Products

If your ECS instances need to be used together with other Alibaba Cloud products, note the following:

- ECS instances, Relational Database Service (RDS), and Object Storage Service (OSS) in different regions are not interconnected over the internal network.
- ECS instances in different regions cannot share a load balancer across regions; that is, ECS instances purchased in different regions cannot be attached to the same load balancer instance.

## 5. Instances and Lifecycle

An ECS instance is equivalent to a virtual machine containing the most basic computing components, such as CPU, memory, operating system, network, and disks. You can conveniently customize and change the instance configuration. You have full control over this virtual machine; the only difference from your local server is that you just need to log on to Alibaba Cloud to use the cloud server and perform independent management, top-tier configuration, and other operations.

### Inherent instance states

Throughout this lifecycle, an instance has several inherent states, as shown in the table below:

| State | State type | Description | Corresponding API state |
| --- | --- | --- | --- |
| Preparing | Intermediate state | The state after the instance is created and before it enters Running. Remaining in this state for a long time indicates an anomaly. | Pending |
| Created | Stable state | The instance has been created and is waiting to start. | Stopped |
| Starting | Intermediate state | The state after the instance is restarted, started, or otherwise operated from the console or via the API, and before it enters Running. Remaining in this state for a long time indicates an anomaly. | Starting |
| Running | Stable state | The instance is running normally; instances in this state can run your business. | Running |
| Stopping | Intermediate state | The state after a stop operation is performed from the console or via the API, and before the instance enters Stopped. Remaining in this state for a long time indicates an anomaly. | Stopping |
| Stopped | Stable state | The instance has been stopped normally; instances in this state cannot serve business externally. | Stopped |
| Reinitializing | Intermediate state | The state after the system disk or data disk is re-initialized from the console or via the API, and before the instance enters Running. Remaining in this state for a long time indicates an anomaly. | Stopped |
| Replacing system disk | Intermediate state | The state after the operating system is replaced from the console or via the API, and before the instance enters Running. Remaining in this state for a long time indicates an anomaly. | Stopped |

Either situation puts the instance into the Expired state. Instances in this state are stopped and cannot serve business externally. ## 6. Deployment Sets

- **Improve business reliability**: You may want instances of the same application to avoid being placed on the same physical host, rack, or switch as much as possible, so that a failure of a physical host, rack, or switch does not heavily impact your business.
- **Improve business network performance**: In some scenarios, instances exchange a large amount of network traffic, and you want the lowest possible network latency or the highest possible network bandwidth between them. In such cases, you want the relevant instances to be concentrated under the same switch as much as possible, to reduce network latency and guarantee network bandwidth.
- A Deployment Set is a capability provided by Alibaba Cloud ECS that makes the physical topology of hosts, racks, and switches visible to you, and lets you choose a deployment strategy that matches your business type to improve the overall reliability or performance of your business.

Deployment Set strategies include:

- Deployment strategies: four strategies in all, including best-effort concentration, strict concentration, best-effort dispersion, and strict dispersion. Best-effort and strict concentration suit scenarios requiring higher performance, while best-effort and strict dispersion aim for higher availability.
- Deployment domains: three levels, including host, rack, and switch. Host and rack support the two dispersion strategies (best-effort and strict), while switch supports all four deployment strategies.

## 7. Cloud Disks

### Parameter comparison of the three disk types

- Basic cloud disk: designed for low-I/O application scenarios, providing hundreds of IOPS of I/O performance for ECS instances.
- Ultra cloud disk: designed for applications with moderate I/O requirements, providing storage performance of up to 3,000 random IOPS for ECS instances.
- SSD cloud disk: designed for I/O-intensive applications, providing stable, high random IOPS performance.

### Ultra cloud disk

The ultra cloud disk uses a hybrid medium of solid-state drives and magnetic hard drives as its storage medium, and has the following features:

- **I/O performance**: Up to 3,000 random read/write IOPS and 80 MBps of throughput.
- **Data reliability**: Uses a distributed triple-replica mechanism to provide 99.9999999% data reliability.
- **Performance guidelines**:
  - IOPS: starts at 1,000 IOPS, increases by 6 IOPS per GB, up to 3,000;
  - Throughput: starts at 50 MBps, increases by 0.1 MBps per GB, up to 80 MBps;
  - For example, a 250 GB ultra cloud disk delivers 2,500 random read/write IOPS and 75 MBps of throughput.
- **Maximum capacity**: A single ultra cloud disk provides up to 32768 GB of storage space.
- **Standalone mounting**: Ultra cloud disks can be attached to any ECS instance within the same availability zone.

Application scenarios:

- Small and medium-sized relational database applications such as MySQL, SQL Server, and PostgreSQL.
- Medium and large development and testing applications that require high data reliability and moderate performance.

### SSD cloud disk

The SSD cloud disk uses a distributed triple-replica mechanism to provide high-performance storage with stable, high random I/O and high data reliability, and has the following features:

- **High performance**: Up to 20,000 random read/write IOPS and 300 MBps of throughput.
- **IOPS**: Starts at 1,200 IOPS, with 30 random IOPS of capacity per GB, and delivers up to 20,000 random read/write IOPS. For example, a 100 GB SSD cloud disk provides 4,200 IOPS; a 334 GB SSD cloud disk provides 11,220 IOPS.
  **Note**: An SSD cloud disk achieves its expected IOPS performance only when attached to an I/O-optimized instance; when attached to a non-I/O-optimized instance, the expected IOPS performance cannot be achieved.
- **Throughput**: SSD cloud disk throughput=min{80+0.5*capacity, 300} MBps; it starts at 80, increases by 0.5 MBps per GB, and is capped at 300 MBps of throughput.
- **Performance benchmarks**:
  - With block sizes of 4 KB/8 KB, IOPS can reach a maximum of 20,000.
  - With a block size of 16 KB, IOPS peak at about 17,200 and throughput reaches the 300 MBps cap.
  - With a block size of 32 KB, IOPS peak at about 9,600 and throughput reaches the 300 MBps cap.
  - With a block size of 64 KB, IOPS peak at about 4,800.
  - And so on.
- **Data reliability**: Uses a distributed triple-replica mechanism to provide 99.9999999% data reliability.
- **Maximum capacity**: A single SSD cloud disk provides up to 32768 GB of storage space.
- **Standalone mounting**: SSD cloud disks can be attached to any ECS instance within the same availability zone.

Application scenarios: with stable, high random I/O performance and high data reliability, SSD cloud disks are suitable for the following scenarios:

- Medium and large relational database applications such as PostgreSQL, MySQL, Oracle, and SQL Server.
- Medium and large development and testing environments with high data reliability requirements.

### Basic cloud disk

The basic cloud disk uses magnetic hard drives as its storage medium and a distributed triple-replica mechanism to provide high data reliability, and has the following features:

- **I/O performance**: Provides hundreds of random read/write IOPS and up to 30-40 MBps of throughput.
- **Data reliability**: Uses a distributed triple-replica mechanism to provide 99.9999999% data reliability.
- **Maximum capacity**: A single basic cloud disk provides up to 2000 GB of storage space.
- **Standalone mounting**: Basic cloud disks can be attached to any ECS instance within the same availability zone.

Application scenarios:

- Suitable for application scenarios where data is infrequently accessed or the I/O load is low; if the application needs higher I/O performance, an SSD cloud disk is recommended.
- Application environments that need low cost along with random read/write I/O.

### Triple-replica technology for cloud disks

**Chunk**: Reads and writes performed by ECS users on virtual disks are ultimately mapped to reads and writes of files on Alibaba Cloud's data storage platform. Alibaba Cloud provides a flat, linear storage space and internally slices the linear address space; each slice is called a Chunk. For every Chunk, Alibaba Cloud creates three replicas and stores these replicas on different nodes in the cluster according to a certain strategy, guaranteeing the reliability of user data.

**Principle of the three replicas**: In Alibaba Cloud's data storage system there are three roles: Master, Chunk Server, and Client. A write operation from an ECS user, after passing through layers of transformation, is ultimately executed by the Client. The execution process is briefly described as follows:

- The Client computes the Chunk corresponding to this write operation.
- The Client queries the Master for the locations of the three replicas of that Chunk.
- Based on the result returned by the Master, the Client sends write requests to these three Chunk Servers.
- If all three writes succeed, the Client returns success to the user; otherwise, the Client returns failure.

## 8. Internal Network

Currently, on the Alibaba Cloud internal network, non-I/O-optimized instances share gigabit bandwidth and I/O-optimized instances share 10-gigabit bandwidth, with no special restrictions. Because the network is shared, the bandwidth speed cannot be guaranteed to remain constant.

For ECS instances on the internal network:

- For **classic network** instances:
  - Instances of the same account in the same region are interconnected over the internal network by default if they are in the same security group.
  - Instances of the same account in the same region but in different availability zones can connect normally over the internal network if they are in the same security group, even if their internal IP addresses are not in the same subnet.
  - Instances of different accounts in the same region can achieve internal network interconnection through security groups; see [Security group use cases](https://help.aliyun.com/document_detail/25475.html).
- For **VPC** instances:
  - Instances of the same account, in the same region and the same VPC:
    - If they are in the same security group, they are interconnected over the internal network.
    - If they are in different security groups, internal network interconnection requires security group authorization.
  - Instances of the same account in the same region that are in different VPCs require Express Connect for network interconnection; see [Express Connect use cases](https://help.aliyun.com/document_detail/27787.html).
- An instance's internal IP address cannot be modified or changed.
- The internal and external networks of an instance do not support VIP (virtual IP) configuration.
- Instances of different network types cannot interconnect over the internal network by default. You can enable the [ClassicLink feature](https://help.aliyun.com/document_detail/57517.html) to allow classic network ECS instances to access cloud resources within a VPC over a private network.
