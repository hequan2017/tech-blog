> **About this post**
>
> This post provides a complete Python script for sending email in bulk: it reads a customer list line by line from 1.csv (first column: customer name; second column: Cc recipients; third column onward: recipients), assembles festival greeting emails with a Word attachment using MIMEMultipart, logs in over SMTP with STARTTLS, and sends them one by one with a 7-second interval between emails to avoid being rate-limited. It focuses on the difference between the two ways of writing Cc — with a single Cc recipient, write the string directly; with multiple recipients, join them with COMMASPACE just like To, and include the Cc recipients in the recipient list passed to sendmail. The post closes with a known issue where Chinese attachment names show up as "Unnamed" on mobile clients.

> **Technical notes**
>
> The code is written in Python 2 style: the universal-newline mode of `open('1.csv', 'U')` was removed in Python 3.11+, and a plain `open('1.csv')` is enough. In the original post, the value of `'Content-Disposition'` had been escaped by the blog platform into `p_w_upload` (i.e. attachment); this has been fixed — the "Chinese attachment name shows as Unnamed" bug at the end of the post stems precisely from this. On Python 3, a more robust approach is to use MIMEApplication and Header-encode the Chinese filename. Also note that nowadays SMTP login for mailboxes such as 163 requires an authorization code instead of the account password.

## 1. Complete Script

```python
# !/usr/bin/env python
# -*- coding: UTF-8 -*-
import csv
from email.mime.multipart import MIMEMultipart
from email.mime.text import MIMEText
from email.mime.application import MIMEApplication
from email.utils import COMMASPACE, formatdate
from email.mime.base import MIMEBase
from email import encoders
import time

def send_mail(server, fro, to, subject, text, chao):
    assert type(server) == dict
    assert type(to) == list
    msg = MIMEMultipart()
    msg['From'] = fro
    msg['Subject'] = subject
    msg['To'] = COMMASPACE.join(to)  # COMMASPACE==', '
    msg['Cc'] = chao  # Cc (a plain string for one recipient; join multiple like To)
    msg['Date'] = formatdate(localtime=True)

    xlsxpart = MIMEBase("application", "msword")
    xlsxpart.set_payload(open(u'通知.docx','rb').read(), 'utf-8')
    xlsxpart.add_header('Content-Disposition', 'attachment', filename="通知.docx")
    msg.attach(xlsxpart)

    import smtplib
    smtp = smtplib.SMTP(server['name'], server['port'])
    smtp.ehlo()
    smtp.starttls()
    smtp.ehlo()
    smtp.login(server['user'], server['passwd'])
    smtp.sendmail(fro, to+[chao], msg.as_string())
    smtp.close()


if __name__ == '__main__':
    server = {'name': '', 'user': 'xxxxx', 'passwd': 'xxx', 'port': 25}
    fro = 'xxxxxxxx'
    subject = 'xxxxx'
    with open('1.csv', 'U') as csvfile:
        # reader = csv.DictReader(csvfile)
        reader = csv.reader(csvfile)
        l = []
        for row in reader:
            l.append(row)
    print("开始")
    for i in l:
        name = i[0]
        mail = i[2:10]
        chao = i[1]
        b = '''
        您好！
        值此“八一”建军节之际，祝愿贵公司蓬勃发展，建军节快乐！

            '''
        a = "尊敬的{0}:".format(name)
        text = a + b
        while '' in mail:
            mail.remove('')
        to = mail
        print('to', to, 'ok', 'chao', 'ok')
        time.sleep(7)
        send_mail(server, fro, to, subject, text, chao)
```

## 3. Notes on Cc

```python
msg['To'] = COMMASPACE.join(to)  # COMMASPACE==', '
msg['Cc'] = chao  # COMMASPACE==', '
```

```python
smtp.sendmail(fro, to+[chao], msg.as_string())
```

Note in particular the code above: only 1 person is being Cc'd here.

Cc means carbon copy. Pay attention to whether you are Cc'ing one person or several. If there are several, they must be formatted the same way as To (joined with `COMMASPACE.join()`).

## 4. Known Bug

This script has a bug: when the attachment has a Chinese filename, mobile clients receive it and display it as "Unnamed", while desktop clients work fine.

> The original post says "not yet solved" here. A later investigation found the root cause: at publishing time the value of `'Content-Disposition'` was escaped into `p_w_upload`, so clients could not recognize the attachment descriptor and showed "Unnamed"; after fixing it back to `attachment`, Chinese attachment names display correctly. See the technical notes above for details.
