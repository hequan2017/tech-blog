> **About this post**
>
> This post documents how to set up MySQL 5.7 master-slave replication using
> the traditional binlog position method: after the slave is cloned directly
> from the master, you need to change the server-id, the UUID in auto.cnf,
> and the pid file name; binlog-do-db / replicate-do-db are used to replicate
> only the autoops database; log-bin is enabled on the master and a rep
> replication account is created, then the data is dumped with
> mysqldump --master-data=2 + --single-transaction; after importing it on the
> slave, run CHANGE MASTER with MASTER_LOG_FILE/POS, start slave, and confirm
> both threads show Yes.

> **Technical notes**
>
> 1. MySQL 5.7 reached end of official support (EOL) in October 2023; plan an
>    upgrade to MySQL 8.0.
> 2. Creating accounts with `GRANT ... IDENTIFIED BY` is deprecated in MySQL
>    8.0; use `CREATE USER` first, then `GRANT`. `CHANGE MASTER TO` has also
>    been replaced by `CHANGE REPLICATION SOURCE TO`.
> 3. GTID replication (`gtid_mode=ON`) is recommended instead, which removes
>    the manual step of locating binlog positions.

---

## 1. Parameters to Change After Cloning

Installation is omitted; refer to my earlier posts. The slave is cloned from the master. After cloning the master database, you need to change the server-id and the UUID in /data/mysql/auto.cnf, and rename the pid file.

## 2. Replication Filter Configuration (my.cnf)

```ini
master:  # send only
binlog-do-db=autoops

slave:   # receive only
replicate-do-db=autoops
```

## 3. Master Operations

Enable `log-bin=mysql-bin` in the configuration file (the slave usually does not enable it):

```sql
mysql> show variables like 'log_bin%';
+---------------------------------+-------+
| Variable_name                   | Value |
+---------------------------------+-------+
| log_bin                         | ON    |
+---------------------------------+-------+

mysql> grant replication slave on *.* to 'rep'@'192.168.10.%' identified by '123456';
mysql> flush privileges;
```

Dump the data (use --single-transaction for InnoDB; MyISAM requires --lock-all-tables):

```bash
mysqldump -uroot -p -B autoops --events --master-data=2 --single-transaction > rep.sql
```

MASTER_LOG_FILE and MASTER_LOG_POS are recorded in rep.sql:

```sql
22 -- CHANGE MASTER TO MASTER_LOG_FILE='mysql-bin.000009', MASTER_LOG_POS=1564447;
```

Transfer it to the slave:

```bash
scp rep.sql root@192.168.10.36:/root
```

## 4. Slave Operations

Import the data:

```bash
mysql -uroot -p123456 < /opt/rep.sql
```

Specify the master and the replication position:

```sql
CHANGE MASTER TO
MASTER_HOST='192.168.10.29',
MASTER_PORT=3306,
MASTER_USER='rep',
MASTER_PASSWORD='123456',
MASTER_LOG_FILE='mysql-bin.000009',
MASTER_LOG_POS=1486295;
```

Start replication and verify (this generates the /data/master.info file):

```sql
mysql> start slave;
mysql> show slave status\G;
```

Both threads showing Yes means success:

```text
Slave_IO_Running: Yes
Slave_SQL_Running: Yes
```

Relay log and replication position information (excerpt from the show slave status output):

```text
relay-bin.index

/data/3307/relay-bin.000001
/data/3307/relay-bin.000002
                                        # relay logs

427
mysql-bin.000005
591
```
