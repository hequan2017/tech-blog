> **About this post**
>
> This post features the author's first hand-drawn architecture diagram, on the
> topic of memcached's cache read/write flow: the browser sends a request to the
> application server; on a cache hit, the result is returned directly; on a miss,
> memcache is checked first, and if the data still isn't there, the request falls
> back to the RDBMS relational database to read it, while writing a copy of the
> result back to memcache — the classic Cache-Aside pattern. The post consists of
> just this one illustration.

> **Technical notes**
>
> The diagram shows the Cache-Aside pattern, an approach that remains universal
> to this day and applies to both memcached and Redis; memcached is still actively
> maintained (1.6.x) and is commonly deployed in production alongside a database
> as a front-line cache.
