> **About this post**
>
> The first post in my OpenStack study notes: a quick rundown of the SaaS/PaaS/IaaS/XaaS concepts, followed by installing OpenStack Liberty on CentOS 7.2 with the packstack tool from the RDO project. It covers the two installation methods (the one-shot allinone install and the answer-file install), how to batch-change the passwords in the answer file, how to log into the Dashboard with keystonerc_admin after installation, and how to add a second compute node (192.168.1.202) by editing the answer file.

> **Technical notes**
>
> OpenStack Liberty (released in 2015) and Mitaka are long past EOL; as of 2026 the community-maintained releases follow the 2024/2025 naming scheme (e.g., Caracal, Dalmatian). packstack is now only for single-machine experiments; Kolla-Ansible is recommended for production deployments. CentOS 7 reached EOL in June 2024; consider migrating to Rocky Linux 9 / openEuler 22.03 or similar. In addition, the keystone v2.0 API used in this post (OS_AUTH_URL with /v2.0) has long been deprecated; v3 is the standard now.

## 1. Cloud Computing Service Models and OpenStack Versions

- SaaS: Software as a Service
- PaaS: Platform as a Service (written as "PasS" in the original, a typo)
- IaaS: Infrastructure as a Service
- XaaS: Everything as a Service

The state of OpenStack releases at the time of writing:

- Liberty release (codename meaning: freedom)
- Mitaka release (the newest release at the time; the codename comes from Mitaka, a city in Japan)

RDO is a Red Hat-led open source project that packages OpenStack as RPMs, with the **packstack** tool handling the installation. packstack can be used in two ways:

- **allinone**: installs every component on a single machine; not customizable and only suitable for test environments. Note: the allinone install downloads a cirros test image from the Internet.
- **Answer file**: lets you customize which machine each component goes on and which passwords to use; suitable for multi-node deployments.

Lab environment:

```shell
[root@h1 ~]# cat /etc/redhat-release
CentOS Linux release 7.2.1511 (Core)
```

Network plan:

- Controller node: 192.168.1.201 (h1)
- Compute node: 192.168.1.202 (h2) (the original says "settlement node", which is a typo for "compute node")

## 2. Pre-Installation Prep: Disabling NetworkManager and Configuring the yum Repo

```shell
# Stop and disable NetworkManager (it conflicts with the OpenStack networking service)
[root@h1 ~]# systemctl is-active NetworkManager
active
[root@h1 ~]# systemctl stop NetworkManager
[root@h1 ~]# systemctl disable NetworkManager
```

The packages can be downloaded from a mirror site: http://mirrors.163.com/centos/7.2.1511/cloud/x86_64/ , choosing according to the OpenStack release you need (Liberty in this install). Then configure a local yum repo:

```ini
# /etc/yum.repos.d/openstack.repo
[openstack]
name=openstack
baseurl=file:///root/openstack   # points to the directory holding the downloaded packages
enabled=1
gpgcheck=0
```

```shell
yum clean all
```

## 3. Installing packstack

```shell
# Confirm the packstack package is available in the repo
[root@h1 openstack]# yum list openstack-packstack
可安装的软件包
openstack-packstack.noarch   1:7.0.0-0.10.dev1682.g42b3426.el7   openstack

[root@h1 openstack]# yum install openstack-packstack
```

## 4. Method 1: One-Shot allinone Install

```shell
# Check the demo options
[root@h1 openstack]# packstack --help | grep demo
  Provisioning demo config:
    --provision-demo=PROVISION_DEMO
                        Specify 'y' to provision for demo usage and testing.

# Install all components on this machine without provisioning the demo tenant network
[root@h1 openstack]# packstack --allinone --provision-demo=n
```

## 5. Method 2: Answer-File Install

```shell
[root@h1 ~]# packstack --help | grep ans
  --gen-answer-file=GEN_ANSWER_FILE
                        Generate a template of an answer file.
  --answer-file=ANSWER_FILE

# Generate the answer file template
[root@h1 ~]# packstack --gen-answer-file=he.txt

# Turn off the unneeded components (line numbers within the answer file)
#  67  CONFIG_NAGIOS_INSTALL=n
# 1116  CONFIG_PROVISION_DEMO=n

[root@h1 ~]# grep _PW he.txt    # show all password settings

# Change every *_PW=xxx password to hequan (-i.bak keeps a he.txt.bak backup)
[root@h1 ~]# sed -i.bak -r 's/(.+_PW)=.+/\1=hequan/' he.txt

# Start the installation from the answer file
[root@h1 ~]# packstack --answer-file=he.txt
```

## 6. Login Verification

Before using the command-line tools, source the credentials file:

```shell
[root@h1 ~]# cat keystonerc_admin
unset OS_SERVICE_TOKEN
export OS_USERNAME=admin
export OS_PASSWORD=hequan
export OS_AUTH_URL=http://192.168.1.201:5000/v2.0   # keystone v2.0 API (deprecated; v3 is current)
export PS1='[[34m\u@\h \W(keystone_admin)[0m]\$ '
export OS_TENANT_NAME=admin
export OS_REGION_NAME=RegionOne
```

Browse to `http://192.168.1.201/dashboard`, log in with admin / hequan from the top-right corner, and you can set the language and time zone.

## 7. Adding a Compute Node

On the compute node h2 (192.168.1.202), set up the same yum repo and OpenStack package environment, then configure passwordless SSH login on the controller node:

```shell
[root@h1 ~]# ssh-keygen                                  # generate a key pair (just press Enter throughout)
[root@h1 ~]# ssh-copy-id -i .ssh/id_rsa.pub h2           # copy the public key to h2
```

Edit the answer file to add the new node to the compute host list:

```shell
vim he.txt
# 84  # List the servers on which to install the Compute service.
# 85  CONFIG_COMPUTE_HOSTS=192.168.1.201,192.168.1.202   # just append the new node

# Run the installation again; packstack is idempotent, it will not overwrite existing config and will only set up the new node
packstack --answer-file=he.txt
```
