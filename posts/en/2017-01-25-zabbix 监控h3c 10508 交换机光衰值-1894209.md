> **About this post**
>
> Use SNMP to let Zabbix monitor the transmit/receive power of optical modules on an H3C S10508 core switch. The post provides an auto-discovery rule (based on ifDescr) plus two sets of OIDs for RX/TX power: one borrowing Huawei's enterprise number 2011, and one using H3C's official enterprise number 25506, along with an snmpwalk verification command and a download link for the H3C OID files.

> **Technical notes**
>
> The SNMP OIDs and the monitoring approach are still applicable today; the Zabbix 2.x/3.x UI differs significantly from current versions, so it is advisable to follow the official Zabbix 5.x/6.x documentation when configuring. Also, SNMPv2c uses a plaintext community string, so SNMPv3 with encrypted authentication is recommended for production environments.

---

## Monitoring Target: Optical Attenuation on the H3C 10508

**Auto-discovery rule:**

1. Key: ifDescr
2. SNMP OID: `discovery[{#SNMPVALUE},IF-MIB::ifDescr]`

**RX power (using Huawei's OIDs)**

1. Name: RX-{#SNMPVALUE}
2. Key: `enterprises.2011.10.2.70.1.1.1.12[{#SNMPVALUE}]`
3. SNMP OID: `.1.3.6.1.4.1.2011.10.2.70.1.1.1.12.{#SNMPINDEX}`

**TX power**

1. Name: TX-{#SNMPVALUE}
2. Key: `enterprises.2011.10.2.70.1.1.1.9[{#SNMPVALUE}]`
3. SNMP OID: `.1.3.6.1.4.1.2011.10.2.70.1.1.1.9.{#SNMPINDEX}`

**RX power (using H3C's OIDs)**

1. Name: RX-{#SNMPVALUE}
2. Key: `enterprises.25506.2.70.1.1.1.12[{#SNMPVALUE}]`
3. SNMP OID: `.1.3.6.1.4.1.25506.2.70.1.1.1.12.{#SNMPINDEX}`

**TX power**

1. Name: TX-{#SNMPVALUE}
2. Key: `enterprises.25506.2.70.1.1.1.9[{#SNMPVALUE}]`
3. SNMP OID: `.1.3.6.1.4.1.25506.2.70.1.1.1.9.{#SNMPINDEX}`

If the OIDs above don't work, try the ones below — that should basically let you query everything.

Verification with a Linux command:

```shell
snmpwalk -v 2c -c hequan <switch-ip> <oid>
```
