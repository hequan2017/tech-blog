> **About this post**
>
> This post is a minimal quick note on deploying Zabbix: clone the official zabbix-docker
> repository and switch to the 6.0 branch, symlink the v3 Alpine + MySQL compose file as
> docker-compose.yaml, then bring up the whole monitoring stack with a single
> docker-compose command.

> **Technical notes**
>
> Zabbix 6.0 is an LTS release now in its limited support period (officially supported
> until February 2027); as of 2026 the latest LTS is 7.0 (supported until mid-2029),
> and 8.0 LTS has not yet been released. Compose files with the `_latest` suffix use
> rolling tags such as `alpine-6.0-latest`, which automatically follow minor-version
> updates within the 6.0 branch; to lock a version, pin the image tag to a specific
> minor version (of the form `alpine-6.0.x`). The standalone `docker-compose` (V1)
> was discontinued in June 2023; new environments should use `docker compose` (the
> V2 plugin) instead. Alpine base images do not include tzdata by default, and the
> official `TZ` variable mainly affects the web UI timezone; if you need the
> container's local timezone to be Beijing time, switch to the Ubuntu-based compose
> files or install tzdata yourself.

---

```shell
# Download the docker-compose file
git clone https://github.com/zabbix/zabbix-docker.git

# Start the services
cd zabbix-docker
git checkout 6.0  # switch to the 6.0 branch for a 6.0 installation
ln -s docker-compose_v3_alpine_mysql_latest.yaml docker-compose.yaml  # create a symlink
docker-compose up -d
```
