> **About this post**
>
> This post covers two kinds of password problems with MariaDB on CentOS 7: two ways to change the root password for the first time — `mysqladmin -u root -p[oldpass] password newpass` (note that no space is allowed between the old password and `-p`), or running the `mysql_secure_installation` initialization wizard and following its prompts; and two rescue methods for a forgotten password — starting `mysqld_safe --skip-grant-tables` in grant-free mode, then updating the `user` table to change the password and running `flush privileges`, or adding `skip-grant-tables` to the `[mysqld]` section of `/etc/my.cnf` and changing the password after a restart.

> **Technical notes**
>
> CentOS 7 reached end of life (EOL) on June 30, 2024; migrating to Rocky Linux 9 / AlmaLinux 9 or the homegrown openEuler is recommended.
>
> In newer MariaDB versions (10.4+), root uses unix_socket authentication by default, and the password column of the `mysql.user` table has been merged into `authentication_string`; the password-reset SQL needs to be adjusted for the new syntax.

## 1. Changing the Password for the First Time

### Method 1: mysqladmin

```shell
mysqladmin -u root -p[oldpass] password newpass
```

Note that `oldpass` (the old password) is optional; if the root default password is empty, you do not need to enter it. If you need to change an existing password, make sure there is no space between the old password and `-p`, otherwise an error will be reported; also, `password` and `newpass` (the new password) are separated by a space.

### Method 2: Initialize the database

```shell
/usr/local/mysql/bin/mysql_secure_installation
# path is /usr/bin/mysql_secure_installation when installed via yum
```

The initialization then begins; just follow the prompts one by one.

## 2. Handling a Forgotten Password

### Method 1: mysqld_safe grant-free mode

```shell
systemctl stop mariadb              # stop the mariadb database
mysqld_safe --skip-grant-tables &   # enter standalone mode
mysql
```

```sql
use mysql;      -- enter the mysql database
update user set password=password('newpass') where user='root' and host='localhost';  -- set the new password
flush privileges;   -- flush the privileges
```

Open a new window and test shutting down the database with the new password; a successful shutdown proves the change worked:

```shell
mysqladmin -uroot -p shutdown
systemctl restart mariadb            # restart the service
```

### Method 2: Add skip-grant-tables to the configuration file

```ini
vim /etc/my.cnf

[mysqld]
skip-grant-tables    # add this line, save, then restart the service
```

After the restart, `mysql` logs you in directly and you can change the password as described above.

Note: the original post also mentions the variable `skip_name_resolve = ON` (skips reverse resolution of hostnames; not directly related to password reset).
