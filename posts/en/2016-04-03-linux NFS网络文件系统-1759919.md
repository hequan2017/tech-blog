> **About this post**
>
> This post deploys NFS on CentOS 6.5: install rpcbind and nfs-utils,
> start rpcbind first and then nfs, and check port registration with
> rpcinfo; configure /etc/exports to share /data with 192.168.10.0/24,
> smoothly reload with exportfs, inspect with showmount, and mount on
> the client with mount -t nfs; it analyzes parameters such as nfsnobody
> (UID 65534), root_squash/all_squash, and anonuid/anongid, plus the
> practice of unifying UIDs; the ending compares fstab and rc.local as
> two ways to mount automatically at boot, and includes the rescue-mode
> command for remounting a read-only file system.

> **Technical notes**
>
> CentOS 6 reached end of life (EOL) in November 2020; production
> environments are advised to migrate to Rocky Linux / AlmaLinux /
> Ubuntu LTS. Addendum: on CentOS 7+ service management switches to
> `systemctl start nfs-server`; NFSv4 only needs port 2049, and its
> dependency on rpcbind differs from the mixed v3/v4 scenario in this
> post; the usage of showmount/exportfs is unchanged.

## 1. Environment and Software Installation

```shell
# cat /etc/centos-release
CentOS release 6.5 (Final)
# uname -r
2.6.32-431.el6.x86_64
# uname -m
x86_64
# ls /lib/modules/2.6.32-431.el6.x86_64/kernel/fs/
```

Network File System: the kernel ships with file system module support
(you can also see modules such as xfs in the fs directory above).

Installation (nfs-utils provides rc.nfsd and rpc.mountd; rpcbind handles
port registration):

```shell
# rpm -qa rpcbind nfs-utils
# yum groupinstall "NFS file server" -y
# yum -y install rpcbind nfs-utils
```

## 2. Starting Services and Verification

Start rpcbind first, then nfs:

```shell
# /etc/init.d/rpcbind start
# ps -ef | grep rpc

# rpcinfo -p localhost

100000    4   tcp    111  portmapper
# /etc/init.d/nfs start
# chkconfig nfs on
# chkconfig rpcbind on
```

## 3. Configuring the Share and Mounting

```shell
# vi /etc/exports
# nfs shared data by hequan at 20160403
/data      192.168.10.0/24(rw,sync)
```

Smooth reload and inspection:

```shell
# /etc/init.d/nfs reload          # smooth restart, same as /usr/sbin/exportfs -r
# showmount -e localhost
Export list for localhost:
/data 192.168.10.0/24
```

Client-side mounting, plus granting local write permission to the shared
directory:

```shell
# mount -t nfs 192.168.10.10:/data /mnt     # mount
# chmod o+w /data                          # local permissions on the shared directory
-rw-r--r-- 1 nfsnobody nfsnobody 0 Mar 27 22:31 xx
```

Command quick reference (run man with the process name for details):

- /etc/exports: NFS configuration file
- /usr/sbin/exportfs: NFS administration command; `-rv` applies the
  configuration, equivalent to a graceful restart, sharing the
  directories directly
- /usr/sbin/showmount: view the NFS configuration and mount results
- /var/lib/nfs/etab: the full set of default parameters
- mount: view mount information

```shell
# mount
192.168.10.10:/data on /mnt type nfs (rw,vers=4,addr=192.168.10.10,clientaddr=192.168.10.11)
```

## 5. Common exports Options

Format: absolute path + client (parameters). Three essentials of a
share: the absolute path, the local permissions on the shared directory
(nfsnobody), and the client network segment 192.168.10.0/24.

- rw / ro: read-write / read-only
- sync / async (synchronous / asynchronous): async is faster (data is
  written to memory first) but unreliable — a trade-off between
  performance and reliability
- root_squash: maps root to the anonymous user
- all_squash: squashes all client users into the anonymous user (65534),
  ensuring that all servers have identical permissions on the NFS shared
  directory
- anonuid / anongid: the mapping targets for the anonymous user; every
  client and the server must have the same UID and GID (the UID of
  nfsnobody)

Example of unifying UIDs — create users with the same UID on both ends:

```shell
# useradd hequan -u 555
```

```shell
# vim /etc/exports
/data    192.168.10.0/24(rw,sync,all_squash,anonuid=555,anongid=555)
# mount 192.168.10.10:/data /mnt
```

## 6. Official Example

The EXAMPLE from man exports:

```text
# sample /etc/exports file
/               master(rw) trusty(rw,no_root_squash)
/projects       proj*.local.domain(rw)
/usr            *.local.domain(ro) @trusted(rw)
/home/joe       pc001(rw,all_squash,anonuid=150,anongid=100)
/pub            *(ro,insecure,all_squash)
/srv/www        -sync,rw server @trusted @external(ro)
/foo            2001:db8:9:e54::/64(rw) 192.0.2.0/24(rw)
/build          buildhost[0-9].local.domain(rw)
```

## 7. Automatic Mounting at Boot

Write the mount entry into fstab:

```shell
# vi /etc/fstab
192.168.10.10:/data /mnt/ nfs defaults 0 0
```

After saving and exiting:

```shell
# mount -a
```

Or write it into rc.local:

```shell
# vi /etc/rc.local
/etc/init.d/rpcbind start
/bin/mount -t nfs 192.168.10.10:/data /mnt
```

Boot flow: the power-on self-test loads the BIOS → read the MBR → boot
loader → load the kernel → the init process → init executes rc.sysinit →
start kernel modules → run the scripts for the different runlevels.

Loading network NFS file systems from fstab is not recommended (the boot
hangs if the network is not ready); for automatic mounting, see the next
post on autofs.

## 8. Rescue Mode

In maintenance or rescue mode the file system is read-only:

```shell
# mount -o rw,remount /       # remount as writable
```
