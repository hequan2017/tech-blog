> **About this post**
>
> A record of common operations for MySQL composite indexes: adding a
> (time, id, name) composite unique index to the net table, and dropping
> that index. Also includes the accompanying SQL: finding duplicate values
> by a combination of columns, and keeping the row with the smallest id
> when deleting duplicate records.

> **Technical notes**
>
> - Composite indexes follow the leftmost prefix principle: the query
>   conditions must include the leftmost column `time` for the index
>   to be hit effectively.
> - When `ADD UNIQUE KEY(time, id, name)` does not explicitly name the
>   index, the index name defaults to the first column's name, so the
>   drop is written as ``DROP INDEX `time` ``.
> - For large production tables, add indexes during off-peak hours;
>   InnoDB on MySQL 5.6+ supports INPLACE online index creation,
>   allowing concurrent reads and writes.
> - Wrapping the deduplication subquery in a derived table
>   `(SELECT * FROM net)` works around MySQL's restriction that a
>   subquery in a DELETE cannot reference the target table directly.

---

```sql
-- Add the composite index

ALTER TABLE net
ADD UNIQUE KEY (time, id, name);

-- Drop the composite index

ALTER TABLE net DROP INDEX `time`;

-- Find duplicate values

SELECT *
FROM `net`
WHERE ( `time`, `id`, `name` ) IN (
    SELECT `time`, `id`, `name` FROM `net`
    GROUP BY `time`, `id`, `name` HAVING COUNT(1) > 1
)
AND `id` NOT IN (
    SELECT MIN(`id`) FROM (SELECT * FROM `net`) b
    GROUP BY `time`, `id`, `name` HAVING COUNT(1) > 1
);

-- Delete duplicates, keeping the row with the smallest ID

DELETE FROM `net`
WHERE ( `time`, `id`, `name` ) IN (
    SELECT `time`, `id`, `name` FROM (SELECT * FROM `net`) a
    GROUP BY `time`, `id`, `name` HAVING COUNT(1) > 1
)
AND `id` NOT IN (
    SELECT MIN(`id`) FROM (SELECT * FROM `net`) b
    GROUP BY `time`, `id`, `name` HAVING COUNT(1) > 1
);
```
