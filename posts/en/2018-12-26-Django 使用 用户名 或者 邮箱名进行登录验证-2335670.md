> **About this post**
>
> This post shows how to let Django support login with either a username or an
> email address: define a custom authentication backend CustomBackend that
> inherits from ModelBackend and overrides authenticate(), using
> Q(username=username) | Q(email=username) to look up the user, and returning
> the user object once check_password passes; then specify this backend in
> AUTHENTICATION_BACKENDS in settings.py to make it take effect.

> **Technical notes**
>
> Passing the request argument to `authenticate()` requires Django 1.11 or
> later; this approach still works in Django 2.x through 5.x. Two caveats:
> swallowing the exception entirely in the except block and returning None
> hides problems, so at least log it; and when a username happens to equal
> another user's email, the combined Q query may match multiple rows, so
> get() raises MultipleObjectsReturned, which likewise falls into the except
> branch and returns None (login failure).

---

## 1. views.py: Custom Authentication Backend

```python
from django.contrib.auth.backends import ModelBackend
from django.db.models import Q
from django.contrib.auth.models import AbstractUser, Group, User

class CustomBackend(ModelBackend):
    """Allow login with email as well"""
    def authenticate(self, request, username=None, password=None, **kwargs):
        try:
            user = User.objects.get(Q(username=username) | Q(email=username))
            if user.check_password(password):
                return user
        except Exception as e:
            return None
```

## 2. settings.py: Enable the Backend

```python
AUTHENTICATION_BACKENDS = ('system.views.CustomBackend',)
```

Once configured, either the username or the bound email address entered in the login form will pass authentication.
