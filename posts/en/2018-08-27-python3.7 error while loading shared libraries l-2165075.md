> **About this post**
>
> How to fix the `error while loading shared libraries: libpython3.7m.so.1.0: cannot open shared object file` error after building and installing Python 3.7 from source: the dynamic linker cannot find the compiled shared library, so simply copy the library file into the system library directory.

> **Technical notes**
>
> Besides copying the `.so` file directly to `/usr/lib64` as shown in the post, the more standard approach is to configure the build with `--enable-shared --prefix=/usr/local`, and after installation run `echo /usr/local/lib >> /etc/ld.so.conf.d/python3.conf && ldconfig` to refresh the linker cache. Python 3.7 stopped receiving security updates in June 2023; use 3.10+ for new environments.

---

```text
python3.7: error while loading shared libraries: libpython3.7m.so.1.0: cannot open shared object file: No such file or directory
```

Solution:

Go to the source package directory and copy the compiled shared library file into the system library directory:

```shell
[root@stack Python-3.7.0]# cp libpython3.7m.so.1.0 /usr/lib64/
```

(The redacted library filename in the original post should be `libpython3.7m.so.1.0`; if the error persists after copying, run `ldconfig` to refresh the linker cache.)
