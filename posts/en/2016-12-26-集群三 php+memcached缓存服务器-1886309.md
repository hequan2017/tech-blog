> **About this post**
>
> Third post in the cluster series: compile and install PHP 5.6.22 (after building the
> libiconv/libmcrypt/mhash/mcrypt dependency libraries), share the /data/web directory
> to four backends via NFS; install Memcached 1.4.33 from source (depends on libevent)
> plus the memcache extension for PHP, then use magent + keepalived to front two
> memcached instances with a master/backup VIP (192.168.50.199:12000). It also calls out
> the cache-penetration risk when a failed node recovers and the firewall
> connection-tracking table issue; finally it deploys Discuz with memcache support
> enabled and verifies the hit count via telnet stats.

> **Technical notes**
>
> CentOS 7 reached end of life (EOL) on June 30, 2024; consider migrating to Rocky
> Linux 9 / AlmaLinux 9 or the domestic openEuler. PHP 5.6 also ended security
> maintenance at the end of December 2018; the `--enable-safe-mode` and
> `--enable-magic-quotes` options were removed as of PHP 5.4, so building under 5.6
> produces unrecognized options warnings — it is recommended to simply delete them.
>
> magent has long been unmaintained, and failover loses the master node's data; for a
> new architecture, prefer memcached's own consistent-hashing clients or switch to a
> Redis + cluster solution.

## 4. Install Memcached 1.4.33

Download and compile libevent and memcached:

```shell
cd /tmp
wget http://downloads.sourceforge.net/levent/libevent-2.0.22-stable.tar.gz
wget http://www.memcached.org/files/memcached-1.4.33.tar.gz

tar zxvf libevent-2.0.22-stable.tar.gz
cd libevent-2.0.22-stable
./configure --prefix=/usr/local/
make && make install
ls -al /usr/local/lib | grep libevent-

cd /tmp
tar zxvf memcached-1.4.33.tar.gz
cd memcached-1.4.33
./configure --with-libevent=/usr/local/ --enable-64bit --enable-threads
make && make install
ls -al /usr/local/bin/memcached
```

Create the runtime user and directory:

```shell
groupadd memcached
useradd -g memcached memcached

cd /var/run
mkdir memcached
chown -R memcached.memcached memcached
```

Configure the SysV service script:

```shell
cp /tmp/memcached-1.4.33/scripts/memcached.sysv /etc/init.d/memcached
chown memcached.memcached /etc/init.d/memcached
chmod 755 /etc/init.d/memcached
vim /etc/init.d/memcached
```

```ini
PORT=11211
USER=memcached
MAXCONN=1024
CACHESIZE=128
OPTIONS=""
```

Change the startup command line to:

```shell
/usr/local/bin/memcached -d -p $PORT -u $USER -m $CACHESIZE -c $MAXCONN -P /var/run/memcached/memcached.pid $OPTIONS
```

Start it:

```shell
chkconfig --add memcached
chkconfig --level 235 memcached on
chkconfig --list memcached

service memcached start
ps -ef | grep memcached
service memcached stop
```

## 6. keepalived + magent High Availability

`/etc/keepalived/keepalived.conf` on the master memcache node (do not start
keepalived or memcached at boot):

```ini
! Configuration File for keepalived
global_defs {
 router_id  mem1
}
vrrp_script chk_magent {
  script "/opt/magent.sh"
  interval 2
}
vrrp_script chk_memcached {
   script "killall -0 memcached"
   interval 1
   weight -20
}
vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id  101
    priority 100
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    virtual_ipaddress {
        192.168.50.199/24
    }
    track_script {
        chk_magent
        chk_memcached
        }
   notify_master  "/etc/keepalived/changemail.py master"
   notify_backup  "/etc/keepalived/changemail.py backup"
   notify_fault   "/etc/keepalived/changemail.py fault"
}
```

`/opt/magent.sh` (starts magent as long as keepalived is alive):

```bash
#!/bin/bash
k=`ps -ef |grep keepalived |grep -v grep |wc -l`
if [ $k -gt 0 ];then
    /usr/local/magent/magent -u root -n 51200 -l 192.168.50.199 -p 12000 -s 192.168.50.63:11211 -b 192.168.50.64:11211
else
    pkill -9 magent
fi
```

`/etc/keepalived/keepalived.conf` on the backup memcache node:

```ini
! Configuration File for keepalived
global_defs {
 router_id  mem2
}
vrrp_script chk_magent {
        script "/opt/magent.sh"
        interval 2
}
vrrp_script chk_memcached {
   script "killall -0 memcached"
   interval 1
   weight -20
}
vrrp_instance VI_1 {
    state BACKUP
    interface eth0
    virtual_router_id  101
    priority 90
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    virtual_ipaddress {
        192.168.50.199/24
    }
    track_script {
       chk_magent
       chk_memcached
        }
   notify_master  "/etc/keepalived/changemail.py master"
   notify_backup  "/etc/keepalived/changemail.py backup"
   notify_fault   "/etc/keepalived/changemail.py fault"
}
```

`/opt/magent.sh` (starts magent only when this node holds the VIP):

```bash
#!/bin/bash
k=`ip a |grep 192.168.50.199 |wc -l`
if [ $k -gt 0 ];then
        /usr/local/magent/magent -u root -n 51200 -l 192.168.50.199 -p 12000 -s 192.168.50.53:11211 -b 192.168.50.64:11211
else
    pkill -9 magent
fi
```

### Caveats

After a failed memcached node is repaired, cached data will not flow back to the
repaired node. If the master node designated by magent fails, the master node's cache
data is lost, and after repair you must not restart the memcached service right away:
if you do, clients will query the master node's data, and a high-concurrency website
will bring the database to its knees. Therefore, it is recommended to start the
memcached master node service during an off-peak business period, and then designate
the master and backup cache nodes again through magent.

1. If memcached handles heavy read/write traffic, you must either turn off the
   firewall or configure it not to use the connection-tracking table; otherwise
   /var/log/message will report
   `kernel: nf_conntrack: table full, dropping packet`.
   For details, see http://blog.csdn.net/yanggd1987/article/details/45886913
   and https://my.oschina.net/kisops/blog/150995.
2. After stopping the firewall with `service iptables stop`, do not check it with
   `iptables -L -vnx`, because that command turns the firewall back on — although the
   rules are empty, the connection-tracking table is still being recorded.

## 7. PHP memcache Extension

```shell
cd /tmp
tar zxvf /software/memcache-3.0.8.tgz -C /tmp
cd memcache-3.0.8
/usr/local/php/bin/phpize
./configure --enable-memcache --with-php-config=/usr/local/php/bin/php-config --with-zlib-dir
make
make install
```

`vim /usr/local/php/etc/php.ini`:

```ini
extension_dir = "/usr/local/php/lib/php/extensions/no-debug-non-zts-20131226/"
extension = "memcache.so"
[Memcache]
memcache.allow_failover = 1
memcache.max_failover_attempts = 20
memcache.chunk_size = 8192
```

## 8. Deploy Discuz and Verify

Unpack and deploy:

```shell
unzip /software/Discuz_X3.2_SC_UTF8.zip -d /discuz/
chmod -R 777 /discuz/
```

Enable memcache support, `vim /discuz/upload/config/config_global.php`:

```php
$_config['memory']['memcache']['server'] = '192.168.50.199';   // magent proxy server address
$_config['memory']['memcache']['port'] = 12000;
$_config['memory']['memcache']['pconnect'] = 1;
$_config['memory']['memcache']['timeout'] = 1;
```

Verify cache hits with telnet:

```shell
yum install -y telnet
telnet 192.168.50.199 12000
stats
```

STAT cmd_set 37
STAT cmd_flush 0
STAT cmd_touch 0
