> **About this post**
>
> This post summarizes how to configure and inspect the three MySQL log types
> (error log, general/slow query log, and binary log), and explains the
> differences among the statement/row/mixed binlog formats. It also compares
> the MyISAM and InnoDB engines in terms of features, file structure, and
> tuning essentials, and gives two examples of changing a table's engine.

> **Technical notes**
>
> The examples are based on MySQL 5.5/5.6. InnoDB has been the default engine
> since 5.5.5; the slow-query-related parameters were renamed
> slow_query_log / slow_query_log_file in 5.6; the default binlog format
> changed to ROW in 5.7/8.0 (not mixed as stated in the post); and 8.0 also
> removed the query cache, so the query_cache_size tuning mentioned here no
> longer applies.

---

## 1. Log Types at a Glance

- Error log: service startup and shutdown
- Query log
  - General query log: client connections and SQL
  - Slow query log: queries whose execution time exceeds a specified value
- Binary log: records information about data modifications

## 2. Error Log

```ini
# vim /etc/my.cnf
[mysqld_safe]
log-error=/data/3306/mysql_oldboy3306.err
```

## 3. General Query Log and Slow Query Log

General query log:

```shell
mysql> show variables like 'general_log%';    # general query log parameters
```

```text
+------------------+----------------------------------+
| Variable_name    | Value                            |
+------------------+----------------------------------+
| general_log      | OFF                              |
| general_log_file | /application/mysql/data/lnmp.log |
+------------------+----------------------------------+
```

```shell
mysql> set global general_log = ON;
```

Slow query log:

```ini
long_query_time = 1                      # log queries exceeding (greater than) 1 second; default is 10 seconds
log-slow-queries = /data/3306/slow.log
log-queries-not-using-indexes            # queries not using indexes are also logged
log-long-format                          # log lots of information: update log, binary update log, and slow query log
log-short-format                         # log less information
```

```shell
mysql> show global status like '%slow%';
```

```text
+---------------------+----------+
| Variable_name       | Value    |
+---------------------+----------+
| Slow_launch_threads | 0        |    # 值较大 说明有些东西正在延迟链接的新线程
| long_query_time     | 1.000000 |
| Slow_queries        | 0        |    # 慢查询的记录数
| log_slow_queries    | ON       |    # 是否开启
+---------------------+----------+
2 rows in set (0.00 sec)
```

## 4. Binary Log

```ini
log-bin=mysql-bin
```

```shell
mysql> show variables like '%log_bin%';
```

```text
+---------------+-------+
| Variable_name | Value |
+---------------+-------+
| log_bin       | ON    |
| sql_log_bin   | ON    |    # 临时不记录binlog 用mysql恢复时,可以临时打开
+---------------+-------+
```

Three binlog modes:

- statement level: every SQL statement that modifies data is logged; there is no need to record the change of each row
- Row level: logs the modification of every row, and the slave then applies the same changes to its data; the binlog is large
- mixed: a mix of the two modes above

```shell
mysql> show variables like '%binlog_format%';
```

```text
+---------------+-----------+
| Variable_name | Value     |
+---------------+-----------+
| binlog_format | STATEMENT |
+---------------+-----------+
```

```shell
mysql> set global binlog_format = 'ROW';    # temporary global change; exit and log back in
mysqlbinlog --no-defaults --base64-output=decode-rows -v mysql-bin.000004    # view a ROW-format log file
```

```ini
binlog_format=mixed    # set in my.cnf; the officially recommended mode
```

## 5. MyISAM Engine

Key parameter: `key_buffer_size = 2048M`

Characteristics:

- No transaction support
- Table-level locking
- Reads and writes block each other
- Caches indexes only
- Fast reads and writes with relatively low resource usage
- No foreign key constraints, but full-text indexing is supported
- The default storage engine before 5.5.5

Tuning essentials:

- Set up appropriate indexes
- Adjust read/write priorities so that important operations run first, according to actual needs
- Enable delayed inserts to improve bulk write performance
- Keep operations sequential so that inserts append to the end of the table, reducing blocking
- Break up large, long-running operations to shorten the blocking time of any single operation
- Reduce concurrency; in some high-concurrency scenarios, use application-level queuing
- For relatively static data, making full use of query_cache_size or a memcached caching service can greatly improve access efficiency
- count is especially efficient only when a full table scan is done: `select count(*) from he.quan;`
- You can use InnoDB on the master and MyISAM on the slave in master-slave replication (not recommended)

File composition (under the data/mysql directory):

```text
-rw-rw---- 1 mysql mysql  10630 3月  28 01:04 user.frm     # 文件保存表的定义
-rw-rw---- 1 mysql mysql   1212 4月   6 07:20 user.MYD     # 数据文件
-rw-rw---- 1 mysql mysql   2048 4月   6 07:27 user.MYI     # 索引文件
-rw-rw---- 1 mysql mysql 134217728 4月  7 02:15 ibdata1    # InnoDB的共享表空间
```

## 6. InnoDB Engine

Characteristics:

- **Supports transactions** and ACID, with the 4 transaction isolation levels
- **Row-level locking**
- Read/write blocking depends on the transaction isolation level
- Highly efficient caching: **caches both indexes and data**
- The whole table and primary key are stored in a clustered layout, forming a balanced tree
- Supports partitions and tablespaces, similar to the Oracle database
- Supports **foreign key constraints**; full-text indexing was not supported before 5.5, but is supported in later versions
- Has higher hardware requirements than MyISAM

Tuning essentials:

- Keep the primary key as small as possible
- Avoid full table scans, because they use table locks
- Cache as many indexes and as much data as possible to improve response time and reduce disk I/O consumption
- For bulk small inserts, control the transactions yourself instead of relying on autocommit
- Set the innodb_flush_log_at_trx_commit parameter sensibly; do not chase safety excessively. If = 0, the log buffer is flushed to the log file on disk once per second, and nothing is done when a transaction commits
- Avoid primary key updates, because they cause a large amount of data movement

Key parameter (see `/application/mysql/support-files/my-innodb-heavy-4G.cnf`):

```ini
innodb_buffer_pool_size = 2048M    # caches InnoDB table indexes, data, and insert buffering; 70%-80% of OS memory is optimal
```

## 7. Viewing and Changing Storage Engines

```shell
mysql> show engines;    # storage engines
```

Output of `show engines`:

```text
+--------------------+---------+----------------------------------------------------------------+--------------+------+------------+
| Engine             | Support | Comment                                                        | Transactions | XA   | Savepoints |
+--------------------+---------+----------------------------------------------------------------+--------------+------+------------+
| MRG_MYISAM         | YES     | Collection of identical MyISAM tables                          | NO           | NO   | NO         |
| CSV                | YES     | CSV storage engine                                             | NO           | NO   | NO         |
| MEMORY             | YES     | Hash based, stored in memory, useful for temporary tables      | NO           | NO   | NO         |
| BLACKHOLE          | YES     | /dev/null storage engine (anything you write to it disappears) | NO           | NO   | NO         |
| MyISAM             | YES     | MyISAM storage engine                                          | NO           | NO   | NO         |
| FEDERATED          | NO      | Federated MySQL storage engine                                 | NULL         | NULL | NULL       |
| ARCHIVE            | YES     | Archive storage engine                                         | NO           | NO   | NO         |
| InnoDB             | DEFAULT | Supports transactions, row-level locking, and foreign keys     | YES          | YES  | YES        |
| PERFORMANCE_SCHEMA | YES     | Performance Schema                                             | NO           | NO   | NO         |
+--------------------+---------+----------------------------------------------------------------+--------------+------+------------+
```

Changing the engine:

```shell
mysql> alter table test engine = MyISAM;    # change the engine of the test table
```

```shell
/application/mysql/bin/mysql_convert_table_format --user=root --password=123456 -engine=MyISAM hequan test
```
