> **About this post**
>
> This post explains the basic networking concepts and operations after installing OpenStack with packstack: the relationship between tenants (tenant/project) and users, and using VXLAN to partition tenant networks. The main focus is how to bridge the physical NIC eth0 to the Open vSwitch br-ex bridge as the packet egress (turning ifcfg-eth0 into an OVSPort and ifcfg-br-ex into an OVSBridge that carries the original IP). It then shows how an administrator creates the external network put-ex (VXLAN, segment ID 1) and its subnet put-ip (192.168.2.0/24, DHCP allocation pool and DNS) in the Dashboard, and finally creates a project and a new user, who logs in to create the internal network, a router, and add ports, connecting the internal and external networks.

> **Technical notes**
>
> The ifcfg-* NIC script style used here belongs to the RHEL/CentOS 7 era network-scripts framework; CentOS 7 reached EOL in June 2024. Rocky/Alma 9 have switched to NetworkManager keyfiles, and it is recommended to configure an OVS bridge with nmcli or ovs-vsctl commands. The idea of VXLAN tenant isolation is still broadly applicable today, but new Neutron deployments mostly use OVN instead of the OVS ML2 plugin.

## 1. Tenants and VXLAN

An organization renting this service is called a "tenant / project". Users are created under a tenant. The networks of different tenants are isolated and partitioned from one another via VXLAN.

## 2. Checking the NIC Status After Installation

Whichever network you want to use as the packet egress, that **NIC should be bridged to br-ex**.

## 3. Configuring the NIC (Key Step)

Change eth0 into an OVS port attached to br-ex, and move the IP address onto br-ex:

```shell
[root@h1 network-scripts]# cat ifcfg-eth0
  DEVICE=eth0
  DEVICETYPE=ovs
  TYPE=OVSPort
  OVS_BRIDGE=br-ex
  ONBOOT=yes
  BOOTPROTO=none
[root@h1 network-scripts]# cat ifcfg-br-ex
DEVICE=br-ex
DEVICETYPE=ovs
TYPE=OVSBridge
ONBOOT=yes
BOOTPROTO=none
IPADDR=192.168.1.201
NETMASK=255.255.255.0
GATEWAY=192.168.1.1
DNS1=202.106.0.20
```

After restarting the network, eth0 is subsumed under ovs-system and the IP is carried by br-ex:

```text
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq master ovs-system state UP qlen 1000
    link/ether 00:50:56:a0:b6:6b brd ff:ff:ff:ff:ff:ff
3: ovs-system: <BROADCAST,MULTICAST> mtu 1500 qdisc noop state DOWN
    link/ether d2:18:7d:5e:5e:b9 brd ff:ff:ff:ff:ff:ff
5: br-ex: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UNKNOWN
    link/ether 00:50:56:a0:b6:6b brd ff:ff:ff:ff:ff:ff
    inet 192.168.1.201/24 brd 192.168.1.255 scope global br-ex
       valid_lft forever preferred_lft forever
```

## 5. Creating the Internal Network and Router as a Regular User

Create a project (tenant), then create a new user and associate it with that project. After logging in to the Dashboard as the new user:

1. Create the internal network first;
2. then create a router connected to the external network;
3. finally, add an internal network port to the router, connecting the internal and external networks.
