> **About this post**
>
> This post is a checklist of basic server performance benchmarks: it uses
> sysbench (installed from source) to run the CPU and memory benchmarks and
> explains output fields such as events/s, latency percentiles, and thread
> fairness; disk I/O is tested with fio, covering random read/write IOPS and
> sequential read/write throughput separately, with a parameter-by-parameter
> explanation of direct, iodepth, ioengine, bs, runtime, and more; finally it
> uses dig to measure DNS resolution time, and mtr to measure per-hop packet
> loss and latency to the public internet, explaining what each output column
> means.

> **Technical notes**
>
> - On newer systems there is no need to build from source: the EPEL
>   repository lets you `yum install sysbench fio` directly (sysbench 1.0+
>   uses the `sysbench cpu run` command style, consistent with this post).
> - fio raw-disk tests (-filename=/dev/xxx) destroy the data on the disk; on
>   cloud servers, use a test file path or a temporary disk instead. Only
>   `-direct=1`, which bypasses the cache, reflects real disk performance.
> - The typo in the original ("most frequent latency") has been corrected to
>   "longest latency".

## 1. Installing the tools

```shell
## Install sysbench
wget https://codeload.github.com/akopytov/sysbench/zip/master

unzip master
cd sysbench-master/
./autogen.sh
./configure  --prefix=/usr/local/sysbench
make
make install

## Test disk read/write
yum install fio -y

##
yum install mtr sysstat  -y
```

> ⚠️ Note: **Do not run fio tests on a disk or partition that contains data — it will destroy the existing data.**

## 3. Disk I/O tests (fio)

Before running the following tests, make sure the disk is 4K aligned.

```shell
Test random write IOPS:
fio -direct=1 -iodepth=128 -rw=randwrite -ioengine=libaio -bs=4k -size=1G -numjobs=1 -runtime=1000 -group_reporting -filename=/dev/[device] -name=Rand_Write_Testing
Test random read IOPS:
fio -direct=1 -iodepth=128 -rw=randread -ioengine=libaio -bs=4k -size=1G -numjobs=1 -runtime=1000 -group_reporting -filename=/dev/[device] -name=Rand_Read_Testing

Test write throughput:
fio -direct=1 -iodepth=64 -rw=write -ioengine=libaio -bs=1024k -size=1G -numjobs=1 -runtime=1000 -group_reporting -filename=/dev/[device] -name=Write_PPS_Testing
Test read throughput:
fio -direct=1 -iodepth=64 -rw=read -ioengine=libaio -bs=1024k -size=1G -numjobs=1 -runtime=1000 -group_reporting -filename=/dev/[device] -name=Read_PPS_Testing
```

## 4. Explanation of fio parameters

```text
-direct=1
Ignores the IO cache during the test; data is written directly to disk.

-rw=randwrite
The read/write policy for the test. Possible values: randread (random read), randwrite (random write), read (sequential read), write (sequential write), randrw (mixed random read/write).

-ioengine=libaio
The test uses libaio (Linux AIO, asynchronous IO). Applications usually issue IO in two ways: synchronous and asynchronous. Synchronous IO can issue only one IO request at a time and waits for the kernel to finish it before returning, so iodepth is always less than 1 for a single thread; this can be worked around by running multiple threads concurrently, typically using 16-32 threads working at the same time to fill up the iodepth. Asynchronous IO, usually via libaio, submits a whole batch of IO requests at once and then waits for the batch to complete, reducing the number of interactions and making it more efficient.

-bs=4k
The block size for a single I/O is 4k. The default when this parameter is omitted is also 4k.

-size=1G
The test file size is 1G.

-numjobs=1
The number of test threads is 1.

-runtime=1000
The test runs for 1000 seconds. If this is not configured, fio keeps writing the file of the size given by -size, in chunks of the -bs value, until it is fully written.

-group_reporting
The result display mode: group_reporting means the statistics of all processes are summarized together, rather than being reported per job.

-filename=/dev/[device]
Specifies the name of the test file (device). Testing a raw disk yields real disk performance, but testing a raw disk directly destroys the file system structure — back up your data before testing.

-name=Rand_Write_Testing
The test task name.
```

Sample output:

```text
write: io=1024.0MB, bw=6355.9KB/s, iops=1588, runt=164979msec
```

This means fio performed 1 GB of I/O at roughly 6 MB/s, with 1588 total IOPS over a run time of 164 seconds. Judging by the IOPS value, the IOPS performance of this SSD cloud disk is 1588.

## 5. DNS and network tests

```shell
dig  www.qq.com
;; Query time: 3 msec
```

Use mtr to measure public internet latency and packet loss:

```shell
mtr -r  42.62.55.58  -c 15
Start: Fri Dec 29 11:35:03 2017
HOST: 111                         Loss%   Snt   Last   Avg  Best  Wrst StDev
  1.|-- 42.62.55.58                0.0%    15    0.3   0.3   0.3   0.4   0.0
```

Meaning of each column:

- Second column, Snt: the number of trace rounds; the default is 10, customizable via the `-c` parameter, e.g. `mtr -r -c 15 202.108.33.94`
- Third column, Loss: the packet loss rate for each corresponding IP
- Fourth column, Last: the latency of the most recent reply
- Fifth column, Avg: the average, i.e. the average latency of the sent ping packets
- Sixth column, Best: the best, i.e. the shortest latency
- Seventh column, Wrst: the worst, i.e. the longest latency
- Eighth column, StDev: the standard deviation
