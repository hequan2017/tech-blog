> **About this post**
>
> This post covers the basics of SSH (Secure Shell Protocol, default port 22, protocol version ssh2): the division of labor between the server-side OpenSSH and openssl, the sshd process and the sshd_config configuration file; RSA/DSA public and private keys, and the generation of known_hosts on first connection; the risk that SSH v1 no longer checks the key pair when exchanging data, and the v2 improvement of adding a Diffie-Hellman mechanism; the two authentication methods, password-based and key-based; and finally how to check port listening with netstat / lsof / nmap, plus common ssh / scp / sftp commands.

> **Technical notes**
>
> - The environment here is CentOS 6 (OpenSSH 5.3p1). DSA (ssh-dss) keys have been disabled by default since OpenSSH 7.0; new systems should use RSA or ed25519 keys instead. SSH v1 has been removed entirely; only v2 remains.
> - Service management: on new systems use `systemctl restart sshd`; `/etc/init.d/sshd` was phased out along with SysV init.

## 1. Protocol and Software Components

SSH (Secure Shell Protocol) is used for remote connections, with default port 22 and protocol version ssh2. It mainly consists of the ssh remote connection and the SFTP service.

The server side is OpenSSH:

```shell
# rpm -qa openssh openssl
openssh-5.3p1-94.el6.x86_64
openssl-1.0.1e-15.el6.x86_64      # handles encryption
```

Check the process:

```shell
# ps -ef | grep sshd
root       1243      1  0 19:06 ?        00:00:00 /usr/sbin/sshd
```

## 2. Key Mechanism (Difference Between v1 and v2)

It supports RSA and DSA keys, divided into public keys (Public key) and private keys (Private key).

View the configuration file:

```shell
# less /etc/ssh/sshd_config          # config file
# grep ServerKey /etc/ssh/sshd_config    # temporary public key
#ServerKeyBits 1024
```

First connection (the server's public key will be accepted):

```shell
# ssh root@192.168.10.10
The authenticity of host '192.168.10.10 (192.168.10.10)' can't be established.
RSA key fingerprint is c6:94:5f:af:17:75:7f:dd:bc:2a:54:83:f3:5a:d2:dc.
Are you sure you want to continue connecting (yes/no)?
```

The client records the key information (configuration in `/etc/ssh/ssh_config`):

```shell
# ll ~/.ssh/known_hosts
-rw-r--r-- 1 root root 395 4月   3 19:37 /root/.ssh/known_hosts
```

**SSH 1.x**: ServerKey + Private Key = Key pair. After this key pair is generated, all data is exchanged through it.

> ⚠️ Danger: from then on, data exchange no longer checks the key pair, so there is a risk of tampering.

**Version 2** adds a Diffie-Hellman mechanism to confirm the connection is correct, checking that the data really comes from the right source.

There are two authentication methods: **password-based** and **key-based**.

## 3. Checking Ports and Services

```shell
# netstat -lntup | grep 22
tcp        0      0 0.0.0.0:22                  0.0.0.0:*                   LISTEN      1162/sshd
tcp        0      0 :::22                       :::*                        LISTEN      1162/sshd
```

```shell
# lsof -i :22
COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
sshd    1162 root    3u  IPv4  10478      0t0  TCP *:ssh (LISTEN)
sshd    1162 root    4u  IPv6  10480      0t0  TCP *:ssh (LISTEN)
sshd    1437 root    3r  IPv4  11491      0t0  TCP 192.168.10.11:ssh->bogon:62818 (ESTABLISHED)
```

Scan ports:

```shell
# nmap 192.168.10.10 -p1-65535
```

## 4. Basic Commands

ssh remote connection:

```shell
# ssh root@192.168.10.10
# ssh root@192.168.10.10 ifconfig
```

scp copies files:

```shell
# scp xx root@192.168.10.10:/tmp       # copy file xx to the remote /tmp
# scp root@192.168.10.10:/tmp/xx .     # the reverse: pull it back to the local directory
```

SFTP:

```shell
# sftp root@192.168.10.10
sftp> put /root/xx /tmp     # upload; add the client-side local path
sftp> get /root/xx /tmp     # download to the local current directory
```
