> **About this post**
>
> This article walks through a manual, binary-based deployment of a Kubernetes
> v1.13 cluster: a three-node plan (1 master + 2 nodes), starting with
> initialization such as disabling firewalld/selinux/swap and setting kernel
> parameters, plus installing and configuring Docker; etcd and flanneld follow
> the previous two blog posts; cfssl is then used to issue the CA, server, and
> kube-proxy certificates; on the master, kube-apiserver, kube-scheduler, and
> kube-controller-manager are configured one by one; the nodes rely on TLS
> Bootstrapping so that kubelet can request certificates automatically and
> join the cluster, and kube-proxy is deployed; finally, an nginx deployment
> with three replicas verifies the setup.

> **Technical notes**
>
> CentOS 7 reached end of maintenance (EOL) on June 30, 2024; migrating to
> Rocky Linux 9 / AlmaLinux 9 or the Chinese distribution openEuler is
> recommended.
> Kubernetes v1.13 (2018-12) has long been EOL: bootstrap approaches such as
> --enable-bootstrap-token-auth and token.csv are deprecated, and
> kubectl run --replicas / kubectl expose have also been removed; deploy new
> clusters with kubeadm following the documentation for your current version.
> This article is kept only as a reference for the principles of binary
> deployment.
> Content swallowed by the original editor has been fixed: the Documentation
> links got their github.com prefix back, the apiVersion in kubelet.config was
> completed as kubelet.config.k8s.io/v1beta1, and orphaned vim/sh leftover
> lines were cleaned up; the registry mirror URL in daemon.json and the pause
> image repository prefix were already missing in the original and must be
> filled in per environment.

## 2. Preparation

```shell
systemctl stop firewalld && systemctl disable firewalld
setenforce 0
vi /etc/selinux/config        # change to SELINUX=disabled
```

/etc/hosts:

```text
192.168.100.100  master.hequan.lol  master
192.168.100.101  node01.hequan.lol  node01
192.168.100.102  node02.hequan.lol  node02
```

Disable swap:

```shell
swapoff -a && sysctl -w vm.swappiness=0
vi /etc/fstab     # comment out the swap mount line, as below
```

```text
#UUID=7bff6243-324c-4587-b550-55dc34018ebf swap                    swap    defaults        0 0
```

Kernel parameters:

```shell
cat << EOF | tee /etc/sysctl.d/k8s.conf
net.ipv4.ip_forward = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.bridge.bridge-nf-call-iptables = 1
EOF
sysctl -p /etc/sysctl.d/k8s.conf
```

## 3. Install Docker

```shell
mkdir /data/docker

sudo yum-config-manager --add-repo http://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo

sudo yum makecache fast
sudo yum -y install docker-ce

docker version
systemctl enable docker.service
systemctl start docker.service
```

Configure /etc/docker/daemon.json (the registry mirror URL was lost in the original, leaving only "https://"; fill it in yourself; graph sets the data directory to /data/docker):

```shell
sudo mkdir -p /etc/docker

{"registry-mirrors": ["https://"],"graph": "/data/docker"}

sudo systemctl daemon-reload

```

## 4. Deploy Components on the Master

### 4.1 Generate Certificates

```shell
mkdir /data/ssl/k8s
cd /data/ssl/k8s
```

```shell
# cat ca-config.json
cat > ca-config.json << EOF
{
  "signing": {
    "default": {
      "expiry": "87600h"
    },
    "profiles": {
      "kubernetes": {
         "expiry": "87600h",
         "usages": [
            "signing",
            "key encipherment",
            "server auth",
            "client auth"
        ]
      }
    }
  }
}
EOF

# cat ca-csr.json
cat > ca-csr.json << EOF
{
    "CN": "kubernetes",
    "key": {
        "algo": "rsa",
        "size": 2048
    },
    "names": [
        {
            "C": "CN",
            "L": "Beijing",
            "ST": "Beijing",
            "O": "k8s",
            "OU": "System"
        }
    ]
}
EOF
cfssl gencert -initca ca-csr.json | cfssljson -bare ca -

# cat server-csr.json
cat > server-csr.json << EOF
{
    "CN": "kubernetes",
    "hosts": [
      "10.0.0.1",
      "127.0.0.1",
      "192.168.100.100",
      "kubernetes",
      "kubernetes.default",
      "kubernetes.default.svc",
      "kubernetes.default.svc.cluster",
      "kubernetes.default.svc.cluster.local"
    ],
    "key": {
        "algo": "rsa",
        "size": 2048
    },
    "names": [
        {
            "C": "CN",
            "L": "BeiJing",
            "ST": "BeiJing",
            "O": "k8s",
            "OU": "System"
        }
    ]
}
EOF
cfssl gencert -ca=ca.pem -ca-key=ca-key.pem -config=ca-config.json -profile=kubernetes server-csr.json | cfssljson -bare server

# cat kube-proxy-csr.json
cat > kube-proxy-csr.json << EOF
{
  "CN": "system:kube-proxy",
  "hosts": [],
  "key": {
    "algo": "rsa",
    "size": 2048
  },
  "names": [
    {
      "C": "CN",
      "L": "BeiJing",
      "ST": "BeiJing",
      "O": "k8s",
      "OU": "System"
    }
  ]
}
EOF
cfssl gencert -ca=ca.pem -ca-key=ca-key.pem -config=ca-config.json -profile=kubernetes kube-proxy-csr.json | cfssljson -bare kube-proxy

# ls *pem
# ca-key.pem  ca.pem  kube-proxy-key.pem  kube-proxy.pem  server-key.pem  server.pem

```

### 4.2 apiserver

Extract the server package and copy the master-side component binaries:

```shell
cd /data/src
tar xf kubernetes-server-linux-amd64.tar.gz
cd kubernetes/server/bin/
cp kube-apiserver kube-scheduler kube-controller-manager kubectl /opt/kubernetes/bin
```

Token file /opt/kubernetes/cfg/token.csv:

```csv
MnCwST4J8KAn7qLkMnklR8LytumEBb,kubelet-bootstrap,10001,"system:kubelet-bootstrap"
```

- First column: a random string; you can generate one yourself, e.g. with `head -c 16 /dev/urandom | od -An -t x | tr -d ' '`
- Second column: username
- Third column: UID
- Fourth column: group

Configuration file /opt/kubernetes/cfg/kube-apiserver:

```ini
KUBE_APISERVER_OPTS="--logtostderr=true \
--v=4 \
--etcd-servers=https://192.168.100.100:2379,https://192.168.100.101:2379,https://192.168.100.102:2379 \
--bind-address=192.168.100.100 \
--secure-port=6443 \
--advertise-address=192.168.100.100 \
--allow-privileged=true \
--service-cluster-ip-range=10.0.0.0/24 \
--enable-admission-plugins=NamespaceLifecycle,LimitRanger,SecurityContextDeny,ServiceAccount,ResourceQuota,NodeRestriction \
--authorization-mode=RBAC,Node \
--enable-bootstrap-token-auth \
--token-auth-file=/opt/kubernetes/cfg/token.csv \
--service-node-port-range=30000-50000 \
--tls-cert-file=/opt/kubernetes/ssl/server.pem \
--tls-private-key-file=/opt/kubernetes/ssl/server-key.pem \
--client-ca-file=/opt/kubernetes/ssl/ca.pem \
--service-account-key-file=/opt/kubernetes/ssl/ca-key.pem \
--etcd-cafile=/opt/etcd/ssl/ca.pem \
--etcd-certfile=/opt/etcd/ssl/server.pem \
--etcd-keyfile=/opt/etcd/ssl/server-key.pem"
```

Parameter descriptions:

- --logtostderr: enable logging
- --v: log level
- --etcd-servers: etcd cluster addresses
- --bind-address: listen address
- --secure-port: HTTPS secure port
- --advertise-address: advertised cluster address
- --allow-privileged: allow privileged containers
- --service-cluster-ip-range: virtual IP range for Services
- --enable-admission-plugins: admission control plugins
- --authorization-mode: authentication and authorization; enables RBAC authorization and node self-management
- --enable-bootstrap-token-auth: enables the TLS bootstrap feature, covered later
- --token-auth-file: token file
- --service-node-port-range: default port range allocated for NodePort Services

Service unit /usr/lib/systemd/system/kube-apiserver.service:

```ini
[Unit]
Description=Kubernetes API Server
Documentation=https://github.com/kubernetes/kubernetes

[Service]
EnvironmentFile=-/opt/kubernetes/cfg/kube-apiserver
ExecStart=/opt/kubernetes/bin/kube-apiserver $KUBE_APISERVER_OPTS
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```shell
systemctl daemon-reload
systemctl enable kube-apiserver
systemctl restart kube-apiserver
```

## 5. Deploy Components on the Nodes

### 5.1 Overview

> After TLS authentication is enabled on the master apiserver, the kubelet on a node must present a valid certificate issued by the CA to communicate with the apiserver in order to join the cluster. When there are many nodes, signing certificates by hand is tedious; hence the TLS Bootstrapping mechanism: kubelet automatically requests a certificate from the apiserver as a low-privileged user, and the kubelet certificate is signed dynamically by the apiserver.

### 5.2 Operations on the Master

```shell
vim /etc/profile      # add export PATH=/opt/kubernetes/bin:$PATH
source /etc/profile
```

Bind the kubelet-bootstrap user to the system cluster role:

```shell
/opt/kubernetes/bin/kubectl create clusterrolebinding kubelet-bootstrap \
--clusterrole=system:node-bootstrapper \
--user=kubelet-bootstrap

# kubelet-bootstrap created
```

In the directory where the kubernetes certificates were generated, run the following commands to create the kubeconfig files (remember to update the token and the IPs):

```shell
cd /data/ssl/k8s/

# Create the kubelet bootstrapping kubeconfig
BOOTSTRAP_TOKEN=MnCwST4J8KAn7qLkMnklR8LytumEBb
KUBE_APISERVER="https://192.168.100.100:6443"

# Set cluster parameters
kubectl config set-cluster kubernetes \
  --certificate-authority=./ca.pem \
  --embed-certs=true \
  --server=${KUBE_APISERVER} \
  --kubeconfig=bootstrap.kubeconfig

# Set client credentials
kubectl config set-credentials kubelet-bootstrap \
  --token=${BOOTSTRAP_TOKEN} \
  --kubeconfig=bootstrap.kubeconfig

# Set context parameters
kubectl config set-context default \
  --cluster=kubernetes \
  --user=kubelet-bootstrap \
  --kubeconfig=bootstrap.kubeconfig

# Set the default context
kubectl config use-context default --kubeconfig=bootstrap.kubeconfig

#----------------------

# Create the kube-proxy kubeconfig file

kubectl config set-cluster kubernetes \
  --certificate-authority=./ca.pem \
  --embed-certs=true \
  --server=${KUBE_APISERVER} \
  --kubeconfig=kube-proxy.kubeconfig

kubectl config set-credentials kube-proxy \
  --client-certificate=./kube-proxy.pem \
  --client-key=./kube-proxy-key.pem \
  --embed-certs=true \
  --kubeconfig=kube-proxy.kubeconfig

kubectl config set-context default \
  --cluster=kubernetes \
  --user=kube-proxy \
  --kubeconfig=kube-proxy.kubeconfig

kubectl config use-context default --kubeconfig=kube-proxy.kubeconfig

ls bootstrap.kubeconfig kube-proxy.kubeconfig
```

Distribute the kubeconfig files and the node-side binaries:

```shell
scp bootstrap.kubeconfig kube-proxy.kubeconfig root@node01:/opt/kubernetes/cfg/
scp bootstrap.kubeconfig kube-proxy.kubeconfig root@node02:/opt/kubernetes/cfg/

cd /data/src/kubernetes/server/bin

scp kubelet kube-proxy root@node01:/opt/kubernetes/bin/
scp kubelet kube-proxy root@node02:/opt/kubernetes/bin/
```

### 5.3 Operations on the Nodes

Node mapping:

- node01: 192.168.100.101, 10.0.0.2
- node02: 192.168.100.102, 10.0.0.3

Configuration file /opt/kubernetes/cfg/kubelet (on node02, replace the local IP such as --hostname-override with 192.168.100.102):

```ini
KUBELET_OPTS="--logtostderr=true \
--v=4 \
--hostname-override=192.168.100.101 \
--kubeconfig=/opt/kubernetes/cfg/kubelet.kubeconfig \
--bootstrap-kubeconfig=/opt/kubernetes/cfg/bootstrap.kubeconfig \
--config=/opt/kubernetes/cfg/kubelet.config \
--cert-dir=/opt/kubernetes/ssl \
--pod-infra-container-image=/google-containers/pause-amd64:3.0"
```

> Note: in the original post the --pod-infra-container-image value lacks the image repository prefix; change it to a pause image reachable in your environment (e.g. gcr.io/google-containers/pause-amd64:3.0 or a domestic mirror address).

Parameter descriptions:

- --hostname-override: the hostname shown in the cluster
- --kubeconfig: path to the kubeconfig file; it is generated automatically
- --bootstrap-kubeconfig: points to the bootstrap.kubeconfig file generated earlier
- --cert-dir: where issued certificates are stored
- --pod-infra-container-image: the image that manages Pod networking

Configuration file /opt/kubernetes/cfg/kubelet.config (the apiVersion prefix was eaten in the original; it has been completed as kubelet.config.k8s.io/v1beta1):

```yaml
kind: KubeletConfiguration
apiVersion: kubelet.config.k8s.io/v1beta1
address: 192.168.100.101
port: 10250
readOnlyPort: 10255
cgroupDriver: cgroupfs
clusterDNS: ["10.0.0.2"]
clusterDomain: cluster.local.
failSwapOn: false
authentication:
  anonymous:
    enabled: true
```

Service unit /usr/lib/systemd/system/kubelet.service:

```ini
[Unit]
Description=Kubernetes Kubelet
After=docker.service
Requires=docker.service

[Service]
EnvironmentFile=/opt/kubernetes/cfg/kubelet
ExecStart=/opt/kubernetes/bin/kubelet $KUBELET_OPTS
Restart=on-failure
KillMode=process

[Install]
WantedBy=multi-user.target
```

```shell
systemctl daemon-reload
systemctl enable kubelet
systemctl restart kubelet
```

On the master, list and approve the CSR; the node can then join:

```shell
kubectl get csr
kubectl certificate approve <name>    # name is the CSR name found in the previous step
kubectl get node
```
