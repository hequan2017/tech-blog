> **About this post**
>
> This post shares the same configuration as *h3c Switch Policy-Based Routing*; it is a
> policy-based routing (PBR) snippet for switches: policy `aaa` is applied on Vlan-interface2,
> an advanced ACL 3000 matches a specified source network segment, and matching traffic is
> forced to the next hop 192.168.1.1, achieving policy-based traffic splitting.
>
> **Technical notes**
>
> - H3C Comware style command: `ip address ... sub` denotes a secondary address (Cisco uses
>   `secondary`); 192.168.1.2/30 and the next hop 192.168.1.1 are on the same subnet for
>   interconnection.
> - `0.0.0.255` is a wildcard (inverse) mask, matching one class C source network segment;
>   traffic that misses the policy is still forwarded according to the normal routing table.
>   The title "planning routing" is a typo and should be "policy routing".

---

```shell
interface Vlan-interface2
ip address x.x.x.x 255.255.255.0
ip address 192.168.1.2 255.255.255.252 sub
ip policy-based-route aaa
#

acl number 3000
rule 0 permit ip source x.x.x.x 0.0.0.255
#

policy-based-route aaa permit node 2
if-match acl 3000
apply next-hop 192.168.1.1
#
```
