> **About this post**
>
> A complete example of integrating Celery 3 + django-celery (Redis as the broker, database as the result backend) into a Django 2.0 project: settings configuration, how to write asynchronous and scheduled tasks in tasks.py, configuring scheduled tasks from the Django admin, a description of the database tables generated by djcelery, and the startup commands for the worker / beat / celerycam processes. The tasks also demonstrate a trick for patching `multiprocessing._config` inside the Celery worker so the ansible API can be called.

> **Technical notes**
>
> Celery 3.x and django-celery have both been unmaintained for years. Since Celery 4/5, djcelery has been removed; use `django-celery-beat` for scheduled tasks instead, and all configuration options are now lowercase (e.g. `broker_url`, `result_backend`). Python 3.6 and Django 2.0 are both EOL; for new projects use Python 3.10+, Django 4/5 LTS, and Celery 5. `C_FORCE_ROOT` in this post is for demonstration only; in production, run the worker as a regular user.

### Introduction to Celery

Celery is a distributed asynchronous message task queue developed in Python. With it, you can easily process tasks asynchronously. If your business scenario calls for asynchronous tasks, Celery is worth considering.

#### settings

```python
import djcelery

INSTALLED_APPS = [
    'djcelery',
    'kombu',
]

djcelery.setup_loader()
BROKER_URL = 'redis://127.0.0.1:6379/0'  # message data is stored in DB 0

CELERY_RESULT_BACKEND = 'djcelery.backends.database:DatabaseBackend' # specify the backend
CELERY_ACCEPT_CONTENT = ['application/json']
CELERY_TASK_SERIALIZER = 'json'
CELERY_RESULT_SERIALIZER = 'json'

CELERY_TIMEZONE = 'Asia/Shanghai'

#CELERY_ALWAYS_EAGER = True   # if enabled, Celery runs in eager mode, so tasks no longer need .delay() to run

CELERY_IMPORTS = ('tasks.tasks',)
CELERYBEAT_SCHEDULER = 'djcelery.schedulers.DatabaseScheduler'  # this uses django-celery's default database scheduler; task execution periods are all stored in the ORM database you specify
```

#### tasks.py

```python
from celery import Celery, platforms

platforms.C_FORCE_ROOT = True

app = Celery('my_task')
app.config_from_object('django.conf:settings',)
app.autodiscover_tasks(lambda: settings.INSTALLED_APPS)

@app.task()
def  ansbile():   ## to call the ansible API asynchronously, add the following before the task

    from multiprocessing import current_process
    # try:
    #     current_process()._config
    # except AttributeError:
    current_process()._config = {'semprefix': '/mp'}

@app.task()
def  cmd_job(host,cmd):   ## run a command
    i = asset.objects.get(network_ip=host)
    ret = ssh(ip=i.network_ip, port=i.port, username=i.username, password=i.password, cmd=cmd)
    return  ret['data']

def test():  ## an example of calling celery asynchronously

    from tasks.tasks import cmd_job

    aa = cmd_job.apply_async(args=('43.241.238.109', 'pwd'))
    print("id",aa.task_id,"return value",aa.get() ,aa.result, "state",aa.state)

    from  djcelery.models import TaskMeta
    b = TaskMeta.objects.get(task_id=aa).result
    print("return value",b)
```

#### Database Structure

```shell
* | celery_taskmeta                   ## asynchronous tasks write their results into this table
* | celery_tasksetmeta
* | djcelery_crontabschedule
* | djcelery_intervalschedule
* | djcelery_periodictask
* | djcelery_periodictasks
* | djcelery_taskstate               ## scheduled tasks run from the Django admin; results are written to this table
* | djcelery_workerstate
```

```python
from djcelery.models import TaskMeta, TaskState          ## access the tables like this
```

![Task results in the celery_taskmeta database table](../assets/2071544/03_753916d5ab898080a32b29ae9be1c8bd.png)

**The result content looks garbled when viewed directly in the database, but it displays correctly when fetched through the ORM. Please be aware of this.**

#### Startup Commands

```shell
# the process that actually executes the tasks
/usr/bin/python   /opt/autoops/manage.py   celery worker  -c  4        --loglevel=info

# task scheduler, publishes scheduled tasks according to the configuration
/usr/bin/python   /opt/autoops/manage.py celery beat --schedule=/tmp/celerybeat-schedule --pidfile=/tmp/django_celerybeat.pid --loglevel=INFO

# Django checks whether the workers are online
/usr/bin/python   /opt/autoops/manage.py   celerycam --frequency=10.0
```
