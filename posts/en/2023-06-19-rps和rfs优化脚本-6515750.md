> **About this post**
>
> A record of a Linux NIC receive-optimization script: it installs the dependency tools, enumerates and filters out the usable physical NICs,
> adjusts each NIC's RingBuffer to 4096, binds the NIC interrupts in order to the cores starting from cpu1 (skipping cpu0),
> and then decides whether to enable or disable RPS, RFS, and XPS based on whether a PPPoE dial-up connection exists and on the relationship between the number of interrupts and the number of CPU cores.
> The end of the post explains the concepts of RingBuffer, hard/soft interrupts, and RPS/RFS/XPS, and offers optimization suggestions such as irqbalance.

> **Technical notes**
>
> RPS/RFS are the kernel's software mechanisms for steering received packets: on multi-queue NICs, RSS (NIC multi-queue) first spreads packets across queues in hardware.
> When the NIC has a single queue or fewer queues than CPU cores, RPS amounts to a software implementation of RSS; building on RPS,
> RFS delivers the packets of the same flow to the same CPU to improve cache hit rates; XPS is the counterpart for the transmit direction. Both are configured via sysfs:
> `/sys/class/net/<iface>/queues/rx-N/rps_cpus`, `rps_flow_cnt`, `tx-N/xps_cpus`,
> and the global flow table size is `/proc/sys/net/core/rps_sock_flow_entries`. Note that in this script every branch that enables
> RPS also sets both `rps_flow_cnt` and `rps_sock_flow_entries` to 0 (the script comments say the brpc
> thread model does not enable RFS), so RFS is not actually enabled. Newer alternatives include aRFS (requires NIC/driver support)
> and receive-side redirection based on the XDP/eBPF cpumap; the authoritative reference is the kernel documentation `Documentation/networking/scaling.rst`.

## 1. Optimization Script

The complete script is as follows:

```shell
#!/bin/bash
# https://github.com/sklochkov/performance-tuner/blob/master/src/
# https://github.com/torvalds/linux/blob/master/Documentation/networking/scaling.rst

yum install redhat-lsb -y

if [ -n "`lsb_release -i | grep -i "debian"`" ]
then
    apt-get install -y net-tools bc ethtool
else
    yum install -y net-tools bc ethtool
fi

# number of CPU cores
cpus=`grep -c processor /proc/cpuinfo`

str=""
for vth in `ls /sys/devices/virtual/net/`;do
    str="${vth}|${str}"
done
# virtual NIC list, separated by |
vthstr=`echo ${str} | sed 's/^\(.*\)|$/\1/g'`

# physical NIC list, separated by spaces
interfaces=`sed -n '3,$p' /proc/net/dev | awk -F ":" '{print $1}' | grep -Ev "${vthstr}" | sed 's/ //g'`
# physical NIC list, separated by |
#interfaces_shugang=`sed -n '3,$p' /proc/net/dev | awk -F ":" '{print $1}' | grep -Ev "${vthstr}" | sed 's/ //g' |tr "\n" "|"  | sed 's/^\(.*\)|$/\1/g'`

#
filter_interfaces=""
for interface in ${interfaces};do
        ip_down=`ip add|grep -w "${interface}:"| grep -v 'NO-CARRIER'`
        if [ -z "${ip_down}" ];then
             echo "interface: ${interface} is down! remove it"
        else
            echo "filter_interfaces:${filter_interfaces}"
            if [ -z ${filter_interfaces} ];then
                    filter_interfaces="${interface}"
            else
                    filter_interfaces="${filter_interfaces} ${interface}"
            fi
        fi
        echo -e "interfaces:\n${interfaces}"
        echo "filter_interfaces:${filter_interfaces}"
done

echo -e "interfaces:\n${interfaces}"
echo "filter_interfaces:${filter_interfaces}"

# overwrite the value
interfaces=${filter_interfaces}

# eth interfaces   queue size defaults to 1000
for interface in ${interfaces};do
    /sbin/ethtool -G ${interface} rx 4096
    /sbin/ethtool -G ${interface} tx 4096

    q=(`grep -E "${interface}" /proc/interrupts | awk '{print $1}' | cut -d: -f 1 | grep -e '^[0-9]*$'`)
    echo "${interface} 物理网卡中断号列表:${q[*]}"
    echo "${interface} 中断号数量:${#q[@]}"
    # skip cpu0
    k=1 # k increments along with the IRQ number
    for i in ${q[*]};do # i is the IRQ number
        echo ${k} > /proc/irq/$i/smp_affinity_list
        echo "irq: ${i} cpu_list: `cat /proc/irq/${i}/smp_affinity_list`"
        k=$[${k}+1]
        if [ ${k} -eq ${cpus} ]
        then
           k=0
        fi
    done

    if_pppoe_running=`ps -ef|grep -i 'pppoe'|grep -v grep |wc -l`

    # fewer interrupts than cores
    # https://github.com/torvalds/linux/blob/master/Documentation/networking/scaling.rst#suggested-configuration-3
    rps_sock_flow_entries=32768
    # skip cpu0
    if [ ${cpus} -lt 32 ]
    then
        default_affinity="fffffe"
    else
        default_affinity="fffffffe"
    fi
    if [ ${if_pppoe_running} -gt 0 ];then
        # pppoe dial-up present: rps on, rfs off
        echo 0 > /proc/sys/net/core/rps_sock_flow_entries
        RX=`ls -ld /sys/class/net/${interface}/queues/rx* 2>/dev/null | wc -l`
        TX=`ls -ld /sys/class/net/${interface}/queues/tx* 2>/dev/null | wc -l`
        if [ $RX -gt 0 ] ; then
            for i in `seq $RX` ; do
                echo ${default_affinity} > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus
                echo 0 > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt
                echo "/sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus `cat /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus`"
                echo "/sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt `cat /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt`"
            done
        fi
        if [ $TX -gt 0 ] ; then
            for i in `seq $TX` ; do
                echo "${default_affinity}" > /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus
                echo "/sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus `cat /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus`"
            done
        fi
    elif [ ${#q[@]} -lt ${cpus} ];then
            # no pppoe dial-up: rps and rfs both on
            RX=`ls -ld /sys/class/net/${interface}/queues/rx* 2>/dev/null | wc -l`
            TX=`ls -ld /sys/class/net/${interface}/queues/tx* 2>/dev/null | wc -l`
            if [ $RX -gt 0 ] ; then
                for i in `seq $RX` ; do
                    echo ${default_affinity} > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus
                    # brpc thread-model don't open rfs
                    echo "0" > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt
                    echo "/sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus `cat /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus`"
                    echo "/sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt `cat /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt`"
                done
            fi
            if [ $TX -gt 0 ] ; then
                for i in `seq $TX` ; do
                    echo "${default_affinity}" > /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus
                    echo "/sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus `cat /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus`"
                done
            fi
            # brpc thread-model don't open rfs
            echo "0" > /proc/sys/net/core/rps_sock_flow_entries
    else
        # close rps/rfs
        echo "0" > /proc/sys/net/core/rps_sock_flow_entries
        if [ -d /sys/class/net/${interface}/queues ] ; then
            RX=`ls -ld /sys/class/net/${interface}/queues/rx* 2>/dev/null | wc -l`
            TX=`ls -ld /sys/class/net/${interface}/queues/tx* 2>/dev/null | wc -l`
            if [ $RX -gt 0 ] ; then
                for i in `seq $RX` ; do
                    echo "0" > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus
                    echo "0" > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt
                    echo "/sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus `cat /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus`"
                    echo "/sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt `cat /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt`"
                done
            fi
            if [ $TX -gt 0 ] ; then
                for i in `seq $TX` ; do
                    echo "0" > /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus
                    echo "/sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus `cat /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus`"
                done
            fi
        fi
    fi
done
```

## 2. Script Explanation

1. Installs the redhat-lsb package, which is used to detect the operating system type.
2. Detects the operating system type; if it is a Debian system, net-tools, bc, and ethtool are installed with apt-get; otherwise these tools are installed with yum.
3. Gets the number of CPU cores.
4. Gets the list of virtual NICs and stores it in the variable `vthstr`.
5. Gets the list of physical NICs, stores it in the variable `interfaces`, and removes the virtual NICs from the list.
6. Filters out the physical NICs whose network is unavailable and stores the available physical NICs in the `filter_interfaces` variable.
7. Overwrites the `interfaces` variable with the value of `filter_interfaces`.
8. Performs the following operations on each physical NIC:
    - Uses the ethtool command to set the receive queue (rx) and transmit queue (tx) sizes to 4096.
    - Gets the list of the physical NIC's IRQ numbers and stores it in the variable `q`; for each IRQ number, sets the corresponding CPU affinity so that interrupts are distributed across different CPU cores.
    - If a pppoe process is running on the system, turns off the RPS- and RFS-related settings.
    - If the number of the physical NIC's IRQ numbers is less than the number of CPU cores, enables RPS and RFS and sets the corresponding CPU affinity.
    - If none of the above conditions is met, disables RPS and RFS.

## 3. RingBuffer

The ethtool command sets the receive queue (rx) and transmit queue (tx) sizes to 4096. The RingBuffer (ring buffer) defaults to 512 and supports being adjusted to at most 4096; the default differs from device to device.

```shell
ethtool -g eth0
```

```text
Ring parameters for eth0:
Pre-set maximums:
RX:             4096
RX Mini:        0
RX Jumbo:       0
TX:             4096
Current hardware settings:
RX:             512
RX Mini:        0
RX Jumbo:       0
TX:             512
```

If `fifo_errors` is not 0, it means packets were dropped because the RingBuffer could not hold them; this can be resolved by adjusting the RingBuffer size:

```shell
ethtool -S p7p2 | grep fifo_errors
```

```text
     rx_fifo_errors: 0
     tx_fifo_errors: 0
```

## 4. Interrupts and CPU Affinity

The script gets the list of the physical NIC's IRQ numbers and stores it in the variable `q`; for each IRQ number, it sets the corresponding CPU affinity so that interrupts are distributed across different CPU cores.

/proc is actually a virtual filesystem in Linux used for communication between kernel space and user space; /proc/interrupts is part of this communication mechanism and provides a read-only view of interrupt usage.

`k=1` means skipping cpu0 and starting from cpu1. `smp_affinity_list` is used to set the CPU affinity of the IRQ handler: the value of the variable `${k}` is written into the `/proc/irq/$i/smp_affinity_list` file, where `${k}` is a variable holding the CPU number and `$i` is a variable holding the IRQ number. This assigns the IRQ handlers to different CPUs, achieving parallel processing and load balancing. The purpose is to distribute the interrupt handlers across multiple CPUs, making full use of the system's multi-core resources to improve network performance and the overall throughput of the system.

**What is an interrupt?**

Processing performed by the corresponding hardware or software upon receiving an asynchronous signal from peripheral hardware (relative to the CPU and memory) or a synchronous signal from software; issuing such a signal is called making an interrupt request (interrupt request, IRQ).

**Hard interrupts and soft interrupts?**

- Hard interrupt: an asynchronous signal sent by peripheral hardware to the CPU or memory is called a hard interrupt.
- Soft interrupt: an interrupt signal sent to the operating system kernel by the software system itself is called a soft interrupt. It is usually an interrupt to the OS kernel raised by a hard interrupt handler or the process scheduler — what we commonly call a system call (System Call).

## 5. RPS and RFS

- RSS (receive side scaling): NIC multi-queue.
- RPS (Receive Packet Steering) is a software mechanism that distributes received packets across multiple processor cores to improve the parallel performance of packet processing.
- RFS (Receive Flow Steering) is a software mechanism that intelligently selects receive queues on multi-queue devices to achieve load balancing and parallel processing.
- XPS (transmit packet steering): applied to the transmit direction.

### RPS

On a single-queue NIC in a multi-core system, or on a multi-queue NIC when there are more cores than queues, the RPS feature can be used to distribute packets across multiple cores so that the cores process packets in softirqs. This is effectively a software implementation of RSS.

Simply write the CPU list into the rps_cpus file of the corresponding queue:

```shell
echo ${default_affinity} > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus
echo "${default_affinity}" > /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus
```

If the system has fewer than 32 CPU cores, default_affinity is set to "fffffe", meaning the interrupt handlers can run on all cores except CPU0. If the system has 32 or more CPU cores, default_affinity is set to "fffffffe", which likewise allows running on all cores except CPU0; the two differ only in mask width (to cover a larger number of cores).

### RFS

RFS (Receive Flow Steering) works together with RPS. RPS tries to balance packet reception across CPUs, but it ignores the question of data locality — how to maximize the CPU cache hit rate. RFS delivers the packets belonging to the same flow to the same CPU for processing, which improves the cache hit rate.

```shell
sysctl -w net.core.rps_sock_flow_entries=32768
echo 32768 > /proc/sys/net/core/rps_sock_flow_entries
echo 2048 > /sys/class/net/eth0/queues/rx-0/rps_flow_cnt
```

Here 2048 is 32768 divided by the number of queues.

### Disabling RPS and RFS

```shell
echo "0" > /proc/sys/net/core/rps_sock_flow_entries
echo "0" > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_cpus
echo "0" > /sys/class/net/${interface}/queues/rx-$[$i - 1]/rps_flow_cnt
echo "0" > /sys/class/net/${interface}/queues/tx-$[$i - 1]/xps_cpus
```

## 6. Notes

1. High network load: when the system faces a high network load, enabling both RPS and RFS improves the parallel performance of packet processing. RPS distributes the received packets across multiple processor cores, while RFS distributes traffic across multiple receive queues to achieve load balancing.

   Suggested configuration: enable both RPS and RFS, and configure appropriate queue-to-CPU mappings according to the system configuration and hardware support.

2. Multi-queue network interfaces: for network interfaces that support multiple queues, RPS and RFS can be leveraged to improve parallel processing capability. Mapping receive queues to transmit queues yields better load balancing and packet processing efficiency.

   Suggested configuration: enable RPS and RFS, and configure appropriate receive-queue to transmit-queue mappings according to the system configuration and the characteristics of the network interface.

3. Situations where RFS is not suitable:

    1. Low network load: if your system faces a relatively low network load, enabling RFS may not bring an obvious performance gain. RFS mainly plays its role under high load, distributing traffic across multiple receive queues through load balancing to achieve parallel processing. Under low load, this extra load-balancing mechanism may not deliver significant performance improvements.
    2. Single-queue network interfaces: if your network interface supports only a single receive queue, the benefit of enabling RFS will be limited. RFS needs multiple receive queues to distribute traffic and balance the load; with only one queue available, RFS cannot play its role.
    3. PPPoE dial-up itself is usually single-queue, but after the dial-up connection is established, the operating system and the network drivers may use multiple queues to handle the data received and sent through the PPP interface. This allows multiple CPU cores or threads to process the network traffic, improving performance and throughput. The specific multi-queue configuration and implementation depend on the operating system, the network drivers, and the hardware capabilities of the network interface.

## 7. Optimization Suggestions

1. Check the NIC's multi-queue support:

```shell
ethtool -l eth0
```

2. Observe the CPU interrupt distribution (`irq` for hard interrupts, `soft` for soft interrupts):

```shell
mpstat -P ALL 2
```

3. Enable the irqbalance service so that the system automatically adjusts the distribution of network interrupts across multiple CPU cores:

```shell
yum -y install glib2-devel
yum -y install irqbalance
systemctl start irqbalance
```

4. Enable the RPS/RFS features to balance CPU load in software and optimize receive-packet interrupt handling.
