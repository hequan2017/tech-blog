> **About this post**
>
> This post is a quick review of the key knowledge points for the Alibaba Cloud ACP certification
> for cloud computing engineers, covering eight areas organized by product line:
> ECS billing modes, cloud disk specifications, and snapshot/security group quotas; OSS Bucket/Object concepts,
> intranet access, referer-based hotlink protection, and the image service; Auto Scaling's scaling groups/rules
> and cooldown mechanisms; VPC tunnel isolation, and VSwitch and route entry limits; SLB's Layer-4 (LVS) /
> Layer-7 (Tengine) architecture, health checks, and timeout settings; CDN node caching and bandwidth billing;
> the Cloud Shield four-layer defense system and Aegis; and CloudMonitor's metrics, dimensions, and alert
> rules — all presented as concise bullet-point summaries.

> **Technical notes**
>
> These are 2017 ACP exam-prep notes. Many quota figures in the text (100 security groups, 30 SLB instances,
> 24 VPC VSwitches, etc.) and the feature boundaries reflect the limits of that era; Alibaba Cloud has adjusted
> them many times over the years, so for exam preparation always refer to the latest official documentation.
> Two product full-name typos have been corrected: ECS should be Elastic Compute Service and OSS should be
> Object Storage Service (both were mistakenly written as "Server" in the original); Aegis has since been
> upgraded and renamed to Security Center, and capabilities such as Anti-DDoS Pro also differ from those days.

## 1. ECS Elastic Compute

Elastic Compute Service (ECS) is a computing service whose processing power can be scaled elastically.

- CPU and memory changes require stopping the instance; bandwidth does not.
- Vertical scaling: bandwidth, CPU, memory; horizontal scaling: servers
- Region (geographic region); Zone (availability zone)
- Security groups may contain instances across availability zones; disks can only be attached within the same availability zone; snapshots and images can be used across availability zones, and images can be copied to other regions
- When a failure occurs, an instance can only migrate within the same availability zone
- Default system disk 40GB-500GB; system disk device name: /dev/xvda
- An image must be selected when creating an ECS instance to determine its operating system
- Replacing the system disk does not change the instance's IP address or MAC address.

### Billing and Cloud Disks

- Subscription (monthly/yearly): minimum one week; bandwidth can be upgraded at any time; cannot be released ahead of schedule
- Pay-As-You-Go: does not support instance type or bandwidth upgrades; can be released at any time
- Ultra cloud disk: 20 -- 32768GB, 3000* IOPS, 80MBps; all have 3 backups, on different physical servers under different switches
- SSD cloud disk: 20 -- 32768GB, 20000* IOPS, throughput 300MBps
- Basic cloud disk: 2000GB, hundreds of IOPS, 30MBps
- A disk can only be attached to 1 instance at a time. You can set whether it is released together with the instance; pay-as-you-go only
- One ECS instance can mount at most 16 data disks
- Resizing requires restarting the server and manually resizing the file system; the data is preserved.
- When an instance is released, all disks are detached

Manually extending the file system after resizing:

```bash
e2fsck -f /dev/vdb1
resize2fs /dev/vdb1
```

### Snapshots, Security Groups, and Quotas

- Snapshot: a copy of disk data at a certain point in time
- Incremental snapshots
- Cloud Shield is installed by default
- Security group: specify a source IP address range (CIDR block) or the ID of a source security group (intranet); supports both inbound and outbound directions
- Each user can have at most 100 security groups, and each security group can contain at most 1000 instances.
- Each instance can join at most 5 security groups, and each security group can have at most 100 rules.
- Security group priority ranges from 1 to 100; 1 is the highest
- 32-bit operating systems cannot be selected for instances with more than 4GB of memory
- Instance families 2 and 3 support I/O optimization; in family 1, only instances of 2C4G and above do.
- To delete a snapshot, the corresponding image must be deleted first
- Each disk provides a quota of 64 snapshots
- Each instance can have at most 10 tags

### API and Signatures

- ECS API: `ecs.aliyuncs.com`
- Signature mechanism (signature), Access Key ID / Access Key Secret
- A single key allows 5000 calls/day; at most 5 keys

## 2. OSS Object Storage

Object Storage Service (OSS), a cloud storage service.

### Basic Concepts and Quotas

- 99.9% availability, ten 9s of reliability, triple data backup, security, DDoS protection, access logs, unlimited scaling
- Object: PUT up to 5GB; multipart upload up to 48.8TB; must be contained in a Bucket
- Bucket: a namespace; at most 10 per user; globally unique; cannot be modified; capacity up to 2PB
- Server: a virtual storage space (user)
- Access ID & Key: user identity, API key
- A Bucket's availability zone cannot be changed
- Three-level domain name: bucketname.endpoint

### Access and Permissions

- Only users on ECS instances can access OSS through its intranet endpoint, free of traffic charges
- They must be in the same region
- Access URL format: bucket-name.data-center-domain/object-name
- Permissions: private, public read, public read/write
- Non-empty buckets cannot be deleted (it must contain no fragments and no objects)
- Expiration time, custom space
- Batch deletion supports up to 1000 objects
- Each bucket can bind up to 20 domain names
- When an Object's Content-Type=application/octet-stream, accessing a jpg-format Object via the OSS public endpoint triggers a direct download by default

### Hotlink Protection (referer)

- Hotlink protection based on the referer header
- Whitelist empty: the referer field is not checked for emptiness (otherwise all requests would be rejected)
- Whitelist not empty:
  - If a rule disallowing an empty referer field is set, only requests whose referer belongs to the whitelist are allowed; all others (including an empty referer) are rejected
  - If a rule allowing an empty referer field is set, requests with an empty referer and requests matching the whitelist are allowed; all other requests are rejected. For browsing with a browser, allowing an empty referer field must be set.

### Logs and Image Service

- Log records: user-defined prefix, source bucket, time, and a string generated by the OSS system
- Image service: the style feature (representing a series of complex processing parameters with a simple alias)
- Style rule @: style@!alias (to avoid overly long URLs); pipe |: multiple processing operations chained together
- Disable the image processing service first, then delete the bucket
- Public-read-write / Public-read / creator can write / Private
- Server-side encryption, hotlink protection, bucket permission control, Access ID and request signatures
- OSS itself does not provide IP blacklists, but IP black/white lists can be used indirectly through the CDN

## 3. Auto Scaling ESS (Free)

- Scheduled tasks: 20; when several trigger at the same time, the most recently created scheduled task is selected for execution
- Alert tasks: names must be unique
- An ECS instance must be specified
- Supports the RDS access whitelist

### Core Concepts

- Scaling Group: a collection of ECS instances, with a minimum and maximum size; has the highest authority
- Scaling Configuration: the specification of ECS instances
- Scaling Rule: the number of instances to scale out or in
- Scaling Activity: a scaling activity is produced after a rule is successfully triggered. (Within the same scaling group, only one scaling activity can execute at a time, and activities cannot be terminated)
- Scaling Trigger Task: a task used to trigger scaling rules, e.g., scheduled tasks and alert tasks
- Cooldown Period: the lock period after a scaling activity completes (it only rejects scaling activity requests triggered by CloudMonitor alert tasks; manual and scheduled operations can bypass the cooldown) (counted after the last successful activity)

### Quotas and Constraints

- Tasks that trigger scaling rules exist independently of the scaling group; deleting a scaling group does not delete the tasks
- States: Active, Inactive, Deleting
- When modifying a scaling group's properties, the region, SLB, and RDS cannot be changed; only the Active/Inactive status can be modified
- Forced deletion is supported
- 1 scaling group has 10 scaling rules; 1 user can scale at most 100 ECS instances

### Workflow for Manually Adding Existing ECS Instances

1. Check the scaling group's health status and boundary conditions, and the ECS instance's status and type.
2. Allocate an ActivityId and execute the scaling activity.
3. Add the ECS instance.
4. Modify Total Capacity.
5. Add the RDS whitelist.
6. Attach to the SLB with the weight set to 0.
7. After waiting 60 seconds, set the weight to 50.
8. The scaling activity completes and the cooldown starts.

## 4. VPC Virtual Private Cloud

### Related Network Layer Protocols

- Application layer: HTTP
- Transport layer: TCP, UDP
- Network layer: ICMP, IP, routing
- Data link layer: ARP, RARP

### Components and Limits

- Different VPCs are isolated from each other by tunnel IDs
- VRouter (router)
- VSwitch
- Route Table: 1
- Route Entry
- Elastic IP Address (EIP)
- Dedicated line access
- Each VPC can contain at most 200 VRouter/VSwitch resources; more can be requested via a support ticket.
- CIDRBlock
- After successful creation, the network segment cannot be modified
- To delete a VPC, everything inside it must be deleted first
- Each route table can have at most 48 custom route entries
- One VPC can have at most 24 VSwitches
- Private network segments: 192.168.0.0/16, 172.16.0.0/12, 10.0.0.0/8

## 5. SLB Server Load Balancing

Server Load Balancer (SLB) provides load balancing.

- High availability, low cost, security | public and private network instances free
- LoadBalancer: represents an SLB instance
- Listener: represents the user-defined load balancing policies and forwarding rules
- BackendServer: a group of backend cloud servers
- Layer 4 TCP/UDP: based on LVS; health checks can choose TCP or HTTP
- Layer 7 HTTP/HTTPS: based on Tengine; health checks can be disabled
- Control system: used to configure and monitor SLB
- Health checks
- Session persistence (session)
- Weighted Round Robin (WRR), Weighted Least Connections (WLC)
- Certificate management service provided for HTTPS

### Billing and Quotas

- Traffic-based billing: only downstream traffic is charged (public outbound traffic)
- Fixed bandwidth
- Intranet rate limit 1Gbps
- One SLB supports at most 50 listener configurations
- Weight 0-100; 0 means no forwarding; after being set, existing long connections remain and changes take effect in real time
- At most 100 certificates
- Each user can have at most 30 SLB instances. Ports 1-65535
- SLB instances can be in different Zones.
- Create multiple SLB instances in the same or different regions and serve traffic externally through DNS round robin
- No limit on the ECS instances behind an SLB
- Availability up to 99.95%
- Security: integrates with Cloud Shield to defend against DDoS attacks, including CC, SYN flood, and other DDoS attack types.

Connection timeout for each listener type:

- TCP 900 seconds
- UDP 300 seconds
- HTTP 60 seconds
- HTTPS 60 seconds

## 6. CDN Content Delivery Network

Content Delivery Network (CDN): distributes origin content to nodes across the whole country, shortening the latency for users to fetch objects.

- Use cases: small-file acceleration, large-file acceleration, video on demand, live video streaming
- For users: quick application, personalized configuration, reports, log analysis, OPEN API interface, hotlink protection support
- Edge nodes: high-speed cache
- Bandwidth peak, traffic; bandwidth utilization = actual traffic GB / (peak bandwidth Mbps x 10.54); 1Mbps of bandwidth at 100% daily utilization equals 10.54GB.
- Bandwidth billing: tiered billing
- Smart DNS: returns different IP addresses based on the customer's origin
- Alibaba Cloud CDN: composed of a smart scheduling system and cache software | L1 cache - BGP - L2 cache - origin
- Origin: IP origin, OSS origin
- Cache refresh: URL refresh, directory refresh, URL prefetch
- Origin: the origin determines which IP a back-to-origin request goes to
- Back-to-origin host: the back-to-origin host determines which site on that IP the back-to-origin request hits

## 7. Cloud Shield Security Protection

- WAF protection (Web Application Firewall)
- CC protection (against CC attacks) and IP black/white lists: only one can take effect at a time.
- URL authentication: 3 methods
- 4-layer defense architecture: network layer, host layer, application layer, data layer
- Security system: Cloud Shield, cloud services, cloud security operations
- Security Manager: DDoS protection service, port security checks, remote login alerts, host password brute-force defense, website backdoor detection
- Security checkup: web vulnerability detection, webpage trojan detection
- DDoS types: DNS Query Flood, NTP reply Flood
- Cleansing threshold: automatic, manual
- Cloud Shield technical protection does not cover CC attacks
- Aegis: host password brute-force protection, remote login alerts, website backdoor detection, high-risk vulnerability patching, trojan file scanning and removal
- Database protection: whitelist restricting source IPs, intranet access mode, brute-force protection, SQL injection protection, SQL audit
- Application firewall: cross-site attacks, CRLF attacks, SQL injection attacks, FastCGI attacks, WEBSHELL attacks

## 8. CloudMonitor

Cloud Monitor System.

- Openness, network advantages, open platform support
- Site monitoring, cloud product monitoring, custom monitoring, alerts and contact management

### Monitoring and Alerting Concepts

- Monitoring items: HTTP: `http.response Time` & `http.status`
- Monitoring point: an instance of a monitoring item
- Dimension: the dimension that locates where monitoring item data resides; currently dimensions are represented by "field information"
- Rule: condition
- Alert group
- Alert method
- Status code, response time
