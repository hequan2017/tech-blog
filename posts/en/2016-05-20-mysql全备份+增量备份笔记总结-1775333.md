> **About this post**
>
> This post walks through the complete workflow of MySQL full and incremental backups: use cases for cold/warm/hot backups, common mysqldump options (--single-transaction, --master-data, -B, -F, --events, etc.), per-database backup scripts, binlog rotation and recovery by position or point in time, and fixes for common errors (unknown variable, ERROR 1046, the mysql.event warning).
>
> **Technical notes**
>
> The commands in this post reflect the MySQL 5.1/5.5 era; from MySQL 8.0 on, the binary log is enabled by default and GRANT can no longer implicitly create users. For large production databases, XtraBackup physical backups are recommended instead; mysqldump suits small-to-medium databases. When parsing binlogs, remember to add --no-defaults to bypass client character-set options.

## 1. Basic Backup Concepts

Three types by service state:

- Cold backup: requires shutting down the MySQL service; performed with both read and write requests disallowed
- Warm backup: the service is online, but only read requests are supported; write requests are not allowed
- Hot backup: the business is unaffected while the backup runs

Which type applies depends on business requirements, not on the backup tool. MyISAM does not support hot backups; InnoDB does, but it requires specialized tools.

By backup content:

- Full backup: backs up all character sets
- Incremental backup: data changed since the last full or incremental backup; it cannot be used on its own and must be combined with a full backup. The backup frequency depends on how often the data changes
- Differential backup: data changed since the last full backup

Recommended recovery strategies:

```text
Full + incremental + binary logs
Full + differential + binary logs
```

## 2. Full Backup Commands and Options

MyISAM:

```shell
mysqldump -uroot -p'123456' -A -B -F --flush-privileges --master-data=2 -x --events | gzip > /opt/x_$(date +%F).sql.gz
```

InnoDB:

```shell
mysqldump -uroot -p123456 --single-transaction -A -B -F --events | gzip > /server/backup/x_$(date +%F).sql.gz
```

Common options explained:

- `--single-transaction`: for MyISAM, use `-x` (--lock-all-tables) to lock tables directly; for InnoDB, use this option to guarantee backup consistency. It is equivalent to setting the isolation level REPEATABLE READ, so that during this session's dump it will not see data committed by other sessions
- `--master-data[=#]`: automatically locates the binlog position; This causes the binary log position and filename to be
  - `--master-data=1`: the binlog no longer needs to be flushed; very useful when doing incremental backups
  - `--master-data=2`: a comment is added afterward, which makes it easier to find
- `-E, --events`: Dump events
- `-A, --all-databases`: dump all databases; usually combined with `-B` plus `--events`
- `-B, --databases`: back up multiple specified databases. Visibly, adding `-B` adds the commands that create the database and connect to it; a must for production backups
- `-F, --flush-logs`: flush and rotate the binlog

Additional note: for either of the two backups above, if the database contains stored procedures and triggers, these options are also needed:

```shell
--triggers --routines --hex-blob    # most companies omit these three options
```

Triggers and stored procedures — if your database has blob columns and you do not add this option, the blob data will be lost.

## 3. Per-Database Backup

```shell
mysql -uroot -p'123456' -e "show databases;" | grep -Evi "Database|infor|perf" | sed -r 's#^([a-z].*$)#mysqldump -uroot -p'"'"'123456'"'"' --events -B \1 | gzip > /tmp/logs/\1.sql.gz#g' | bash
```

- `-t, --no-create-info`: use this if you want to dump only the table data
- `-d, --no-data`: back up the table structure only; No row information

## 4. Common Errors and Fixes

mysqlbinlog reports an unknown variable:

```text
mysqlbinlog: unknown variable 'default-character-set=utf8'
```

Fix:

```shell
mysqlbinlog --no-defaults ./mysql-bin.000007
```

During a full MySQL dump you may see the following warning (by default the event table is not backed up; the warning goes away only when --events is added):

```text
Warning: Skipping the data of table mysql.event. Specify the --events option explicitly
```

Fix:

```shell
--events --ignore-table=mysql.event
```

ERROR 1046 (3D000) at line 22: No database selected — edit the .sql file and add `use db_name;` before line 22.

## 5. Recovery Workflow

First restore the full backup:

```shell
mysql -uroot -p123456 < /server/backup/x.sql
```

Restoring multiple per-database files:

```shell
for name in `ls *.sql | sed 's#.sql##g'`; do mysql -uroot -p123456 < ${name}.sql; done
```

Then:

```shell
mysqladmin -uroot -p123456 flush-log       # rotate the log
```

Collect all the binlogs, remove the bad ones, and convert the rest into SQL statements:

```shell
cp mysql-bin.000016 /server/backup/
mysqlbinlog --no-defaults -d user mysql-bin.000016 > bin.sql
mysql -uroot -p123456 < bin.sql
```

Piping into `| mysql` also works.

Recovery by binlog position and time:

```shell
mysqlbinlog --start-position=107 --stop-position=1000 -d db_name binlog_file
mysqlbinlog --start-datetime='2013-09-10 00:00:00' --stop-datetime='2013-09-10 01:01:01' -d db_name binlog_file
```

```shell
egrep -v "#|\*|--|^$"    # filter to inspect the backup content
```

rsync combined with a scheduled job:

```shell
rsync -avz /data/3306/mysql-bin.000* rsync_backup@10.0.0.18::backup --password-file=/etc/rsync.password
```

## 6. Backup-Related Configuration in a Master-Slave Architecture

**One master with multiple slaves; one slave is used for backups.**

Set up passwordless login:

```shell
vim .my.cnf    # configure the login
```

```ini
[client]
user=root
host=localhost
password=123456
```

View/set the character set:

```shell
mysql> show variables like "character_set%";    # view the character set
```

```ini
[client]                      # set the character set
default-character-set=utf8

[mysqld]
character-set-server=utf8     # 5.5
default-character-set=utf8    # 5.1

[mysql]
default-character-set=utf8
```

Enable the bin-log; keep one full backup plus backups of all incremental binlog files:

```shell
mysql> show full processlist;              # connection status
mysql> show variables like "%log_bin%";
```

```text
+---------------------------------+-------+
| Variable_name                   | Value |
+---------------------------------+-------+
| log_bin                         | OFF   |
| log_bin_trust_function_creators | OFF   |
| sql_log_bin                     | ON    |
+---------------------------------+-------+
```

```shell
mysql> flush tables with read lock;    # read lock
mysql> unlock tables;                  # unlock
```

Master-slave related parameters:

```ini
replicate_wild_ignore_table=mysql.%     # wildcards are allowed
--skip-name-resolve                     # start mysqld with this option to disable DNS hostname lookups
slave-skip-errors = 1032,1062           # skip errors 1032, 1062
lower_case_table_names=1                # make MySQL case-insensitive! Use with caution; it affects existing table names

[mysqld]
read-only                               # read-only; root is not restricted
```

Replication out of sync.

Enable binlog logging on the slave for cascading replication and use it as the database backup:

```ini
log-bin = /data/3307/mysql-bin
log-slave-updates    # controls whether updates applied on the slave are written to its binary log; off by default. Required when this slave B also acts as the master of server C, so that C can receive B's binary logs for sync
expire_logs_days = 7    # keep for 7 days
```

Monitoring status:

```shell
# mysql -e "show slave status\G;" | egrep 'Slave_IO_Running|Slave_SQL_Running' | awk '{print $2}' | egrep 'Yes' | wc -l
```
