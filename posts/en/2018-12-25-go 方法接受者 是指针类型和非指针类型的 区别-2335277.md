> **About this post**
>
> Using the same set of examples — a Tesla struct implementing the Car interface (GetName/Run) — this post compares value receivers and pointer receivers in Go: a value receiver `(t Tesla)` operates on a copy, so renaming the field in GetName does not affect the original struct, and the interface variable stores the value directly, `c = t`; a pointer receiver `(t *Tesla)` can modify the original struct's fields, and the interface variable must store an address, `c = &t`. The conclusion at the end: only by passing a pointer can you modify and preserve the struct's value in other methods.

> **Technical notes**
>
> In the original post, several occurrences of `t.Name` / `return t.Name` / `t.Name` arguments were swallowed by the web editor and have been restored; the language tag of the two code blocks was corrected from python to go. In the non-pointer section, the comment at `c = t` was mistakenly written in the original as "implemented with a pointer, pass the address"; it has been corrected to reflect pass-by-value. The typo "tes t" in the program output has been corrected to "test". As a supplement: by the method-set rules, if `T` has only pointer-receiver methods, only `*T` implements the interface; with value-receiver methods, both `T` and `*T` implement the interface.

## 1. Non-pointer type (value receiver)

```go
package main

import "fmt"

// Define the interface
type Car interface {
	GetName() string
	Run()
}

// Define the struct
type Tesla struct {
	Name string
}

// Implement the interface's GetName() method
func (t Tesla) GetName() string {
	t.Name = "test"
	return t.Name
}

// Implement the interface's Run() method
func (t Tesla) Run() {
	fmt.Printf("%s is running\n", t.Name)
}

func main() {
	var c Car
	var t Tesla = Tesla{"Tesla Model S"}
	c = t // The interface above is implemented with a non-pointer Tesla, so just pass the value here
	fmt.Println(c.GetName())
	c.Run()
}
```

Program output:

```text
test
Tesla Model S is running
```

Although GetName() with a value receiver does change Name, it only changes a copy; the values in the original struct and in the interface variable are unaffected, so Run() still prints "Tesla Model S".

## 2. Pointer type (pointer receiver)

```go
package main

import "fmt"

// Define the interface
type Car interface {
	GetName() string
	Run()
}

// Define the struct
type Tesla struct {
	Name string
}

// Implement the interface's GetName() method
func (t *Tesla) GetName() string {
	t.Name = "test"
	return t.Name
}

// Implement the interface's Run() method
func (t *Tesla) Run() {
	fmt.Printf("%s is running\n", t.Name)
}

func main() {
	var c Car
	var t Tesla = Tesla{"Tesla Model S"}
	c = &t // The interface above is implemented with the pointer *Tesla, so the address must be passed here
	fmt.Println(c.GetName())
	c.Run()
}
```

Program output:

```text
test
test is running
```

GetName() with a pointer receiver modifies the struct itself, so the subsequent Run() reads the changed "test".

## 3. Conclusion

> Passing a pointer makes it possible to modify the value of the struct being passed in, and the change takes effect in other methods as well.
> I had always written Python and never understood what pointers were good for. Using them here, I finally understand a little.
