> **About this post**
>
> In front-end/back-end separated development, browser cross-origin access (CORS) is an issue the back end must handle. This post shows how to enable CORS in the goframe framework: a BeforeServe hook is attached to all routes via `BindHookHandlerByMap`, which writes the CORS-related response headers into the response, and for OPTIONS preflight requests it returns success directly and interrupts further processing (`r.ExitAll()`), preventing preflight requests from reaching the business logic.

> **Technical notes**
>
> This post is based on goframe v1 (the gogf/gf era). v1 was discontinued around 2022; the current version is GoFrame v2 (import path `github.com/gogf/gf/v2`). GoFrame v2 offers better CORS support: it provides the out-of-the-box `r.Response.CORSDefault()`, and the official recommendation is to handle CORS uniformly through middleware (`MiddlewareHandlerResponse` / a custom CORS middleware), so manually attaching a BeforeServe hook is no longer needed.

---

```go
s := g.Server()
	s.BindHookHandlerByMap("/*any", map[string]ghttp.HandlerFunc{
		"BeforeServe": func(r *ghttp.Request) {

			r.Response.CORS(ghttp.CORSOptions{
				AllowOrigin:      "*",
				AllowMethods:     "POST, GET, OPTIONS, PUT, DELETE,UPDATE,",
				AllowCredentials: "false",
				MaxAge:           1728000,
				AllowHeaders:     "Authorization, Content-Length, X-CSRF-Token, Token,session,X_Requested_With,Accept, Origin, Host, Connection, Accept-Encoding, Accept-Language,DNT, X-CustomHeader, Keep-Alive, User-Agent, X-Requested-With, If-Modified-Since, Cache-Control, Content-Type, Pragma",
				ExposeHeaders:    "Content-Length, Access-Control-Allow-Origin, Access-Control-Allow-Headers,Cache-Control,Content-Language,Content-Type,Expires,Last-Modified,Pragma,FooBar",
			})

			if r.Request.Method == "OPTIONS" {
				_ = r.Response.WriteJson(g.Map{
					"code": http.StatusOK,
					"msg":  "",
					"data": nil,
				})
				r.ExitAll()
			}

		}})
```
