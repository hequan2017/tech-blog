> **About this post**
>
> This post explains three ways to implement Apache virtual hosts — name-based, port-based, and IP-based — to host multiple sites on a single server: first create the /var/html/{www,blog,bbs} site directories and generate test pages with a for loop; then write three `<VirtualHost *:80>` blocks in extra/httpd-vhosts.conf (configuring DocumentRoot, ServerName, ServerAlias, and separate error/access logs for each); then enable the Include directive in the main configuration file httpd.conf and set Directory access permissions for the /var/html directory (Order allow,deny / Allow from all); finally, it notes that you should check the logs when something goes wrong, and that if a FQDN-related message appears at startup you need to set ServerName.

> **Technical notes**
>
> The `Order allow,deny` / `Allow from all` syntax is Apache 2.2 access control, replaced by `Require all granted` in 2.4 (you must enable mod_access_compat or rewrite the configuration); name-based virtual hosts in 2.4 also no longer require the NameVirtualHost directive. The domain names and email suffix in the original text were lost during scraping and must be filled in yourself when configuring.

## 1. Overview

Deploy multiple sites with different domain names and site directories; you can also use different ports or different IPs.

In other words, the three approaches to virtual hosts: **name-based, port-based, and IP-based**.

## 2. Create the Site Directories and Test Pages

```shell
mkdir /var/html/{www,blog,bbs} -p
for name in www blog bbs; do echo "http://$name" > /var/html/$name/index.html; done
```

## 3. Configure the Virtual Hosts

Edit the virtual host configuration file:

```shell
vim conf/extra/httpd-vhosts.conf
```

(The domain names and email suffix are missing from the original; the values of ServerName/ServerAlias/ServerAdmin need to be filled in yourself:)

```apache
<VirtualHost *:80>
    ServerAdmin     hequan@
    DocumentRoot    "/var/html/www"
    ServerName
    ServerAlias
    ErrorLog    "logs/www-error_log"
    CustomLog   "logs/www-access_log" common
</VirtualHost>

<VirtualHost *:80>
    ServerAdmin     hequan@
    DocumentRoot    "/var/html/blog"
    ServerName
    ErrorLog    "logs/blog-error_log"
    CustomLog   "logs/blog-access_log" common
</VirtualHost>

<VirtualHost *:80>
    ServerAdmin     hequan@
    DocumentRoot    "/var/html/bbs"
    ServerName
    ErrorLog    "logs/bbs-error_log"
    CustomLog   "logs/bbs-access_log" common
</VirtualHost>
```

## 4. Enable in the Main Configuration File and Set Directory Permissions

Edit the main configuration file:

```shell
vi httpd.conf
```

Enable the virtual host configuration and set access permissions for the site directories:

```apache
Include conf/extra/httpd-vhosts.conf

<Directory "/var/html">              # Directory permissions
    Options FollowSymLinks
    AllowOverride None
    Order allow,deny
    Allow from all
</Directory>
```

## 5. Troubleshooting Tips

When something goes wrong, check the logs (each virtual host's error_log and access_log under the logs/ directory).

FQDN domain name: if a message says the server's fully qualified domain name cannot be reliably determined at startup, you need to set ServerName in httpd.conf. The note from the official configuration file:

```apache
# If your host doesn't have a registered DNS name, enter its IP address here.
#
#ServerName www.example.com:80
```
