> **About this post**
>
> Hands-on beginner notes for Puppet: set up a master/agent architecture on two machines, complete certificate signing to establish trust (the agent sends the request and the master signs it with `puppet cert --sign`), then write the site.pp and node.pp manifests, demonstrating how to install software with a package resource and how to create a file with permissions on the agent using a file resource.

> **Technical notes**
>
> This post reflects Puppet 3.x-era practices: starting the service directly with `puppet master`, the `import` statement, and the `puppet cert` subcommand are all deprecated in Puppet 4+. Modern versions use puppetserver (a JVM service), manage certificates with `puppetserver ca`, and use `/etc/puppetlabs/code/environments/production/manifests` as the manifest entry point. These days Ansible is the more mainstream choice for configuration management.

The master and the agent establish trust through certificate-based encryption.

## 1. Environment Preparation and Installation

Hosts resolution on the two machines:

```text
192.168.2.130   puppet.hequan.lol   puppet
192.168.2.131   station.hequan.lol  station
```

```bash
# on the master
yum install puppet.noarch puppet-server.noarch
# on the agent
yum install puppet.noarch
```

## 2. Configure and Start the Master

```bash
[root@puppet puppet]# ls
auth.conf  fileserver.conf  manifests  modules  puppet.conf
[root@puppet puppet]# vim puppet.conf
```

```ini
[master]
    certname=puppet.hequan.lol
```

```bash
[root@puppet puppet]# puppet master
[root@puppet puppet]# netstat -lntup | grep 8140
tcp        0      0 0.0.0.0:8140            0.0.0.0:*               LISTEN      2580/ruby
```

## 3. The Agent Sends a Certificate Request

```bash
[root@station ~]# puppet agent --server=puppet.hequan.lol --no-daemonize --verbose --onetime   ## looks for puppet by default
```

On the master side, check the requests and sign:


## 4. Writing Manifests

`/etc/puppet/manifests` is the manifest directory on the master server, which needs to contain xxx.pp files:

```bash
[root@puppet manifests]# ll
-rw-r--r-- 1 root root 159 8月  31 20:58 node.pp
-rw-r--r-- 1 root root  53 8月  31 20:48 site.pp

[root@puppet manifests]# cat site.pp
```

```puppet
$puppetserver="puppet.hequan.lol"
import 'node.pp'
```

```bash
[root@puppet manifests]# cat node.pp
```

```puppet
node 'station.hequan.lol' {
    # how to define a resource:
    # resource type {'resource name': attr1 => 'value1'}
    package{"system-config-date":ensure=>'present'}
}
```

You can also define an nginx package and a file resource:

```puppet
package {'nginx':
    ensure => present,
}

file {"/root/aa1.txt":
    ensure => "present",
    mode   => "0000"
}
```

After running on the agent, verify:

```bash
[root@station puppet]# ll /root
总用量 4
---------- 1 root root 0 8月  31 21:26 aa1.txt
```
