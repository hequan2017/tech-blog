> **About this post**
>
> This post compares soft links and hard links: the difference between ln and ln -s, using ll -li to observe inodes and link counts, and that only soft links can be created for directories. It explains that a file is truly deleted only when both the hard link count i_link=0 and no process holds it open (i_count=0). An experiment with an httpd access log shows that when the log is held by a process, rm frees no disk space after deletion; restart the service or truncate the file with >. It ends with the three timestamps atime/mtime/ctime and the stat command, plus miscellaneous commands such as usermod/useradd and chattr to lock account files.

> **Technical notes**
>
> The experiment environment is CentOS 6 (mkfs ext3, /etc/init.d service scripts). The trick of using lsof | grep del to locate files that are "deleted but still held by a process" still works today. On CentOS 7+ the default filesystem is xfs, but the troubleshooting approach for disk space not being freed is the same, and files can also be recovered via /proc/<PID>/fd.

## 1. Soft Links and Hard Links

```shell
# ln source_file link_file     # hard link
# ln -s source_file link_file  # soft link
# ln -s /application/apache2.2.17/ /application/apache
```

Observe the inode and link count:

```shell
# ll -li a b c
402871 -rw-r--r-- 2 root root 3 3月  27 19:10 a
402872 lrwxrwxrwx 1 root root 1 3月  27 19:16 b -> a
402871 -rw-r--r-- 2 root root 3 3月  27 19:10 c
```

Only soft links can be created for directories.

## 2. Conditions for File Deletion

A file is truly deleted only when both conditions are met:

- Hard link count i_link=0: a new file starts with i_link=1, creating a hard link makes it i_link=2, and the file is deleted once i_link=0
- No process holds the file: i_count increases by 1 while a process holds the file, and the file is truly deleted only when i_count=0

## 3. Experiment: Deleting a Log File Held by a Process

Install httpd and point the logs to a separate small partition:

```shell
# yum -y install httpd
# grep log httpd.conf --color=auto
# sed -i 's@CustomLog logs/access_log combined@CustomLog /app/log/access_log combined@g' /etc/httpd/conf/httpd.conf
# mkdir /app/log -p
# dd if=/dev/zero of=/dev/sdc bs=8k count=10
# mkfs -t ext3 /dev/sdc
# mount /dev/sdc /app/log/ -o loop
# df -h
# tail -f access_log
```

Generate some traffic, then delete the log:

```shell
# rm -f access_log
# lsof | grep del
# /etc/init.d/httpd restart
```

Solutions:

1. Delete the file and restart the service
2. Truncate the file instead of deleting it
3. Do not delete today's files held by a process; delete older ones instead

```shell
# for n in `seq 100000`; do curl -s 192.168.10.10 > /dev/null; done
# > access_log          # truncate the file
# lsof -i :22
```

## 4. Directory Link Count and User/Login-Related Commands

The hard link count of a directory changes after you create a subdirectory:

```shell
# ls -ld /hequan/ett/
drwxr-xr-x 2 root root 4096 3月  27 20:08 /hequan/ett/
# info ln
# mkdir -p /hequan/ett/xx
# ls -ld /hequan/ett
drwxr-xr-x 3 root root 4096 3月  27 20:09 /hequan/ett
```

## 5. Three Timestamps and stat

- access (atime): time of last access
- modify (mtime): modification time; `ls -lt` sorts by it by default
- change (ctime): time of status change (updated when metadata such as permissions or owner changes)

```shell
# stat a
# ls -l --time-style=long-iso
```
