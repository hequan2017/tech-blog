> **About this post**
>
> This is an advanced hands-on note on rsync daemon mode: starting the service,
> checking the process, and writing to /etc/rc.local for autostart at boot;
> on the client side, excluding multiple files with --exclude={1,2} and
> --exclude-from, and on the server side, excluding them with the exclude
> parameter in /etc/rsyncd.conf followed by a service restart; it focuses on
> demonstrating the danger of --delete exact-replica synchronization in two
> directions — when pushing, "whatever the local machine has, the server has";
> when releasing/downloading code, "whatever the remote has, the local has,
> and what the remote lacks is deleted locally too"; it closes with two
> troubleshooting clues: the timeout parameter and the /var/log/rsyncd.log log.

> **Technical notes**
>
> The environment in this post is CentOS 6 (rsync 3.0.6), which reached end of
> life (EOL) in November 2020; on that system, service autostart relies on
> /etc/rc.local, while newer distributions should use a systemd unit instead.
> --delete is a destructive parameter; it is advisable to first preview with
> -n (--dry-run) to confirm. After changing the server-side configuration,
> restart with pkill rsync followed by rsync --daemon; the equivalent on newer
> systems is systemctl restart rsyncd.

## 1. Starting the Service and Autostart at Boot

```shell
rsync --daemon
ps -ef | grep rsync
echo "/usr/bin/rsync --daemon" >> /etc/rc.local
```

## 2. Excluding Files from Synchronization

Client-side exclusion (excluding multiple files):

```shell
rsync -avz /data/ --exclude={1,2} \
    rsync_backup@192.168.10.10::hequan --password-file=/etc/rsync.password
```

Reading the exclusion list from a file:

```text
--exclude-from=<exclusion-list-file>
```

Server-side exclusion (configured in /etc/rsyncd.conf):

```shell
vi /etc/rsyncd.conf
```

```ini
exclude = 1 2 3
```

Restart the service after modifying the configuration:

```shell
pkill rsync
rsync --daemon
```

## 3. Exact-Replica Synchronization with --delete (Dangerous)

Exact-replica synchronization is extremely dangerous; be especially careful when doing backups:

Push direction — whatever the local machine has, the server has (it will wipe out the extra files on the server side; be careful):

```shell
rsync -avz /data/ rsync_backup@192.168.10.10::hequan \
    --password-file=/etc/rsync.password --delete
```

Code release/download direction — whatever the remote has, the local has, and what the remote does not have is deleted locally too:

```shell
rsync -avz rsync_backup@192.168.10.10::hequan /data/ \
    --password-file=/etc/rsync.password --delete
```

## 4. Timeout and Logs

- `timeout = 400`: the timeout setting in rsyncd.conf, which prevents the server from waiting indefinitely when a client misbehaves
- `/var/log/rsyncd.log`: the rsync daemon log; check here first when something goes wrong
