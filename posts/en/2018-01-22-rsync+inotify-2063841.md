> **About this post**
>
> A complete solution for real-time file synchronization using rsync daemon + inotify-tools: the server hosts rsync through xinetd, changes the default port from 873 to 8888, and configures the rsyncd.conf module and password file; the client compiles and installs inotify-tools 3.14 and raises the kernel inotify parameters. A sync script handles events by category (CREATE/MODIFY/DELETE/ATTRIB), uses `-R` to preserve the directory structure, and syncs the parent directory on deletion; finally, a crontab job provides a scheduled full sync as a fallback.

> **Technical notes**
>
> The rsync + inotify approach still works today, but environments differ considerably: hosting rsync via xinetd is uncommon on RHEL 8+/Rocky 8+, where a plain `rsync --daemon` or a systemd socket is simpler; inotify-tools is now in EPEL/official repositories, so building from source is no longer necessary; the default of the kernel parameter `fs.inotify.max_user_watches` is much higher on recent kernels — just tune it to your workload. For large-scale production, consider lsyncd, syncthing, or object storage.

### rsync

#### Target server setup

```shell
* Default port is 873; changed to 8888 here
* rsync  data mirror backup tool
* xinetd network daemon service
```

#Install the software

```shell
yum install rsync xinetd -y

rpm -qa|grep rsync
rsync-3.0.9-18.el7.x86_64
```

#Set up the xinetd config file for start on boot

```shell
cat >>  /etc/xinetd.d/rsync  <<EOF
service rsync
{
        disable = no
        flags           = IPv6
        socket_type     = stream
        wait            = no
        user            = root
        server          = /usr/bin/rsync
        server_args     = --daemon
        port            = 8888
}
EOF
```

```shell
vim /etc/services
254 rsync           8888/tcp                         # rsync
255 rsync           8888/udp                         # rsync
```

#Create the user

```shell
groupadd rsync
useradd -g rsync rsync
mkdir /home/rsync/backup/
chown -R rsync.rsync /home/rsync/backup/
```

#Set up the rsyncd config file

```shell
cat >>  /etc/rsyncd.conf  <<EOF
port = 8888
uid = rsync
gid = rsync
use chroot = no
max connections = 40
timeout = 300
pid file = /var/run/rsyncd.pid
lock file = /var/run/rsyncd.lock
log file = /home/rsync/backup/rsyncd.log

ignore errors
read only = false
list = false
hosts allow = 192.168.10.0/24
hosts deny = 0.0.0.0/32
auth users = rsync
secrets file =/etc/rsyncd.passwd

[backup]
path = /home/rsync/backup/
EOF
```

#Set the account password

```shell
echo rsync:hequan            >    /etc/rsyncd.passwd
```

#Set permissions

```shell
chmod 600 /etc/rsyncd.passwd
chmod 600 /etc/rsyncd.conf
```

#Start

```shell
systemctl start xinetd.service
```

### inotify

- A powerful, fine-grained, asynchronous mechanism for monitoring file system events

#Check whether the server kernel supports inotify; if the entries below exist, it is supported

```shell
ll /proc/sys/fs/inotify
total 0
-rw-r--r-- 1 root root 0 Jan 22 17:39 max_queued_events
-rw-r--r-- 1 root root 0 Jan 22 17:39 max_user_instances
-rw-r--r-- 1 root root 0 Jan 22 17:39 max_user_watches
```

```shell
yum install make  gcc gcc-c++  -y

cd /usr/local/src/
wget http://github.com/downloads/rvoicilas/inotify-tools/inotify-tools-3.14.tar.gz

tar xf inotify-tools-3.14.tar.gz
cd inotify-tools-3.14
./configure --prefix=/usr/local/inotify
make && make install

echo "PATH=/usr/local/inotify/bin:$PATH" >> /etc/profile.d/inotify.sh
source /etc/profile.d/inotify.sh
echo "/usr/local/inotify/lib" >/etc/ld.so.conf.d/inotify.conf
ln -s /usr/local/inotify/include  /usr/include/inotify
```

```shell
sysctl -a | grep max_queued_events
sysctl -a | grep max_user_watches
sysctl -a | grep max_user_instances

echo  'fs.inotify.max_queued_events=99999999
fs.inotify.max_user_watches=99999999
fs.inotify.max_user_instances=65535
'   >>  /etc/sysctl.conf

/sbin/sysctl -p
```

```shell
vim /data/rsync_inotify.sh
#!/bin/bash
src=/data/                              # source path to sync
cd $src
des=backup                              # the name published by rsync --daemon on the target server; rsync --daemon itself is not covered here — it is fairly simple, just search online
rsync_passwd_file=/etc/rsyncd.passwd    # password file for rsync authentication
ip1=192.168.10.149                      # target server 1
user=rsync                              # authentication user defined by rsync --daemon
cd ${src}                               # in this approach, due to how rsync sync works, you must cd into the source directory first so that inotify watches ./ and the directory structure stays consistent after the rsync sync; feel free to experiment and see the results yourself
/usr/local/inotify/bin/inotifywait  -mrq --format  '%Xe %w%f' -e modify,create,delete,attrib,close_write,move ./  |   while read file         # loop over the "list of changed file paths" reported by the monitor
do
        INO_EVENT=$(echo $file | awk '{print $1}')      # split the inotify output and assign the event type field to INO_EVENT
        INO_FILE=$(echo $file | awk '{print $2}')       # split the inotify output and assign the file path field to INO_FILE
        echo "-------------------------------$(date)------------------------------------"
        echo $file
        #create, modify, close-write, moved-in events
        #create and modify share one branch, because both are definitely file operations; even a newly created directory only syncs an empty directory, which does not affect speed.
        if [[ $INO_EVENT =~ 'CREATE' ]] || [[ $INO_EVENT =~ 'MODIFY' ]] || [[ $INO_EVENT =~ 'CLOSE_WRITE' ]] || [[ $INO_EVENT =~ 'MOVED_TO' ]]         # check the event type
        then
                echo 'CREATE or MODIFY or CLOSE_WRITE or MOVED_TO'
                rsync -avzcR  --port=8888    --password-file=${rsync_passwd_file}      $(dirname ${INO_FILE})    ${user}@${ip1}::${des}        # the INO_FILE variable holds the path; -c verifies file content

                 #look closely at the rsync command above: the source uses $(dirname ${INO_FILE}), meaning each pass only syncs the directory containing the changed file (syncing only the changed file itself can miss files in some extreme production environments; this way nothing is missed while still keeping good speed — a good balance), and the -R option then appends the source directory structure recursively on the target, keeping the directory structure consistent
        fi
        #delete, moved-out events
        if [[ $INO_EVENT =~ 'DELETE' ]] || [[ $INO_EVENT =~ 'MOVED_FROM' ]]
        then
                echo 'DELETE or MOVED_FROM'
                rsync  -avzR   --port=8888   --delete --password-file=${rsync_passwd_file}       $(dirname ${INO_FILE}) ${user}@${ip1}::${des}
                #note the rsync command: syncing the already-deleted path ${INO_FILE} directly would fail with a "no such file or directory" error, so the source synced here is the parent path of the deleted file or directory, plus --delete to remove files that exist on the target but not on the source. Deleting a specific file is not possible this way; the closer the deleted path is to the root, the more directories get synced and the longer the deletion sync takes. If you have a better approach, feedback is welcome.
        fi
        #attribute-change events: operations such as touch, chgrp, chmod, chown
        if [[ $INO_EVENT =~ 'ATTRIB' ]]
        then
                echo 'ATTRIB'
                if [ ! -d "$INO_FILE" ]                 # if the attribute change is on a directory, skip syncing, because syncing a directory triggers a recursive scan; when the files under it get synced, rsync updates the directory as well
                then
                        rsync -avzcR  --port=8888   --password-file=${rsync_passwd_file}     $(dirname ${INO_FILE})    ${user}@${ip1}::${des}
                fi
        fi
done
```
