> **About this post**
>
> This post demonstrates dynamic provisioning with a Kubernetes StorageClass
> backed by NFS through a set of YAML manifests: deploying
> nfs-client-provisioner (a ServiceAccount + Deployment pointing to the NFS
> server 192.168.100.111 and the shared directory /data1); creating a
> ClusterRole / ClusterRoleBinding for authorization; defining a StorageClass
> named nfs; and finally creating a PVC (test-claim) to test automatic PV
> provisioning.

> **Technical notes**
>
> This post was written in 2019: the extensions/v1beta1 API used by the
> Deployment was removed in k8s 1.16+, so modern versions need apps/v1 plus a
> selector; the nfs-client-provisioner (external-storage) project has been
> archived and the community now maintains
> kubernetes-sigs/nfs-subdir-external-provisioner; the
> volume.beta.kubernetes.io/storage-class annotation in the PVC has been
> superseded by spec.storageClassName; the podsecuritypolicies authorization
> in the ClusterRole was removed along with PSP in k8s 1.25.

## 1. Deploy the nfs-client-provisioner

> An NFS server needs to be set up in advance.

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: nfs-client-provisioner
---
kind: Deployment
apiVersion: extensions/v1beta1
metadata:
  name: nfs-client-provisioner
spec:
  replicas: 1
  strategy:
    type: Recreate
  template:
    metadata:
      labels:
        app: nfs-client-provisioner
    spec:
      serviceAccount: nfs-client-provisioner
      containers:
        - name: nfs-client-provisioner
          image: registry.cn-hangzhou.aliyuncs.com/open-ali/nfs-client-provisioner
          volumeMounts:
            - name: nfs-client-root
              mountPath: /persistentvolumes
          env:
            - name: PROVISIONER_NAME
              value: hequan.com/nfs
            - name: NFS_SERVER
              value: 192.168.100.111
            - name: NFS_PATH
              value: /data1
      volumes:
        - name: nfs-client-root
          nfs:
            server: 192.168.100.111
            path: /data1
```

## 2. RBAC Authorization

```shell
vim clusterrole.yaml   # Create a ClusterRole
```

```yaml
kind: ClusterRole
apiVersion: rbac.authorization.k8s.io/v1
metadata:
  name: nfs-provisioner-runner
rules:
  - apiGroups: [""]
    resources: ["persistentvolumes"]
    verbs: ["get", "list", "watch", "create", "delete"]
  - apiGroups: [""]
    resources: ["persistentvolumeclaims"]
    verbs: ["get", "list", "watch", "update"]
  - apiGroups: ["storage.k8s.io"]
    resources: ["storageclasses"]
    verbs: ["get", "list", "watch"]
  - apiGroups: [""]
    resources: ["events"]
    verbs: ["watch", "create", "update", "patch"]
  - apiGroups: [""]
    resources: ["services", "endpoints"]
    verbs: ["get"]
  - apiGroups: ["extensions"]
    resources: ["podsecuritypolicies"]
    resourceNames: ["nfs-provisioner"]
    verbs: ["use"]
```

```shell
vim clusterrolebinding.yaml   # Create a ClusterRoleBinding
```

```yaml
kind: ClusterRoleBinding
apiVersion: rbac.authorization.k8s.io/v1
metadata:
  name: run-nfs-provisioner
subjects:
  - kind: ServiceAccount
    name: nfs-client-provisioner
    namespace: default
roleRef:
  kind: ClusterRole
  name: nfs-provisioner-runner
  apiGroup: rbac.authorization.k8s.io
```

## 3. StorageClass

```yaml
kind: StorageClass
apiVersion: storage.k8s.io/v1
metadata:
  name: nfs
provisioner: hequan.com/nfs
parameters:
  archiveOnDelete: "false"
```

## 4. Testing

Create a PVC (test-claim) to test automatic PV provisioning:

```yaml
kind: PersistentVolumeClaim
apiVersion: v1
metadata:
  name: test-claim
  annotations:
    volume.beta.kubernetes.io/storage-class: "nfs"
spec:
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 1Mi
```
