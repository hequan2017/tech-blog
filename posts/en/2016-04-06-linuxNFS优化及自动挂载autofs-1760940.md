> **About this post**
>
> This post covers NFS mount option tuning and autofs automatic mounting:
> what the security options nosuid/noexec/nodev do and their limits (an
> interpreter call can bypass noexec); using dd and time to compare write
> performance between rsize/wsize=1024 and the default 131072 (22.1 MB/s vs
> 5.5 MB/s); using noatime/nodiratime to reduce timestamp updates when
> reading files; a recommended mount option combination for CentOS 6
> x86_64; enlarging socket buffers via /proc/sys/net/core and persisting
> them in /etc/sysctl.conf; and finally on-demand automatic mounting with
> autofs (auto.master + auto.misc, automatic unmount after a 10-second
> timeout), plus a firewall and common command cheat sheet.

> **Technical notes**
>
> The environment here is CentOS 6. On CentOS 7+ service management moved
> to systemctl; the autofs package name and config file paths are
> unchanged. Hard-link-style hard mounts ignore the intr option under
> NFSv4.2; enlarging rmem/wmem is still a useful reference for high-latency
> networks, but should be combined with real bandwidth testing.

---

## 1. Secure Mount Options

```shell
# mount -t nfs -o nosuid,noexec,nodev,rw 192.168.10.10:/data /mnt
# grep mnt /proc/mounts
192.168.10.10:/data/ /mnt nfs4 rw,nosuid,nodev,noexec,relatime,vers=4,rsize=131072,wsize=131072,namlen=255,hard,proto=tcp,port=0,timeo=600,retrans=2,sec=sys,clientaddr=192.168.10.11,minorversion=0,local_lock=none,addr=192.168.10.10 0 0
```

- noexec: blocks running executables directly; it only applies to executing
  the command itself — going through an interpreter doesn't count
- nosuid/noexec: shell and php execution still works, but adding an
  interpreter no longer does (security options)

```shell
# ll rm
-rwsr-xr-x 1 root root 57440 3月  28 00:08 rm
# ./rm /tmp/xx
-bash: ./rm: 权限不够
```

## 2. rsize/wsize Performance Comparison

Confirm the sync option on the server:

```shell
# cat /var/lib/nfs/etab
/data   192.168.10.0/24(rw,sync,wdelay,hide,nocrossmnt,secure,root_squash,no_all_squash,no_subtree_check,secure_locks,acl,anonuid=65534,anongid=65534,sec=sys,rw,root_squash,no_all_squash)
```

On the client, force-unmount and remount:

```shell
# umount -lf /mnt/          # force unmount
# mount -t nfs -o nosuid,noexec,rsize=1024,wsize=1024,rw 192.168.10.10:/data/ /mnt
```

Performance test:

```shell
# time dd if=/dev/zero of=/tmp/testfile bs=9k count=2000
记录了2000+0 的读入
记录了2000+0 的写出
18432000字节(18 MB)已复制，3.37836 秒，5.5 MB/秒

real    0m3.526s
user    0m0.002s
sys     0m0.257s
```

After removing rsize=1024 and wsize=1024 (removing the read/write size
limits):

```text
18432000字节(18 MB)已复制，0.833856 秒，22.1 MB/秒

real    0m0.842s
user    0m0.001s
sys     0m0.065
```

## 4. Recommended Mount Options

Recommended for CentOS 6 x86_64:

```shell
mount -t nfs -o noatime,nodiratime,nosuid,noexec,nodev,rw,bg,hard,intr,rsize=131072,wsize=131072 192.168.10.10:/data /mnt
```

Simple performance tuning:

```shell
mount -t nfs -o noatime,nodiratime,rsize=131072,wsize=131072 192.168.10.10:/data /mnt
```

Check the mount options:

```shell
# grep /mnt /proc/mounts
```

## 5. Kernel Socket Buffer Tuning

Official tuning — check the defaults first:

```shell
# cat /proc/sys/net/core/rmem_default     # receive socket buffer size
124928
# cat /proc/sys/net/core/rmem_max
124928
```

Temporary adjustment from the command line:

```shell
# echo 8388608 > /proc/sys/net/core/rmem_default
# echo 16777216 > /proc/sys/net/core/rmem_max
```

Kernel tuning for a production NFS environment, written to
/etc/sysctl.conf:

```shell
cat >> /etc/sysctl.conf <<EOF
net.core.wmem_default = 8388608        # w: send
net.core.rmem_default = 8388608        # r: receive
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
EOF
sysctl -p
```

## 7. autofs Automatic Mounting

CentOS 6 client:

```text
autofs.x86_64 : A tool for automatically mounting and unmounting
              : filesystems
```

```shell
# yum -y install autofs
```

(Do not uninstall with yum remove; it can cause many problems.)

```shell
# /etc/init.d/autofs start
```

Main configuration file /etc/auto.master:

```text
/mnt   /etc/auto.misc   --timeout 10      # auto-unmounts 10 seconds after exit
```

Mount definition /etc/auto.misc:

```text
nfsdata    -fstype=nfs    192.168.10.10:/data
```

The mount is triggered when /mnt/nfsdata is accessed; the final mount
details (hidden from users):

```text
192.168.10.10:/data    18G  2.5G  14G  15% /mnt/nfsdata
```

Other configuration parameters: /etc/sysconfig/autofs.
