> **About this post**
>
> This post is a getting-started operations manual for Kubernetes 1.10.1
> (part one): it first deploys kubectl on a node and connects it to the
> apiserver via kubeconfig, then provides two kubectl subcommand cheat
> sheets (create/expose/rollout/scale and describe/logs/exec/apply, etc.),
> then demonstrates common commands following the complete workflow of
> "create → inspect → expose/publish → troubleshooting → image update and
> rollout → rollback → delete", and finally shows how to write Deployment
> + Service YAML along with recommendations for managing configuration files.

> **Technical notes**
>
> - Kubernetes 1.10 is long past EOL. The `apiVersion: extensions/v1beta1`
>   used in this post was removed in 1.16; Deployments must switch to
>   `apps/v1` and declare an explicit selector.
> - `kubectl run --replicas` has been deprecated since 1.12 and now creates
>   only a single Pod; use `kubectl create deployment` to deploy applications.
>   The `rolling-update` command has been removed.
> - Heapster, which `kubectl top` depends on, has been retired; newer
>   versions require metrics-server.
> - Fixed content that was eaten by an editor or garbled: restored `create`
>   and `describe` as the first rows of the two command tables; changed
>   `certificate`'s "××× resource" to "modify certificate resources" per the
>   official documentation; filled in the missing `taint` description per the
>   official documentation; and corrected the em-dash typo in `exec –it`
>   to `-it`.

## 1. Deploying the kubectl management tool on a node

```shell
# Set the apiserver address and root CA for the cluster entry named kubernetes
kubectl config set-cluster kubernetes --server=https://192.168.1.107:6443 --certificate-authority=ca.pem
# Set the client certificate auth fields for the cluster-admin user entry
kubectl config set-credentials cluster-admin --certificate-authority=ca.pem --client-key=admin-key.pem --client-certificate=admin.pem

# Set the default cluster and user for the context entry named default
kubectl config set-context default --cluster=kubernetes --user=cluster-admin
# Set the current context to default
kubectl config use-context default
```

## 2. kubectl command cheat sheet (1)

| Command | Description |
| --- | --- |
| create | Create a resource from a file or from stdin |
| expose | Expose a resource as a new Service |
| run | Run a particular image in the cluster |
| set | Set specific features on objects |
| get | Display one or many resources |
| explain | Reference documentation |
| edit | Edit a resource with the default editor |
| delete | Delete resources by file name, stdin, resource name, or label selector |
| rollout | Manage the rollout of a resource |
| rolling-update | Perform a rolling update of the given ReplicationController |
| scale | Scale the number of Pods for a Deployment, ReplicaSet, RC, or Job |
| autoscale | Automatically choose the number of Pods to scale up or down |
| certificate | Modify certificate resources |
| cluster-info | Display cluster info |
| top | Display resource (CPU/Memory/Storage) usage. Requires Heapster to be running |
| cordon | Mark a node as unschedulable |
| uncordon | Mark a node as schedulable |
| drain | Drain a node in preparation for maintenance |
| taint | Update the taints on one or more nodes |

## 4. Common workflow

1. Create:

```shell
kubectl run nginx --replicas=3 --labels="app=example" --image=nginx:1.10 --port=80
```

2. Inspect:

```shell
kubectl get deploy
kubectl get pods --show-labels
kubectl get pods -l app=example
kubectl get pods -o wide
```

3. Publish:

```shell
kubectl expose deployment nginx --port=88 --type=NodePort --target-port=80 --name=nginx-service
kubectl describe service nginx-service
```

4. Troubleshooting:

```shell
kubectl describe TYPE NAME_PREFIX
kubectl logs nginx-xxx
kubectl exec -it nginx-xxx bash
```

5. Update:

```shell
kubectl set image deployment/nginx nginx=nginx:1.13
```

Or:

```shell
kubectl edit deployment/nginx
```

Rollout management:

```shell
kubectl rollout status deployment/nginx
kubectl rollout history deployment/nginx
kubectl rollout history deployment/nginx --revision=3
kubectl scale deployment nginx --replicas=10
```

6. Rollback:

```shell
kubectl rollout undo deployment/nginx-deployment
kubectl rollout undo deployment/nginx-deployment --to-revision=3
```

7. Delete:

```shell
kubectl delete deploy/nginx
kubectl delete svc/nginx-service
```

## 5. Managing resources with YAML configuration files

Notes on configuration files:

- When defining configuration, specify the latest stable API version (currently v1);
- Configuration files should be stored in a version control repository outside the cluster, so that configurations can be quickly rolled back, recreated, and restored if needed;
- Configuration files should be written in YAML rather than JSON. Although both formats work, YAML is more user-friendly;
- Related objects can be grouped into a single file, which is usually easier to manage;
- Do not specify default values unnecessarily; simple, minimal configurations reduce errors;
- Describing an object in comments makes it easier to maintain.

Create a new `nginx-deployment.yml`:

```yaml
apiVersion: extensions/v1beta1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 1
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.13
        ports:
        - containerPort: 80

---

apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
  - name: http
    port: 80
    protocol: TCP
    targetPort: 80
  type: NodePort
```

Create the resources:

```shell
kubectl create -f nginx-deployment.yml
```
