> **About this post**
>
> This post is a note on installing and configuring the Glance image service: it first introduces the four image states (active/saving/killed/queued), then walks through the full Glance installation on the h4 node — yum installation, initializing the database with openstack-db, registering the user/service/endpoint with keystone, copying glance-api.conf from the template and editing it (database connection, RabbitMQ, keystone authentication), and starting the three services api/registry/scrubber. It then demonstrates two image backend switches: switching to Swift object storage, and switching to Ceph RBD (including deploying MON/OSD/MDS on h5/h6 with ceph-deploy, creating the glance pool, and configuring the Glance node as a Ceph client). Finally it covers the key points of manually building a qcow2 image under KVM (installing cloud-init, removing the MAC binding, adding serial console parameters to grub, sealing with virt-sysprep, and compressing with qemu-img).

> **Technical notes**
>
> The standalone CLIs in this post, such as `keystone user-create` and `glance image-list`, were deprecated long ago; use the unified commands instead, such as `openstack user create` and `openstack image list`. The glance-registry service was deprecated in the Rocky release and removed in Stein; the auth_host/auth_port/admin_user style in `[keystone_authtoken]` has become auth_url/username/password. Both the Ceph hammer release and the ceph-deploy tool are no longer maintained; deployments now use cephadm. The image-building approach (cloud-init + virt-sysprep + qemu-img) is still generally applicable today, and you can also use the distribution's official cloud image directly.

## 1. Images and Their States

An image is a virtual disk that has an OS installed on it, and Glance handles its management.

Image states:

- **active**: The image has been fully uploaded and is available
- **saving**: It is being uploaded and not yet complete
- **killed**: An error occurred during upload
- **queued**: The upload has not really completed, but the image is marked as present

## 2. Install Glance and Register It with Keystone

Installation steps: register the account needed by glance with keystone → create the glance service → specify the endpoint → install the software:

```shell
[root@h4 ~]# yum -y install openstack-glance.noarch
[root@h4 ~]# openstack-db --init --service glance --password 123456 --rootpw 123456
[root@h4 ~(keystone_admin)]# keystone user-create --name glance --pass 123456
[root@h4 ~(keystone_admin)]# keystone user-role-add --user glance --tenant services --role admin
[root@h4 ~(keystone_admin)]# keystone service-create --name glance --type image --description "glance jingxiang"
[root@h4 ~(keystone_admin)]# keystone endpoint-create --service-id 3d0969b633044029a895da1ca2855464 --publicurl 'http://192.168.1.204:9292' --internalurl 'http://192.168.1.204:9292' --adminurl 'http://192.168.1.204:9292'
```

## 3. Modify the Configuration Files

Glance consists of three services: api accepts user requests, registry interacts with the database, and scrubber interacts with other interfaces:

```shell
[root@h4 glance(keystone_admin)]# systemctl list-unit-files | grep glanc
openstack-glance-api.service                disabled   # accepts user requests
openstack-glance-registry.service           disabled   # interacts with the database
openstack-glance-scrubber.service           disabled   # interacts with other interfaces
[root@h4 glance(keystone_admin)]# ls
glance-api.conf    glance-registry.conf  metadefs     schema-image.json
glance-cache.conf  glance-scrubber.conf  policy.json
[root@h4 glance(keystone_admin)]# cd /usr/share/glance/    # template directory
[root@h4 glance(keystone_admin)]# ls
glance-api-dist.conf      glance-registry-dist.conf
glance-api-dist-paste.ini glance-registry-dist-paste.ini
glance-cache-dist.conf    glance-scrubber-dist.conf
[root@h4 glance(keystone_admin)]# cp glance-api-dist.conf /etc/glance/glance-api.conf   # copy the template
```

Edit glance-api.conf:

```ini
[DEFAULT]
debug = False
verbose = True
use_stderr = False
log_file = /var/log/glance/api.log
filesystem_store_datadir = /var/lib/glance/images/
scrubber_datadir = /var/lib/glance/scrubber
image_cache_dir = /var/lib/glance/image-cache/
rabbit_host = 192.168.1.204
rabbit_port = 5672
rabbit_hosts = $rabbit_host:$rabbit_port
rabbit_use_ssl = false
rabbit_userid = guest
rabbit_password = guest
rabbit_login_method = AMQPLAIN
[database]
connection = mysql://glance:123456@192.168.1.204/glance
[keystone_authtoken]
admin_tenant_name = services
admin_user = glance
admin_password = 123456
auth_host = 192.168.1.204
auth_port = 35357
auth_protocol = http
auth_uri = http://192.168.1.204:5000/
[paste_deploy]
config_file = /usr/share/glance/glance-api-dist-paste.ini

```

```shell
[root@h4 glance]# chown root.glance glance-api.conf
[root@h4 glance]# systemctl start openstack-glance-api.service openstack-glance-registry.service openstack-glance-scrubber.service
[root@h4 glance]# systemctl enable openstack-glance-api.service openstack-glance-registry.service openstack-glance-scrubber.service
```

## 5. Change the Image Storage Backend

### 5.1 Swift as the Backend Store

```ini
#filesystem_store_datadir = /var/lib/glance/images/   # disable local storage first
[glance_store]
default_store = swift              # default is file, change it to swift
stores = file, http                # leave the default as is
swift_store_auth_version = 2       # default version is 2
stores = glance.store.swift.Store,glance.store.filesystem.Store   # this entry must be added, otherwise uploads fail
swift_store_auth_address = http://192.168.1.204:5000/v2.0/   # keystone authentication of the controller
swift_store_user = service:swift   # use the swift user
swift_store_key = hequan           # password
swift_store_container = glance     # the container to be created
swift_store_create_container_on_put = True    # create the container automatically on upload
swift_store_large_object_size = 5120         # 5 GB max limit, but the limit is ineffective when combined with glance
swift_store_large_object_chunk_size = 200    # chunk size 200MB
swift_enable_snet = False
```

```shell
[root@h4 glance(keystone_admin)]# systemctl restart openstack-glance-api.service openstack-glance-registry.service openstack-glance-scrubber.service
```

### 5.2 Ceph Shared Storage

![Hand-drawn Ceph architecture diagram: the client reaches OSDs through the metadata service, with MON monitors](../assets/1828592/01_wKioL1eQyIXiJOY3AAExaGE5bbI635.png)

Install the EPEL repository and add the Ceph yum repository:

```shell
rpm -vih http://mirrors.sohu.com/fedora-epel/7/x86_64/e/epel-release-7-2.noarch.rpm
```

```ini
# vim /etc/yum.repos.d/ceph.repo
[ceph]
name=Ceph noarch packages
baseurl=http://mirrors.163.com/ceph/rpm-hammer/el7/x86_64/
enabled=1
gpgcheck=1
type=rpm-md
gpgkey=http://mirrors.163.com/ceph/keys/release.asc
```

Install ceph-deploy and ceph (install ceph on all nodes; ceph-deploy only needs to be installed on the admin node):

```shell
yum -y update && yum -y install ceph ceph-deploy
```

**1) Generate the MON-related information**; the monitor server is h5:

```shell
[root@h5 xx]# ceph-deploy new h5
[root@h5 xx]# ls
ceph.conf  ceph-deploy-ceph.log  ceph.mon.keyring
```

**2) Modify the ceph.conf configuration file according to your own situation:**

```ini
osd_pool_default_size = 2      # number of replicas, default is 3
osd_pool_default_min_size = 1  # minimum is 1
```

**3) Generate the keys**; when a client wants to connect to the Ceph server, a username and password are required:

```shell
[root@h5 xx]# ceph-deploy mon create-initial
[root@h5 myceph]# ls
ceph.bootstrap-mds.keyring  ceph.client.admin.keyring  ceph.mon.keyring
ceph.bootstrap-osd.keyring  ceph.conf
ceph.bootstrap-rgw.keyring  ceph.log
```

**4) Start preparing the OSD configuration:**

```shell
mkdir /path1 /path2
[root@h5 xx]# ceph-deploy osd prepare h5:/path1 h6:/path2
[root@h5 xx]# ceph-deploy osd activate h5:/path1 h6:/path2    # activate
[ceph_deploy.osd][DEBUG ] Host h5 is now ready for osd use.
```

**5) Copy the keys to each node:**

```shell
[root@h5 ceph]# ceph-deploy admin h5 h6
[root@h5 ceph]# ceph health    # health check
```

**6) Create the storage pool:**

```shell
[root@h5 ceph]# ceph-deploy mds create h5
[root@h5 ceph]# rados lspools
[root@h5 ceph]# rados mkpool glance
[root@h5 ceph]# rados rmpool glance glance --yes-i-really-really-mean-it   # delete the pool
```

### 5.3 Configure Glance as a Ceph Client

Install the Ceph client on the Glance node (h4) and push the configuration over:

```shell
[root@h4 ceph(keystone_admin)]# ls
rbdmap
[root@h5 myceph]# ceph-deploy admin h4
[root@h4 ceph(keystone_admin)]# ls
ceph.client.admin.keyring  ceph.conf  rbdmap
```

Edit glance-api.conf:

```ini
[glance_store]
default_store = rbd
stores = rbd
rbd_store_pool = glance
rbd_store_user = admin
rbd_store_ceph_conf = /etc/ceph/ceph.conf
rbd_store_chunk_size = 8
```

```shell
systemctl restart openstack-glance-api.service openstack-glance-registry.service openstack-glance-scrubber.service
-rw------- 1 root root 63 7月 21 16:43 ceph.client.admin.keyring
setfacl -m u:glance:r-- ceph.client.admin.keyring    # set permissions so the glance user can read the keyring
```

## 6. Building an Image

```shell
yum -y groupinstall "Server with GUI"
yum install virt-manager python-virtinst qemu-kvm-tools qemu-kvm libvirt
```

Key points for building an image in KVM:

1. Create the storage volume centos.qcow2 and install the system with a basic installation;
2. Configure the network card and remove the MAC address binding (remove HWADDR from ifcfg and the udev rules);
3. Install the basic component openssh-clients;
4. Install cloud-init (the cloud initialization package).

Modify grub to set the serial console parameters (so that nova console-log can capture logs):

```shell
[root@h4 ~]# vim /etc/default/grub
GRUB_CMDLINE_LINUX="net.ifnames=0 biosdevname=0 console=tty0 console=ttyS0,115200n8 rhgb quiet"
[root@h4 ~]# grub2-mkconfig -o /boot/grub2/grub.cfg
```

Seal the image (clean up machine-specific information such as the machine ID, logs, and SSH host keys):

```shell
[root@h5 ~]# yum whatprovides */virt-sysprep
[root@h5 ~]# yum -y install libguestfs-tools-c
[root@h4 ~]# virt-sysprep -d centos
[root@h4 ~]# cd /openstack-image/
[root@h4 openstack-image]# qemu-img info centos.qcow2
qemu-img convert -c -O qcow2 centos.qcow2 newcentos.qcow2   # compress the image ("conver" in the original is a typo)
```
