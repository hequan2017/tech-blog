> **About this post**
>
> This post is a beginner's introduction to LVS load balancing: it first distinguishes the two cluster types, load balancing and high availability; introduces the components of LVS (the kernel IPVS module, the ipvsadm management tool, and keepalived) and the four address concepts CIP/VIP/DIP/RIP; focuses on the DR (Direct Routing) mode — rewriting the destination MAC of the data frame to distribute requests, real servers binding the VIP on lo:0 while suppressing ARP, and responses returning directly to the client; lists scheduling algorithms such as rr/wrr/wlc/dh/sh; and provides complete commands for compiling and installing ipvsadm on the Director, configuring the VIP and virtual services, and binding the VIP with ARP suppression on the RS side.

> **Technical notes**
>
> CentOS 6 reached end of life (EOL) in November 2020; for production environments, migrating to Rocky Linux / AlmaLinux / Ubuntu LTS is recommended.
> On current distros you can simply run `yum install ipvsadm` — no manual compilation needed; IPVS has long been built into the kernel, and `modprobe ip_vs` is only needed when the module is not yet loaded.
> Production environments usually manage the VIP, the RS list, and health checks through keepalived instead of typing ipvsadm commands by hand; prefer `ip addr add` over the `ifconfig eth0:0` alias syntax.

## 1. Cluster and LVS Basic Concepts

A cluster: a group of computers connected through a network to form a system, where each node is an independent server running its own processes.

It addresses high concurrency and high throughput, and offers transparency, high performance, high availability, scalability, manageability, and programmability.

- Load balancing clusters: lvs, nginx, haproxy
- High availability clusters: keepalived

Linux Virtual Server (LVS):

- Scheduling implementation: IPVS (kernel module)
- Management tool: ipvsadm
- keepalived provides management and high availability

Four key addresses:

1. CIP (Client computer's IP address): the public IP, used by the client.
2. VIP (Virtual IP address): the IP address the Director uses to serve clients.
3. RIP (Real IP address): the IP address used by the cluster nodes (the back-end servers that actually provide the service).
4. DIP (Director's IP address): the address the Director uses to communicate with the D/RIP side.

Packets flow CIP ←→ DIP ←→ RIP, with the VIP carried externally by the Director:

## 2. LVS Working Modes and the DR Principle

Modes: NAT, TUN, **DR**, FULLNAT.

DR (Direct Routing) mode:

By rewriting the destination MAC address of the request packet, requests are sent to a real server, and the real server returns the processing result of the response directly to the client.

Based on the load of each server, the LVS scheduler **dynamically selects one server**; it neither modifies nor encapsulates the IP packet, but changes the **MAC address of the data frame** to that of the **selected server**, then sends the modified frame on the LAN where the server group resides. Since the frame's MAC address is that of the selected server, the server will certainly receive the frame and can extract the IP packet from it.

When the server finds that the packet's destination address VIP is configured on one of its local network devices, it processes the packet and then, according to the routing table, returns the response packet **directly to the client**.

This requires the Director Server and the Real Servers to each have a network interface on the same physical network segment.

## 3. LVS Scheduling Algorithms (8-10 in Total)

1. **rr** round robin scheduling
2. **wrr** weighted round robin scheduling / **wlc** weighted least connections scheduling
3. dh destination address hashing scheduling
4. sh source address hashing scheduling

## 4. Director Side: Installation and Configuration

Install the dependencies and compile ipvsadm:

```shell
yum -y install kernel-devel libnl* popt* gcc
ln -s /usr/src/kernels/2.6.32-642.1.1.el6.x86_64/ /usr/src/linux
tar zxvf ipvsadm-1.26.tar.gz
cd ipvsadm-1.26
make && make install
```

Load the kernel module and verify:

```shell
modprobe ip_vs
lsmod | grep ip_vs
```

```text
ip_vs                 126897  0
libcrc32c               1246  1 ip_vs
ipv6                  336282  265 ip_vs
```

Check the version:

```shell
/sbin/ipvsadm
```

```text
IP Virtual Server version 1.2.1 (size=4096)
Prot LocalAddress:Port Scheduler Flags
  -> RemoteAddress:Port           Forward Weight ActiveConn InActConn
```

Configure the VIP on the Director and add a host route:

```shell
ifconfig eth0:0 192.168.10.40
route add -host 192.168.10.1 dev eth0
route -n
```

```text
Destination     Gateway         Genmask         Flags Metric Ref    Use Iface
192.168.10.1    0.0.0.0         255.255.255.255 UH    0      0        0 eth0
```

Add the virtual service and the real servers:

```shell
ipvsadm -C
ipvsadm --set 30 5 60
ipvsadm -A -t 192.168.10.40:80 -s rr -p 20                 # -D deletes it
ipvsadm -a -t 192.168.10.40:80 -r 192.168.10.11 -g -w 1    # -d deletes it
ipvsadm -a -t 192.168.10.40:80 -r 192.168.10.10 -g -w 1
```

View the rules:

```shell
ipvsadm -L -n
```

```text
IP Virtual Server version 1.2.1 (size=4096)
Prot LocalAddress:Port Scheduler Flags
  -> RemoteAddress:Port           Forward Weight ActiveConn InActConn
TCP  192.168.10.40:80 rr persistent 20
  -> 192.168.10.10:80             Route   1      0          0
  -> 192.168.10.11:80             Route   1      0          0
```

## 5. Real Server Side: Binding the VIP and Suppressing ARP

On the RS side, bind the VIP to lo:0:

```shell
ifconfig lo:0 192.168.10.40/32 up
route add -host 192.168.10.40 dev lo
```

Suppress ARP:

```shell
echo "1" > /proc/sys/net/ipv4/conf/lo/arp_ignore
echo "2" > /proc/sys/net/ipv4/conf/lo/arp_announce
echo "1" > /proc/sys/net/ipv4/conf/all/arp_ignore
echo "2" > /proc/sys/net/ipv4/conf/all/arp_announce
```
