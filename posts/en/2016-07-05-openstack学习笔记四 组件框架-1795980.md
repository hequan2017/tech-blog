> **About this post**
>
> This post outlines the core OpenStack components and their division of labor:
> nova manages virtual machines, cinder provides cloud disks, swift offers
> object storage, glance manages images, and neutron handles networking. All
> components must register with keystone for authentication, the components
> communicate with one another via RabbitMQ, and the environment relies on
> MySQL to store their data. It also presents the framework split across the
> four node types — control, compute, network, and storage — and uses the
> openstack-status command to actually inspect the running state of each
> service in an all-in-one environment, along with keystone users, glance
> images, nova-managed services, and the lists of networks, flavors, and
> instances.

> **Technical notes**
>
> Components mentioned here such as nova-network, glance-registry, the
> ceilometer services, and the standalone keystone process were gradually
> removed or merged in later releases (nova-network was replaced by Neutron,
> and Ceilometer was split into Gnocchi/Aodh, among other changes); the
> keystone CLI was folded into the unified openstack CLI long ago. The
> openstack-status tool is likewise gone in newer versions — use commands such
> as `openstack compute service list` instead. The idea of dividing
> responsibilities among components remains unchanged to this day.

## 1. Core components and their roles

![Diagram of OpenStack component relationships](../assets/1795980/01_wKioL1d7Y5axIAUcAAGfHpahaZg188.png)

- **nova**: manages virtual machines
- **cinder**: cloud disks
- **swift**: object storage (containers)
- **glance**: images
- **neutron**: networking
- **keystone**: authentication; all components must register with keystone

The components communicate with one another via RabbitMQ, and the environment also needs MySQL to store each component's data.

![Horizon system information page: all 11 services are active](../assets/1795980/02_wKioL1d7Y6SAMcmwAABx_euWN2s683.png)

## 2. Node framework division

1. **Control node**: runs keystone, the dashboard, and so on
2. **Compute node**: the machines that run virtual machines
3. **Network node**: provides routing and DHCP for the virtual machines inside compute nodes
4. **Storage node**

![Diagram of a multi-node OpenStack framework](../assets/1795980/03_wKioL1d7Y7ChSVIMAANheC-Ejkg318.png)
