> **About this post**
>
> This post first explains the principles of OpenStack Swift object storage: the three concepts of
> container/object/account, how the ring maps objects via partitions (2^n) onto zones, the three
> ring files and the /srv/node mount point, and the division of labor among the consistency
> services (auditor/replicator/updater), the proxy service, and the three types of storage
> services. It then walks through a hands-on installation on the h4 node: installing the Swift
> components with yum, registering the user, tenant, and endpoint with Keystone, preparing two xfs
> partitions mounted as zone1/zone2, creating and rebalancing the three rings with
> swift-ring-builder, and starting the account/object/container services. Finally it configures
> proxy-server.conf to connect to Keystone, starts the proxy and memcached, verifies with swift
> post/upload/list, and observes partition fault tolerance.

> **Technical notes**
>
> CentOS 7 reached end of life (EOL) on June 30, 2024; consider migrating to Rocky Linux 9,
> AlmaLinux 9, or the China-developed openEuler. The `keystone` CLI used in this post was removed
> as of the Queens release; use the `openstack` CLI instead. In `swift-ring-builder create 12 2 1`
> the three arguments are, in order, the number of partitions 2^12, the replica count 2, and the
> minimum migration interval of 1 hour. In production, load balancing should also be added in
> front of the proxy, and multiple memcached instances should be configured.

## 1. Swift principles: containers, rings, and zones

Project → object storage → container: even a folder you create inside a container shows up on the disk as a file — that is, an object.

First, look at the Swift service on h1 deployed by packstack and how objects land on disk:

```shell

[root@h1 ~(keystone_admin)]# keystone endpoint-list | grep 30c62c3c0797462a8bd4ff059a71296e
```

Mapping: the ring maps objects onto disks.

1. Container — objects are created inside a container
2. Object — a file is an object
3. Account — permissions

Ring files, saved to disk:

- `account.ring.gz` — account
- `container.ring.gz` — container
- `object.ring.gz` — object

The directory where data is saved on disk is called a zone. The mount point `/srv/node/swiftloopback/` must be placed under the **`/srv/node/`** directory:

- zone1
- zone2 — the two are identical, acting as backups

After a packstack installation, when you upload a file only **one copy** is kept on disk.

An object is first mapped to a virtual node/partition (2^n), and then mapped to a zone.

Purpose: to reduce the amount of data migration.

## 2. Composition of the Swift services

1. Consistency server

   - auditor — scans periodically; when it finds a problem, the faulty file is moved to quarantine
   - replicator — copies the identical file over from the other zone to keep the data in sync
   - update — if the replicator fails, wait a while and try again

2. Proxy server

   Accepts requests sent by users, such as uploads and deletions.

3. Storage services

   - container server
   - object server
   - account server

## 3. Installing the software and registering with Keystone

```shell
[root@h4 ~]# yum list openstack-swift*
[root@h4 ~]# yum -y install openstack-swift.noarch openstack-swift-account.noarch openstack-swift-container.noarch openstack-swift-object.noarch  openstack-swift-proxy.noarch   memcache*  python-swiftclient
```

Every service must register with Keystone:

```shell
[root@h4 ~(keystone_admin)]# keystone  user-create  --name swift --pass  hequan
[root@h4 ~(keystone_admin)]# keystone   tenant-create  --name services
[root@h4 ~(keystone_admin)]# keystone user-role-add --user swift  --tenant services --role  admin
```

Create the service and specify the endpoint:

```shell
[root@h4 ~(keystone_admin)]# keystone  service-create  --name swift --type  object-store --description "swift"
keystone  endpoint-create  --service-id  0995c9a9ed4847da86435bca9a7be8fc  --publicurl  'http://192.168.1.204:8080/v1/AUTH_%(tenant_id)s'  --internalurl  'http://192.168.1.204:8080/v1/AUTH_%(tenant_id)s'  --adminurl  'http://192.168.1.204:8080'
```

## 4. Configuring storage and creating the rings

Two partitions were prepared. In fstab they are mounted as zone1 and zone2 under /srv/node:

```shell
zone1 zone2          under /srv/node
/dev/sdb1            /srv/node/zone1           xfs   defaults 0 0                  ## mount
/dev/sdb2            /srv/node/zone2           xfs   defaults 0 0
```

```shell
[root@h4 ~(keystone_admin)]# chown -R swift.swift /srv/node/
```

`swift.conf` stores the hash suffix:

```ini
[swift-hash]
swift_hash_path_suffix = %SWIFT_HASH_PATH_SUFFIX%
```

Now look again at what the object file path means: `zone/object type/partition number/suffix/hash of the file name/timestamp of the upload`:

```shell
[root@h1 ~(keystone_admin)]# find /srv/node/swiftloopback/ -type f -name "*.data"
/srv/node/swiftloopback/objects/102340/afe/63f12ea37cca17f0227381adcf93eafe/1467982747.16551.data

[root@h1 ~(keystone_admin)]# date --date=@1467982747.16551
2016年 07月 08日 星期五 20:59:07 CST
```

### Creating the ring files

Create the templates, specifying how many replicas and how many partitions there are:

```shell
[root@h4 swift(keystone_admin)]# swift-ring-builder account.builder create 12 2 1
[root@h4 swift(keystone_admin)]# swift-ring-builder object.builder create 12 2 1
[root@h4 swift(keystone_admin)]# swift-ring-builder container.builder create 12 2 1
```

Specify the mapping locations. The IP must be changed in all 3 server config files:

```shell
[root@h4 swift]# vim account-server.conf           # change the ip in all 3
  6 bind_ip = 192.168.1.204
```

```shell
[root@h4 swift(keystone_admin)]# swift-ring-builder  account.builder  add  z1-192.168.1.204:6202/zone1 100
[root@h4 swift(keystone_admin)]# swift-ring-builder  account.builder  add  z2-192.168.1.204:6202/zone2 100
[root@h4 swift(keystone_admin)]# swift-ring-builder  object.builder  add  z1-192.168.1.204:6200/zone1 100
[root@h4 swift(keystone_admin)]# swift-ring-builder  object.builder  add  z2-192.168.1.204:6200/zone2 100
[root@h4 swift(keystone_admin)]# swift-ring-builder  container.builder  add  z1-192.168.1.204:6201/zone1 100
[root@h4 swift(keystone_admin)]# swift-ring-builder  container.builder  add  z2-192.168.1.204:6201/zone2 100
```

Rebalance to generate the ring files:

```shell
[root@h4 swift(keystone_admin)]# swift-ring-builder account.builder  rebalance
[root@h4 swift(keystone_admin)]# swift-ring-builder object.builder  rebalance
[root@h4 swift(keystone_admin)]# swift-ring-builder container.builder  rebalance
[root@h4 swift(keystone_admin)]# ls *.gz
account.ring.gz  container.ring.gz  object.ring.gz
```

## 5. Starting the storage services

```shell
[root@h4 srv(keystone_admin)]# systemctl  start openstack-swift-account  openstack-swift-object  openstack-swift-container
[root@h4 srv(keystone_admin)]# systemctl  is-active openstack-swift-account  openstack-swift-object  openstack-swift-container
active
active
active
[root@h4 srv(keystone_admin)]# systemctl  enable openstack-swift-account  openstack-swift-object  openstack-swift-container
```

## 6. The proxy server and verification

Fill the authtoken section of `proxy-server.conf` with the swift account registered in Keystone:

```ini
[filter:authtoken]
paste.filter_factory = keystonemiddleware.auth_token:filter_factory
admin_tenant_name = services
admin_user = swift
admin_password = hequan
identity_uri = http://192.168.1.204:35357/
auth_port = 35357
auth_protocol = http
#auth_uri = http://192.168.1.204:5000/
```

```shell
[root@h4 swift(keystone_admin)]# systemctl  start openstack-swift-proxy.service
[root@h4 swift(keystone_admin)]# systemctl  enable openstack-swift-proxy.service
[root@h4 swift(keystone_admin)]# systemctl  start memcached.service
[root@h4 swift(keystone_admin)]# systemctl  enable  memcached.service

[root@h4 swift(keystone_admin)]# swift  post h1
[root@h4 swift(keystone_admin)]# swift list
h1
[root@h4 swift(keystone_admin)]# swift  upload  h1  /etc/hosts
```

If any single partition fails, everything can still be viewed normally; if both fail, the data can no longer be viewed.
