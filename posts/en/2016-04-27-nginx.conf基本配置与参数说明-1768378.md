> **About this post**
>
> A sample nginx.conf with full inline comments: the global section (running
> user, worker_processes, error_log, pid file), the events section (use epoll,
> worker_connections and the maximum concurrency, plus an estimate of the
> system's open file handle limit), and the http section (mime types, the
> log_format log format, sendfile/keepalive/tcp_nodelay, gzip compression,
> request buffer sizes), as well as a server virtual host: home page index,
> 50x error pages, expires 30d for static files, PHP requests forwarded via
> fastcgi to 127.0.0.1:9000, and access to .ht files denied.

> **Technical notes**
>
> The configuration style in this post generally applies to all nginx 1.x
> releases; two updates: modern versions recommend setting `worker_processes`
> to `auto` so it matches the number of CPU cores automatically; when
> forwarding PHP requests, the difference between `include fastcgi_params` and
> `fastcgi.conf` is that the latter already includes the SCRIPT_FILENAME line.
> CentOS 7 reached EOL on 2024-06-30, and the nginx it ships with is no longer
> updated; for production, Rocky/Alma 9 + nginx 1.26+ is recommended.

## 1. Global Configuration and the events Section

```nginx
# Running user
user nobody;
# Worker processes; usually set equal to the number of CPUs
worker_processes  1;

# Global error log and PID file
#error_log  logs/error.log;
#error_log  logs/error.log  notice;
#error_log  logs/error.log  info;

#pid        logs/nginx.pid;

# Working mode and connection limit
events {
    # epoll is one of the I/O multiplexing methods,
    # available only on Linux kernels 2.6 and above; it can greatly improve nginx performance
    use   epoll;

    # Maximum concurrent connections per worker process
    worker_connections  1024;

    # The total concurrency is the product of worker_processes and worker_connections,
    # i.e. max_clients = worker_processes * worker_connections
    # With a reverse proxy in place, max_clients = worker_processes * worker_connections / 4. Why?
    # Dividing by 4 for the reverse proxy case is an empirical rule of thumb
    # Under the above conditions, a normal nginx server can handle at most 4 * 8000 = 32000 connections
    # The worker_connections value is related to the amount of physical memory
    # Since concurrency is constrained by IO, max_clients must be smaller than the maximum number of files the system can open
    # The maximum number of open files is proportional to memory size; a machine with 1 GB of memory can open roughly 100k files
    # Let's see how many file handles a VPS with 360 MB of memory can open:
    # $ cat /proc/sys/fs/file-max
    # output: 34336
    # 32000 < 34336, i.e. the total concurrent connections are fewer than the total file handles the system can open,
    # which stays within what the operating system can bear
    # So the value of worker_connections should be set appropriately based on the number of worker_processes
    # and the maximum total number of files the system can open,
    # so that the total concurrency stays below the maximum number of files the OS can open
    # In essence, this means sizing the configuration to the host's physical CPUs and memory
    # Of course, the theoretical total concurrency may deviate from reality,
    # since other worker processes on the host also consume system resources.
    # ulimit -SHn 65535
}
```

## 2. http Global Section

```nginx
http {
    # Set the mime types; types are defined in the mime.types file
    include    mime.types;
    default_type  application/octet-stream;

    # Set the log format
    log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                      '$status $body_bytes_sent "$http_referer" '
                      '"$http_user_agent" "$http_x_forwarded_for"';

    access_log  logs/access.log  main;

    # The sendfile directive specifies whether nginx calls the sendfile function (zero copy) to output files.
    # For ordinary applications it must be set to on;
    # for disk-IO-heavy applications such as downloads, it can be set to off,
    # to balance disk and network I/O speed and reduce the system's uptime.
    sendfile     on;
    #tcp_nopush     on;

    # Connection timeout
    #keepalive_timeout  0;
    keepalive_timeout  65;
    tcp_nodelay     on;

    # Enable gzip compression
    gzip  on;
    gzip_disable "MSIE [1-6]\.";

    # Request buffer settings
    client_header_buffer_size    128k;
    large_client_header_buffers  4 128k;
```

## 3. server Virtual Host

```nginx
    # Virtual host configuration
    server {
        # Listen on port 80
        listen    80;
        # Accessed via www.nginx.cn
        server_name  www.nginx.cn;

        # Define the server's default web root directory
        root html;

        # Access log for this virtual host
        access_log  logs/nginx.access.log  main;

        # Default request
        location / {
            # Names of the home page index files
            index  index.php index.html index.htm;
        }

        # Define the error pages
        error_page   500 502 503 504  /50x.html;
        location = /50x.html {
        }

        # Static files, handled by nginx itself
        location ~ ^/(images|javascript|js|css|flash|media|static)/ {
            # Expire after 30 days: static files rarely change, so the expiry can be set large;
            # if they are updated frequently, set it smaller.
            expires 30d;
        }

        # All PHP script requests are forwarded to FastCGI, using the default FastCGI configuration.
        location ~ \.php$ {
            fastcgi_pass 127.0.0.1:9000;
            fastcgi_index index.php;
            fastcgi_param  SCRIPT_FILENAME  $document_root$fastcgi_script_name;
            include fastcgi_params;
        }

        # Deny access to .htxxx files
        location ~ /\.ht {
            deny all;
        }
    }
}
```
