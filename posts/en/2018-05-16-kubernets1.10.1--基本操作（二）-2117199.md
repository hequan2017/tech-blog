## 1. Pod Management

### 1.1 Basic Management

```shell
# Create a pod resource
kubectl create -f pod.yaml
# List pods
kubectl get pods nginx-pod
# Show the pod description
kubectl describe pod nginx-pod
# Update the resource
kubectl apply -f pod.yaml
# Delete the resource
kubectl delete pod nginx-pod
```

### 1.2 Scheduling Constraints

- `Pod.spec.nodeName`: forces the Pod to be scheduled onto the specified Node
- `Pod.spec.nodeSelector`: selects nodes through the label-selector mechanism

### 1.3 Restart Policy (restartPolicy)

- `Always`: whenever the container stops, it is always rebuilt. This is the default policy.
- `OnFailure`: the container is restarted only when it exits abnormally (non-zero exit code).
- `Never`: the container is never restarted once it terminates.

### 1.4 Health Checks

- `livenessProbe`: if the check fails, the container is killed, and handling follows the Pod's restartPolicy.
- `readinessProbe`: if the check fails, Kubernetes removes the Pod from the service endpoints.

Probe methods:

- `httpGet`: sends an HTTP request; it succeeds if the returned status code is in the 200-400 range.
- `exec`: runs a shell command; it succeeds if the returned status code is 0.
- `tcpSocket`: succeeds when a TCP socket connection is established.

### 1.5 Troubleshooting

```shell
kubectl describe TYPE NAME_PREFIX
kubectl logs nginx-xxx
kubectl exec -it nginx-xxx bash
```

## 2. Service

### 2.1 Environment Variables

When a Pod runs on a Node, the kubelet adds a set of environment variables to each container, and programs inside the Pod's containers can use these environment variables to discover Services.

The environment variable names have the following format:

```text
{SVCNAME}_SERVICE_HOST
{SVCNAME}_SERVICE_PORT
```

The service name and port name are converted to uppercase, with hyphens converted to underscores.

Limitations:

1. The creation order of Pods and Services matters: the Service must be created before the Pod, otherwise the environment variables will not be set in the Pod.
2. A Pod can only obtain environment variables for Services in the same Namespace.

### 2.3 Service Types

- ClusterIP: assigns an internal cluster IP address, accessible only from inside the cluster (Pods in the same Namespace); this is the default ServiceType.
- NodePort: assigns an internal cluster IP address and opens a port on every node to expose the service, making it accessible from outside the cluster. Access address: `<NodeIP>:<NodePort>`
- LoadBalancer: assigns an internal cluster IP address and opens a port on every node to expose the service. On top of that, Kubernetes requests a load balancer from the underlying cloud platform and adds each Node ([NodeIP]:[NodePort]) as a backend.

```yaml
        ports:
        - containerPort: 80
      volumes:
      - name: glusterfsvol
        glusterfs:
          endpoints: glusterfs-cluster
          path: gv0
          readOnly: false

---

apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
  - name: http
    port: 80
    protocol: TCP
    targetPort: 80
  type: NodePort
```

## 5. PersistentVolumes

1. PersistentVolume (PV, persistent volume): an abstraction of storage that makes storage a resource in the cluster.
2. PersistentVolumeClaim (PVC, persistent volume claim): a PVC consumes the resources of a PV.
3. A Pod claims a PVC to use as a volume; the cluster looks up the PV bound to the PVC through the PVC and mounts it to the Pod.

`nfs-example.yaml`:

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: nfs-pv
spec:
  capacity:
    storage: 5Gi
  accessModes:
    - ReadWriteMany
  nfs:
    path: "/opt/nfs/data"
    server: 192.168.0.200
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: nfs-pvc
spec:
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 5Gi
---
apiVersion: v1
kind: Pod
metadata:
  name: mypod
spec:
  containers:
    - name: nginx
      image: nginx
      volumeMounts:
      - mountPath: "/usr/share/nginx/html/"
        name: wwwroot
  volumes:
    - name: wwwroot
      persistentVolumeClaim:
        claimName: pvc001
```
