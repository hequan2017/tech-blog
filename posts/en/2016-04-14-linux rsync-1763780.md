> **About this post**
>
> This post introduces the three working modes of rsync — local copy, remote
> shell (ssh channel), and daemon (socket) mode — and explains common options
> one by one, including -avz, -a=-rtopgDl, -e, --delete, and --password-file.
> The core is the server-side setup for daemon mode: edit /etc/rsyncd.conf,
> create the rsync runtime user, write the virtual-user password file
> (rsync_backup:hequan, permission 600), start it with rsync --daemon and
> confirm port 873 is listening, and finally configure the client password
> file to complete push/pull synchronization.

> **Technical notes**
>
> The environment in this post uses rsync 3.0.6 (protocol 30) bundled with
> CentOS 6, which reached end of life (EOL) in November 2020. On newer
> distributions, it is recommended to manage the daemon with systemd (a unit
> file or systemctl start rsyncd); in rsyncd.conf, the boolean values false
> and no are equivalent; the password file permission must be 600, otherwise
> authentication fails.

## 1. Introduction to rsync

rsync is an open-source, fast, and versatile synchronization tool. It supports
full and incremental backups, can transfer data between local and remote
hosts, and can also transfer data as a daemon (socket).

Command format: `rsync options source dest` (source / dest).

Three working modes (SYNOPSIS):

```text
Local:  rsync [OPTION...] SRC... [DEST]

Access via remote shell:
Pull: rsync [OPTION...] [USER@]HOST:SRC... [DEST]
Push: rsync [OPTION...] SRC... [USER@]HOST:DEST

Access via rsync daemon:
Pull: rsync [OPTION...] [USER@]HOST::SRC... [DEST]
      rsync [OPTION...] rsync://[USER@]HOST[:PORT]/SRC... [DEST]
Push: rsync [OPTION...] SRC... [USER@]HOST::DEST
      rsync [OPTION...] SRC... rsync://[USER@]HOST[:PORT]/DEST
```

## 2. Local and remote (shell) sync examples

```shell
# Local sync directly, equivalent to cp
rsync -avz /etc/hosts /tmp/

# Deleting files: make empty dir /null/ and /hequan/ identical
rsync -r --delete /null/ /hequan/

# Push (-e specifies the channel)
rsync -avz -e 'ssh' /etc/hosts hequan@192.168.10.11:~

# Pull
rsync -avz -e 'ssh' hequan@192.168.10.11:~/hosts /home/hequan/
```

## 3. Common options

- `-v` verbose output
- `-z` compress during transfer
- `-a` archive mode, equal to `-rtopgDl`: recursive, preserve file times, owner, permissions, group info, device files, and symlinks
- `-e` specify the channel protocol

In daemon mode, `--delete` (sync with no differences) and `--password-file`
(password file) are also commonly used.

## 4. Daemon mode (server side)

Check the version and install:

```shell
rsync --version
# rsync  version 3.0.6  protocol version 30
yum install rsync -y
```

Edit the configuration file:

```shell
vim /etc/rsyncd.conf
```

```ini
##rsyncd.conf start##
uid = rsync
gid = rsync
use chroot = no
max connections = 200
timeout = 300
pid file = /var/run/rsyncd.pid
lock file = /var/run/rsync.lock
log file = /var/log/rsyncd.log

[hequan]
path = /hequan/
ignore errors
read only = false
list = false
hosts allow = 192.168.10.0/24
hosts deny = 0.0.0.0/32
auth users = rsync_backup
secrets file = /etc/rsync.password
#rsync_config_______________end
```

Start it as a daemon and confirm port 873 is listening:

```shell
rsync --daemon
netstat -lntup | grep 873
```

```text
tcp        0      0 0.0.0.0:873                 0.0.0.0:*                   LISTEN      1768/rsync
```

View the log:

```shell
cat /var/log/rsyncd.log
```

```text
2016/03/29 22:53:45 [1768] rsyncd version 3.0.6 starting, listening on port 873
```

Create the user, set ownership, and write the username and password:

```shell
useradd rsync -s /sbin/nologin
chown -R rsync.rsync /hequan/
echo "rsync_backup:hequan" > /etc/rsync.password   # content is username:password
chmod 600 /etc/rsync.password                      # tighten permissions
```

Verify the password file contents:

```shell
cat /etc/rsync.password
# rsync_backup:hequan
```

## 5. Client configuration and push/pull sync

The client password file contains only the password:

```shell
echo "hequan" > /etc/rsync.password
chmod 600 /etc/rsync.password
```

Pull (`hequan` is the module name):

```shell
rsync -avz rsync_backup@192.168.10.10::hequan /data/
```

```text
Password:
receiving incremental file list
./
test1
```

Non-interactive pull and push (`--password-file` specifies the password file):

```shell
rsync -avz rsync_backup@192.168.10.10::hequan --password-file=/etc/rsync.password /data/
rsync -avz /data/ rsync_backup@192.168.10.10::hequan --password-file=/etc/rsync.password
```

## 6. Deployment recap

Server side (/etc/rsyncd.conf): user, directory, module, virtual user, and
password file.

- Shared directory /hequan; create the rsync user and grant ownership
- Create the password file: copy the path from the config file, then add the
  password content in the format "virtual username:password"
- Set the password file permission to 600
- Start with `rsync --daemon`

Client side:

- The client password file is unrelated to the server's; it contains only the
  password, likewise with permission 600
- Use `--password-file=/etc/rsync.password` to supply the password
- Sync directions: push and pull
