> **About this post**
>
> This post is a blank template for an "XX platform upgrade report", listing only the
> fields such a report should contain: upgrade overview (service name, scope of
> impact, version update), upgrade timing (start/end time, upgrade duration,
> handling duration), purpose of the upgrade, handling process, and personnel
> (person in charge, reviewers, review date). No actual upgrade details are filled
> in, so it can serve as a formatting reference for writing platform
> upgrade/change reports.

> **Technical notes**
>
> The original post is only a report framework, without specific version or command
> information. Templates like this are still common in change management today. In
> actual use, it is advisable to add fields such as a rollback plan, pre-upgrade
> backup and verification checklists, impact assessment, and stakeholder
> notification, aligned with the ITIL change process.

## 1. Report Fields at a Glance

| Group | Fields |
| ---- | ---- |
| Upgrade overview | Service name, scope of impact, version update |
| Upgrade timing | Start time, end time, upgrade duration, handling duration |
| Upgrade content | Purpose of the upgrade, handling process |
| Personnel | Person in charge, reviewers, review date |
