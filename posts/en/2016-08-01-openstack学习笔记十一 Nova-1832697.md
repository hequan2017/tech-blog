> **About this post**
>
> This post covers the compute component of the OpenStack multi-node deployment series: installing nova-api/conductor/scheduler/novncproxy and other components on the controller node, installing nova-compute on the compute node, registering the nova user and compute service in keystone, initializing the nova database, and providing the full nova.conf configuration (VNC, libvirt, neutron integration, scheduler, etc.), and finally verifying that every service is up with `nova-manage service list` and `nova host-list`.

> **Technical notes**
>
> This post is based on Liberty-era components: the standalone nova CLI and `nova-manage service list` are deprecated; use `openstack compute service list` instead; keystone v2.0 authentication and the `admin_tenant_name` style have been removed; `sql_connection` should be changed to `[database] connection`; the nova v3 API and the EC2 API were removed long ago. The `115.29.107.17` appearing in the configuration is the public IP of the author's cloud host at the time; using a public IP directly for internal component communication is a security risk — today components should communicate within an intranet or VPC.

---

Compute nodes run virtual machines.

## 1. Install the nova components

```bash
[root@hequan ~]# yum install openstack-nova.noarch openstack-nova-api.noarch openstack-nova-conductor.noarch \
openstack-nova-novncproxy.noarch openstack-nova-scheduler.noarch openstack-nova-console.noarch   ## controller node
[root@hequan ~]# yum install openstack-nova-compute.noarch   ## compute node
```

## 2. keystone registration and database initialization

```bash
keystone user-create --name nova --pass hequan
keystone user-role-add --user nova --role admin --tenant services
keystone service-create --name nova --type compute --description nova
```
