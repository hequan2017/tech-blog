> Personal notes on the first seven sections of "Vue Stack Development in Practice", a course by Lison, author of iview-admin. Covers: vue-cli 3.0 installation; vue-router named views, aliases, route props, and the navigation guard resolution order; communication between components (props/$emit, the Bus event bus); and Vuex state/getters/mutations/actions plus how to write a persistence plugin.

> **Technical notes**
>
> These notes date from the Vue 2 + Vue Router 3 + Vuex 3 era. Vue 3 has replaced Vuex with Pinia, the event bus pattern is officially deprecated (mitt is recommended), and APIs such as `Vue.config.productionTip` have been removed. The concepts are still worth learning, but use Vue 3 + Pinia + Vue Router 4 for new projects.

#### 3. Routing

```js
{
  path: '/argu/:name',
  name: 'argu',
  component: () => import('@/views/argu.vue'),
  props: true

  props: {
    food: 'banana'  // second approach
  },
  props: route => ({  // third approach
    food: route.query.food
  }),
},

{{ food }}

export default {
  props: {
   food : {
      type: String,
      default: 'lison'
    }
  },
  beforeRouteEnter (to, from, next) {
    next(vm => {
      console.log(vm)
    })
  },
   beforeRouteLeave (to, from, next) {
       // const leave = confirm('Are you sure you want to leave?')
       // if (leave) next()
       // else next(false)
       next()
  },
  beforeRouteUpdate (to, from, next) {
    console.log(to, from)
  }
}

export const setTitle = (title) => {
    window.document.title = title || 'admin'
}

const HAS_LOGINED = true

router.beforeEach((to, from, next) => {
  to.meta && setTitle(to.meta.title)
  if (to.name !== 'login') {
    if (HAS_LOGINED) next()
    else next({ name: 'login' })
  } else {
    if (HAS_LOGINED) next({ name: 'home' })
    else next()
  }
})
```

Full resolution order of the navigation guards:

```text
1. Navigation is triggered
2. The leave guard beforeRouteLeave is called in the deactivated component (the page component about to leave)
3. The global before-each guard beforeEach is called
4. beforeRouteUpdate is called in the reused component
5. The route-exclusive guard beforeEnter is called
6. Asynchronous route components are resolved
7. beforeRouteEnter is called in the activated component (the page component about to enter)
8. The global resolve guard beforeResolve is called
9. Navigation is confirmed
10. The global after hook afterEach is called
11. DOM updates are triggered
12. The callback passed to next inside the beforeRouterEnter guard is invoked with the created instance
```

#### 4. Bus and parent-child component communication

Parent-child components: one-way data flow. The parent passes data down via props, and the child reports changes back through events.

```html
<input @input="handleInput" :value="value"/>  // child component
```

```js
handleInput (event) {
  const value = event.target.value
  this.$emit('input', value)
}
```

```html
<a-input @input="handleInput"/>   // parent component
<a-show :content="inputValue"/>
```

```js
components: {
  AInput,
  AShow
},
methods: {
  handleInput (val) {   // get the value
    this.inputValue = val
  }
}
```

Sibling components (event bus):

```js
import Vue from 'vue'
const Bus = new Vue()
export default Bus

import Bus from './lib/bus'

Vue.config.productionTip = false
Vue.prototype.$bus = Bus

methods: {
  handleClick () {
    this.$bus.$emit('on-click', 'hello')
  }
}

mounted () {
  this.$bus.$on('on-click', mes => {
    this.message = mes
  })
}
```

#### 7. Advanced vuex

Persistent storage (store plugin):

```js
export default store => {
  if (localStorage.state) store.replaceState(JSON.parse(localStorage.state))
  store.subscribe((mutation, state) => {
    localStorage.state = JSON.stringify(state)
  })
}

import saveInLocal from './plugin/saveInLocal'
plugins: [ saveInLocal ]
```

In strict mode, use a computed property's getter/setter together with a mutation:

```html
<a-input v-model="stateValue"/>
```

```js
SET_STATE_VALUE (state, value) {
  state.stateValue = value
}

stateValue: {
  get () {
    return this.$store.state.stateValue
  },
  set (val) {
    this.SET_STATE_VALUE(val)
  }
},
```
