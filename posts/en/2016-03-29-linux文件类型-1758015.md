> **About this post**
>
> This post explains Linux's "everything is a file" design philosophy and the common file types: regular files, directories, block devices, character devices, symbolic links, sockets, and more, plus how to identify them with `ls -l` / `file` / `ls -F`.
> The second half digs into the inode and block concepts — an inode stores metadata (size, owner, pointers to the actual data, but not the file name) while blocks store the actual content — and shows how to inspect inode and block counts and sizes with `dumpe2fs` / `df -ih`. It ends with a "disk filled by small files" experiment showing that running out of inodes also causes `No space left on device`.

> **Technical notes**
>
> The inode/block principles still hold today; only tool details have changed: the default ext4 inode size has grown from 128 bytes to 256 bytes, and `dumpe2fs` only works on ext-family filesystems — for XFS use `xfs_info` and `xfs_db` instead. Also, for scenarios with huge numbers of small files, prefer XFS or format with a higher inode density.

## 1. Everything Is a File

In Linux, "everything is a file". Common file types include:

- Regular files (`-`)
- Directories (`d`)
- Block device files (`b`, e.g. disks)
- Character device files (`c`, e.g. terminals)
- Symbolic links (`l`)
- Socket files (`s`, `.sock`)

## 2. Identifying File Types

The first column of `ls -l` output is type + permissions:

```shell
ls -l
# -rw-r--r--   file type  owner perms  group perms  other perms
# First char: - regular file  d directory  b block device  c char device  l link
```

Use `file` to check the content type of a file:

```shell
file hequan        # hequan: ASCII text   text file
file /bin/cat      # /bin/cat: ELF 64-bit LSB executable ...   binary file
```

Directory attributes and type suffixes:

```shell
ls -ld /etc
ls -F              # / for dirs, * for executables, @ for links (similar to -p)
ls -F /etc/ | grep "/$"   # filter out directories
```

## 3. Device Files and Sockets

View block devices:

```shell
ll /dev/sda
```

Create a character device manually (major 5, minor 1):

```shell
mknod hequanx c 5 1
```

A `.sock` file is a socket file used for inter-process communication (e.g. MySQL's `mysql.sock`).

## 4. Symbolic Links

```shell
ln -s xx xxx       # create a soft link xxx pointing to xx
```

## 5. Common File Extensions

`.tar`, `.tar.gz`, `.tgz` are archive/compression formats;
`.sh`, `.pl`, `.py`, `.html`, `.conf`, `.rpm` correspond to
shell scripts, perl scripts, python scripts, web pages, config files, and RPM packages.

> Note: Linux does not determine file types by extension; extensions are only a convention — use the `file` command for the actual type.

## 6. inode and block

View a file's inode and detailed info:

```shell
ls -lhi            # -i shows the inode number, -h human-readable sizes
stat xx            # show full file metadata
```

- **inode (index node)**: stores file metadata — size, owner, permissions, timestamps, and pointers to the actual data blocks; **it does not store the file name** (file names live in the directory's blocks).
- **block**: stores the file's actual content; every file takes at least 1 inode and 1 block.

View filesystem inode/block parameters:

```shell
df -ih                                   # check inode usage per partition
dumpe2fs /dev/sda1 | grep -i "Inode size"
# Inode size: 128
dumpe2fs /dev/sda1 | grep -i "Block size"
# Block size: 1024
dumpe2fs /dev/sda1 | grep -i "Block count"
# Block count: 512000
# Reserved block count: 25600
dumpe2fs /dev/sda1 | grep -i "Inode count"
# Inode count: 128016
```

You can specify the block size and inode size when formatting:

```shell
mkfs.ext4 -b 4096 -I 1024 /dev/sda
umount /mnt
```

## 7. Classic Question: How Many Small Files Fit on a 100M Partition?

Assume a block size of 4K:

- Writing 1K small files: each file takes 1 inode and 1 block (even under 4K takes a whole block); how many you can write depends on **which runs out first, inodes or blocks** — usually inodes fill up first.
- Writing 1M files: each file takes 256 blocks, so roughly 100 files fit; the bottleneck is blocks (space).

Normally a partition has more blocks than inodes; but in scenarios with huge numbers of small files (masses of sessions, log fragments, etc.) inodes may run out first.

## 8. Experiment: Inode Exhaustion Makes the Disk "Full"

```shell
for n in `seq 1000000`; do touch $n; done
# Fails with No space left on device -- inodes are actually used up
# df -h still shows free space, but df -ih shows IUse% = 100%
```

Troubleshooting: when a disk reports full, check `df -h` (blocks) first, then `df -ih` (inodes). If inodes are exhausted, find and clean up the many small files (commonly under `/var/spool/clientmqueue`, session directories, and temp file directories).
