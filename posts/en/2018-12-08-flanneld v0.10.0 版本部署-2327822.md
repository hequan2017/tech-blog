> **About this post**
>
> Following the etcd cluster deployment, this post sets up the flanneld v0.10.0
> overlay network: first write the Pod subnet configuration
> `/coreos.com/network/config` (172.17.0.0/16, vxlan backend) into etcd, then
> install the flanneld binary on node01 and node02, write the FLANNEL_OPTIONS
> configuration and `flanneld.service`, and modify `docker.service` to reference
> the `/run/flannel/subnet.env` generated by `mk-docker-opts.sh`, so that docker0
> and flannel.1 are on the same subnet; finally, verify container network
> connectivity by accessing the other node's docker0 IP across nodes.

> **Technical notes**
>
> CentOS 7 reached end of maintenance (EOL) on June 30, 2024; migrating to
> Rocky Linux 9 / AlmaLinux 9 or the domestic openEuler is recommended.
> flannel v0.10.0 (2018) is severely outdated; `etcdctl set`, used to write
> into etcd, is an API v2 command — with etcd 3.4+ defaulting to API v3, you
> need ETCDCTL_API=2 or should switch to `etcdctl put`.
> The flannel download URL in the original post was missing the github.com
> prefix and has been completed; in flanneld.service and docker.service,
> directives that lost line breaks or the script name have been fixed
> (including restoring mk-docker-opts.sh); the log command
> `journalctl -u flannel` has been corrected to flanneld.

## 1. Write the Network Configuration into etcd

You can first refer to the previous post, "Etcd v3.3.10 Deployment (3-node Cluster)", to deploy etcd: http://blog.51cto.com/hequan/2327820

```shell
cd /data/ssl/etcd/

/opt/etcd/bin/etcdctl \
--ca-file=ca.pem --cert-file=server.pem --key-file=server-key.pem \
--endpoints="https://192.168.100.100:2379,https://192.168.100.101:2379,https://192.168.100.102:2379" \
set /coreos.com/network/config '{ "Network": "172.17.0.0/16", "Backend": {"Type": "vxlan"}}'
```

## 2. Deployment (perform on both node01 and node02)

```shell
cd /data/src/

wget https://github.com/coreos/flannel/releases/download/v0.10.0/flannel-v0.10.0-linux-amd64.tar.gz

mkdir /opt/kubernetes/bin -p
tar xf flannel-v0.10.0-linux-amd64.tar.gz
mv flanneld /opt/kubernetes/bin/

mkdir /opt/kubernetes/cfg
```

Configuration file /opt/kubernetes/cfg/flanneld:

```ini
FLANNEL_OPTIONS="--etcd-endpoints=https://192.168.100.100:2379,https://192.168.100.101:2379,https://192.168.100.102:2379 -etcd-cafile=/opt/etcd/ssl/ca.pem -etcd-certfile=/opt/etcd/ssl/server.pem -etcd-keyfile=/opt/etcd/ssl/server-key.pem"
```

Service unit /usr/lib/systemd/system/flanneld.service (the ExecStartPost line in the original post lost the script name; mk-docker-opts.sh has been restored):

```ini
[Unit]
Description=Flanneld overlay address etcd agent
After=network-online.target network.target
Before=docker.service

[Service]
Type=notify
EnvironmentFile=/opt/kubernetes/cfg/flanneld
ExecStart=/opt/kubernetes/bin/flanneld --ip-masq $FLANNEL_OPTIONS
ExecStartPost=/opt/kubernetes/bin/mk-docker-opts.sh -k DOCKER_NETWORK_OPTIONS -d /run/flannel/subnet.env
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Modify /usr/lib/systemd/system/docker.service so that Docker references the network parameters generated by flannel (in the original post several directives had lost line breaks and were concatenated; they have been split and restored):

```ini
[Unit]
Description=Docker Application Container Engine
Documentation=https://docs.docker.com
After=network-online.target firewalld.service
Wants=network-online.target

[Service]
Type=notify
EnvironmentFile=/run/flannel/subnet.env
ExecStart=/usr/bin/dockerd $DOCKER_NETWORK_OPTIONS
ExecReload=/bin/kill -s HUP $MAINPID
LimitNOFILE=infinity
LimitNPROC=infinity
LimitCORE=infinity
TimeoutStartSec=0
Delegate=yes
KillMode=process
Restart=on-failure
StartLimitBurst=3
StartLimitInterval=60s

[Install]
WantedBy=multi-user.target
```

Start the services:

```shell
systemctl daemon-reload
systemctl start flanneld
systemctl enable flanneld
systemctl restart docker
```

## 3. Verification

```shell
ps -ef | grep docker
ip addr
```

- Make sure docker0 and flannel.1 are on the same subnet;
- Test connectivity between nodes: from the current node, access the docker0 IP of another node; if it is reachable, Flannel has been deployed successfully;
- If not, check the logs: `journalctl -u flanneld`.
