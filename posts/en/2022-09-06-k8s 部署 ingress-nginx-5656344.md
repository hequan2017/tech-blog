> **About this post**
>
> This post documents the deployment of the ingress-nginx controller v1.3.1 on a Kubernetes v1.25 cluster: downloading the official cloud deployment manifest, pre-pulling images with crictl and switching them to the Alibaba Cloud image registry, changing the Deployment into a DaemonSet + hostNetwork setup, and finally scheduling it onto specific nodes via nodeSelector.
>
> **Technical notes**
>
> ingress-nginx v1.3.1 only supports Kubernetes 1.20-1.25; the latest releases already support v1.30+, and the official recommendation is to deploy with a Helm Chart. The image replacement address `/google_containers` is no longer valid; use `registry.aliyuncs.com/google_containers` instead, or import the images offline.

---

```shell
wget https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.3.1/deploy/static/provider/cloud/deploy.yaml

kubectl label nodes k8s-node1 hasIngress=true

grep -rn image deploy.yaml

crictl pull  /google_containers/nginx-ingress-controller:v1.3.1
crictl pull  /google_containers/kube-webhook-certgen:v1.3.0
sed -i s#registry.k8s.io/ingress-nginx/controller:v1.3.1@sha256:54f7fe2c6c5a9db9a0ebf1131797109bb7a4d91f56b9b362bde2abd237dd1974#/google_containers/nginx-ingress-controller:v1.3.1#g deploy.yaml
sed -i s#registry.k8s.io/ingress-nginx/kube-webhook-certgen:v1.3.0@sha256:549e71a6ca248c5abd51cdb73dbc3083df62cf92ed5e6147c780e30f7e007a47#/google_containers/kube-webhook-certgen:v1.3.0#g deploy.yaml

vim  deploy.yaml
391 kind: DaemonSet
415     spec:
416       hostNetwork: true
            kubernetes.io/os: linux
496         hasIngress: "true"

kubectl apply -f deploy.yaml
```
