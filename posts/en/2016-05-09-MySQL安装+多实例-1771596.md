> **About this post**
>
> This post documents several ways to install MySQL 5.5.32 on Linux (yum,
> compiling from source, and the pre-built binary distribution) together with
> the complete process of a cmake-based build: first install the cmake and
> ncurses-devel dependencies and create the mysql user and group, then use
> cmake to configure common options such as the installation directory,
> character sets, and storage engines before running make. Initialization
> covers copying my-small.cnf, configuring PATH, generating the base databases
> with mysql_install_db, setting up the startup script, and setting the root
> password. The second half explains the concept and use cases of running
> multiple MySQL instances and the multiple-configuration-file deployment
> scheme, covering the directory layout for the /data/3306 and 3307 instances,
> initialization, start/stop, password setup, hardening of the startup scripts,
> and the complete steps for adding a new 3308 instance.

> **Technical notes**
>
> Both MySQL 5.5 and 5.6 are no longer maintained; upgrading to MySQL 8.0+ or
> MariaDB 10.6+ is recommended. `mysql_install_db` has been replaced by
> `mysqld --initialize` since MySQL 5.7; multiple instances can nowadays also
> be managed with a systemd template unit or the official `mysqld_multi`.
> Some build options used in this post, such as `-DWITH_FAST_MUTEXES`, have
> been removed in newer versions.

## 1. Overview of MySQL Installation Methods

- yum installation: `yum install mysql-server`
- Compiling from source: 5.0-5.1 (configure-based, from the source tarball)
- Pre-built binary installation: unpack and use
- **cmake-based compilation: 5.5-5.6** (used in this post)

## 2. Installing Build Dependencies

### 2.1 cmake

```shell
cd /home/oldboy/tools/
tar xf cmake-2.8.8.tar.gz
cd cmake-2.8.8
./configure
# CMake has bootstrapped.  Now run gmake.
gmake
gmake install
cd ../
```

### 2.2 Dependency packages

```shell
yum install ncurses-devel -y
```

## 3. Compiling and Installing MySQL 5.5.32

### 3.1 Create the user and group

```shell
groupadd mysql
useradd mysql -s /sbin/nologin -M -g mysql
```

### 3.2 Extract and compile MySQL

```shell
tar zxf mysql-5.5.32.tar.gz
cd mysql-5.5.32

cmake . -DCMAKE_INSTALL_PREFIX=/application/mysql-5.5.32 \
-DMYSQL_DATADIR=/application/mysql-5.5.32/data \
-DMYSQL_UNIX_ADDR=/application/mysql-5.5.32/tmp/mysql.sock \
-DDEFAULT_CHARSET=utf8 \
-DDEFAULT_COLLATION=utf8_general_ci \
-DEXTRA_CHARSETS=gbk,gb2312,utf8,ascii \
-DENABLED_LOCAL_INFILE=ON \
-DWITH_INNOBASE_STORAGE_ENGINE=1 \
-DWITH_FEDERATED_STORAGE_ENGINE=1 \
-DWITH_BLACKHOLE_STORAGE_ENGINE=1 \
-DWITHOUT_EXAMPLE_STORAGE_ENGINE=1 \
-DWITHOUT_PARTITION_STORAGE_ENGINE=1 \
-DWITH_FAST_MUTEXES=1 \
-DWITH_ZLIB=bundled \
-DENABLED_LOCAL_INFILE=1 \
-DWITH_READLINE=1 \
-DWITH_EMBEDDED_SERVER=1 \
-DWITH_DEBUG=0
# -- Build files have been written to: /home/oldboy/tools/mysql-5.5.32
```

Note: there are many options you can configure at compile time; see the
appendix at the end or the official documentation for details.

```shell
make
# [100%] Built target my_safe_process
make install
ln -s /application/mysql-5.5.32/ /application/mysql
```

If none of the steps above produced any errors, the cmake-based installation
of MySQL 5.5.32 is complete.

## 4. Initialize the Database and Start MySQL

```shell
cp support-files/my-small.cnf /etc/my.cnf
echo 'export PATH=/application/mysql/bin:$PATH' >> /etc/profile
. /etc/profile

chown -R mysql.mysql /application/mysql/data/
chmod -R 1777 /tmp/

cd /application/mysql/scripts/
./mysql_install_db --basedir=/application/mysql/ --datadir=/application/mysql/data/ --user=mysql

cp support-files/mysql.server /etc/init.d/mysqld
/etc/init.d/mysqld start
netstat -lntup | grep 3306
tcp        0      0 0.0.0.0:3306              0.0.0.0:*                   LISTEN      24072/mysqld

/application/mysql/bin/mysqladmin -u root password 'new-password'
```

## 5. Multiple MySQL Instances

### 5.1 Concept and use cases

Multiple instances mean running several MySQL processes on one server, each
listening on a different service port (e.g., 3306/3307): they share one
installation, and may share the same configuration file, startup program, and
data files, yet remain logically independent. The benefit is making use of
spare resources and saving on servers; the drawback is that the instances
compete with each other for resources.

Use cases: resource-constrained companies, workloads without particularly
high concurrency, and portal websites.

There are two deployment schemes: the **multiple-configuration-file scheme**
(used in this post) and the single-configuration-file scheme (`mysql_multi`).

Instance directory layout:

```text
/data
├── 3306    # instance directory
│   └── data    # data files
└── 3307    # instance directory
    └── data    # data files
```

After uploading the configuration files:

```text
/data
├── 3306
│   ├── data
│   └── my.cnf
└── 3307
    ├── data
    └── my.cnf
```

First stop the existing single instance:

```shell
pkill mysqld
```

### 5.2 How multi-instance start/stop actually works

What the multi-instance startup scripts really do to start the MySQL service:

```shell
mysqld_safe --defaults-file=/data/3306/my.cnf 2>&1 > /dev/null &
mysqld_safe --defaults-file=/data/3307/my.cnf 2>&1 > /dev/null &
```

To stop, shut down gracefully:

```shell
mysqladmin -u root -p123456 -S /data/3306/mysql.sock shutdown
mysqladmin -u root -p123456 -S /data/3307/mysql.sock shutdown
```

The final instance directory layout:

```text
/data
├── 3306
│   ├── data
│   ├── my.cnf
│   └── mysql    # startup script
└── 3307
    ├── data
    ├── my.cnf
    └── mysql
```

Set ownership and make the startup scripts executable:

```shell
chown -R mysql.mysql /data
find /data/ -type f -name "mysql" | xargs chmod +x
```

### 5.3 Initialize the multi-instance database files

Create the base database files:

```shell
cd /application/mysql/scripts/
./mysql_install_db --basedir=/application/mysql --datadir=/data/3306/data --user=mysql
./mysql_install_db --basedir=/application/mysql --datadir=/data/3307/data --user=mysql
```

### 5.4 Starting and checking

```shell
/data/3306/mysql start
/data/3307/mysql start

netstat -lntup | grep 330
tail -f /data/3306/mysql_oldboy3306.err
```

### 5.5 Account configuration in the startup script

```shell
cd /data/3307
vim mysql          # startup file
mysql_user="root"
mysql_pwd="123456"
```

To enter mysql:

```shell
mysql -S /data/3306/mysql.sock
```

To switch instances from inside mysql:

```sql
mysql> system mysql -S /data/3306/mysql.sock
```

### 5.6 Set the root passwords of the instances

```shell
mysqladmin -u root -S /data/3306/mysql.sock password '123123'
mysqladmin -u root -S /data/3306/mysql.sock -p'123123' password '123456'
```

### 5.7 Hardening the startup scripts

```shell
find /data/ -type f -name "mysql" -exec chmod 700 {} \;
find /data/ -type f -name "mysql" -exec chown root.root {} \;

pkill mysqld
/data/3306/mysql start
/data/3307/mysql start
```

### 5.9 Adding a new 3308 instance

```shell
mkdir /data/3308/data/ -p
cp /data/3306/my.cnf /data/3308/
cp /data/3306/mysql /data/3308/
chown -R mysql.mysql /data/3308/
cd /data/3308/

vim my.cnf
# server-id = 4
# :%s/3306/3308/g

vim mysql
```

Initialize the data files:

```shell
cd /application/mysql/scripts/
[root@localhost scripts]# ./mysql_install_db --user=mysql --basedir=/application/mysql --datadir=/data/3308/data/
```
