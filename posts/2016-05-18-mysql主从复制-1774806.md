> sql_slave_skip_counter 跳错与级联同步(log-slave-updates)配置。

> **技术备注**
>
> MySQL 5.6+/8.0 推荐 GTID 复制(`CHANGE MASTER TO ... MASTER_AUTO_POSITION=1`),
> 传统基于 binlog 位点的方式仍兼容;8.0.23+ 语法更名为 CHANGE REPLICATION

## 1. 为什么要主从复制

主从复制有利于:

- 数据库架构的健壮性
- 提升访问速度
- 易于维护管理
- 主从互为备份

常见结构:M(主)---- S(从),一主多从,异步同步。

![主从复制原理动图:master 写 binlog,slave 两线程接力同步](assets/1774806/01_wKiom1c8K-Cij7jyAABUrjWR9Ok242.gif)

## 2. 复制过程原理

该过程的第一部分就是 master 记录二进制日志。在每个事务更新数据完成之前,master 在二进制日志记录这些改变。MySQL 将事务串行的写入二进制日志,即使事务中的语句都是交叉执行的。在事件写入二进制日志完成后,master 通知存储引擎提交事务。

下一步就是 slave 将 master 的 binary log 拷贝到它自己的中继日志。首先,slave 开始一个工作线程——I/O 线程。I/O 线程在 master 上打开一个普通的连接,然后开始 binlog dump process。Binlog dump process 从 master 的二进制日志中读取事件,如果已经跟上 master,它会睡眠并等待 master 产生新的事件。I/O 线程将这些事件写入中继日志。

SQL slave thread(SQL 从线程)处理该过程的最后一步。SQL 线程从中继日志读取事件,并重放其中的事件而更新 slave 的数据,使其与 master 中的数据一致。只要该线程与 I/O 线程保持一致,中继日志通常会位于 OS 的缓存中,所以中继日志的开销很小。

此外,在 master 中也有一个工作线程:和其它 MySQL 的连接一样,slave 在 master 中打开一个连接也会使得 master 开始一个线程。复制过程有一个很重要的限制——复制在 slave 上是串行化的,也就是说 master 上的并行更新操作不能在 slave 上并行操作。

## 3. 主库准备(3306 实例)

```shell
mysql -uroot -p123456 -S /data/3306/mysql.sock
```

```sql
mysql> show variables like 'log_bin%';
```

```text
+---------------------------------+-------+
| Variable_name                   | Value |
+---------------------------------+-------+
| log_bin                         | ON    |
+---------------------------------+-------+
```

主从两个实例的 server-id 不能一样。

创建复制账号:

```sql
mysql> grant replication slave on *.* to 'rep'@'192.168.10.%' identified by '123456';
mysql> flush privileges;
```

加读锁,防止备份期间数据变化:

```sql
mysql> flush table with read lock;    # 读锁
mysql> show master status/logs;
```

```text
+------------------+-----------+
| Log_name         | File_size |
+------------------+-----------+
| mysql-bin.000005 |       338 |
+------------------+-----------+
```

全备主库(带日志位点):

```shell
mysqldump -uroot -p123456 -S /data/3306/mysql.sock -A -B --events --master-data=2 > /opt/rep.sql
```

```sql
mysql> unlock tables;    # 解锁
```

## 4. 从库配置与启动(3307 实例)

导入全备数据:

```shell
mysql -uroot -p123456 -S /data/3307/mysql.sock < /opt/rep.sql
mysql -uroot -p123456 -S /data/3307/mysql.sock
```

```sql
CHANGE MASTER TO
MASTER_HOST='192.168.10.10',
MASTER_PORT=3306,
MASTER_USER='rep',
MASTER_PASSWORD='123456',
MASTER_LOG_FILE='mysql-bin.000005',
MASTER_LOG_POS=417;
```

```text
/data/3307/data/master.info    # 生成的文件
```

```sql
mysql> start slave;
mysql> show slave status\G
```

关键状态:

```text
Slave_IO_Running: Yes
Slave_SQL_Running: Yes
```

从库生成的中继日志与同步位点信息:

```text
relay-bin.index
/data/3307/relay-bin.000001
/data/3307/relay-bin.000002
# 中继日志
427
mysql-bin.000005
591
```

## 5. 查看复制状态

```sql
mysql> show processlist;    # 查看状态
```

```text
| Id | User        | Host               | db   | Command     | Time | State                                                                       | Info |
|  1 | rep         | 192.168.10.10:54094| NULL | Binlog Dump |  147 | Master has sent all binlog to slave; waiting for binlog to be updated        | NULL |
|  1 | system user |                    | NULL | Connect     |  144 | Slave has read all relay log; waiting for the slave I/O thread to update it  | NULL |
|  2 | system user |                    | NULL | Connect     |  144 | Waiting for master to send event                                            | NULL |
```

关键状态含义:

- Master has sent all binlog to slave; waiting for binlog to be updated:主库已把 binlog 全部发给从库,等待 binlog 更新
- Slave has read all relay log; waiting for the slave I/O thread to update it:SQL 线程已读完中继日志,等待 I/O 线程更新
- Waiting for master to send event:I/O 线程等待主库产生新事件

```sql
mysql> show slave status\G
```

```text
Slave_IO_Running: Yes
Slave_SQL_Running: Yes
Seconds_Behind_Master: 0
```

## 6. 读写分离授权方案

数据复制是单向的。mysql 库不同步,主从库分别授权。

缺陷:从库切换主库的时候,有连接用户权限的问题。保留一个从库专门准备接替主库。

```ini
# vim /etc/my.cnf
[mysqld]
binlog-ignore-db = mysql
binlog-ignore-db = performance_schema
binlog-ignore-db = information_schema
```

```sql
mysql> create user hequan@localhost identified by '123456';   -- 先不给权限
```

复制过滤参数:

- replicate-do-table:复制的表
- replicate-ignore-table:忽略复制的表
- replicate_wild_ignore_table=mysql.%:可以加通配符,推荐用这种方法

```ini
slave-skip-errors = 1032,1062    # 排除 1032、1062 的报错
lower_case_table_names = 1       # 让 MySQL 不区分表名大小写,慎用,会影响原来的表名
```

## 7. 跳过 DNS 解析与从库只读

--skip-name-resolve 选项启动 mysqld 可禁用 DNS 主机名查找:mysql 接收到连接请求后,获得的是客户端的 ip,为了更好的匹配 mysql.user 里的权限记录(某些是用 hostname 定义的)。如果 mysql 服务器设置了 dns 服务器,并且客户端 ip 在 dns 上并没有相应的 hostname,那么这个过程很慢,导致连接等待。

```ini
skip-name-resolve
```

从库只读:

```ini
[mysqld]
read-only    # 只读,root 不受限
```

授权时不能有 super 或者 all privileges 权限,否则 read-only 对该用户无效。普通用户在只读从库建库会报错:

```sql
mysql> create database xxxxx;
ERROR 1290 (HY000): The MySQL server is running with the --read-only option so it cannot execute this statement
```

## 8. 主从不同步处理

Slave_SQL_Running 为 NO 的情况,可以用下面的命令跳过报错:在 slave 处于 stop 状态下,执行 `set global sql_slave_skip_counter=N` 以跳过命令,N=1。

以一个 insert 语句为例(引擎 InnoDB、binlog_format=statement),在 binlog 中实际上有三个 event,分别为 begin/insert/commit,命令类型都是 Query_log_event:

1. 若 N=1 且当前 event 为 BEGIN,则 N 不变,跳过当前 event 继续;
2. 若 N=1 且当前 event 处于一个事务之内(BEGIN 之后、COMMIT 之前),则 N 不变,跳过当前 event 继续。

## 9. 级联同步

slave 开启从库记录 binlog,可做级联同步,同时当做数据库备份:

```ini
log-bin = /data/3307/mysql-bin
log-slave-updates
expire_logs_days = 7    # 保留 7 天
```
