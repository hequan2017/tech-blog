> **内容介绍**
>
> 本文讲解 Linux"一切皆文件"的设计理念与常见文件类型：普通文件、目录、块设备、
> 字符设备、符号链接、套接字等，以及如何用 `ls -l` / `file` / `ls -F` 识别它们。
> 后半部分深入 inode 与 block 的概念——inode 存元数据（大小、属主、指向实体的指针，
> 不含文件名）、block 存实际内容，并通过 `dumpe2fs` / `df -ih` 查看 inode 与 block 的
> 数量与大小，最后用一个"小文件写满磁盘"的实验说明 inode 耗尽也会导致
> `No space left on device`。

> **技术备注**
>
> inode/block 原理至今通用，仅工具细节有变化：ext4 默认 inode 大小已从 128 字节
> 增大到 256 字节；`dumpe2fs` 仅适用于 ext 系文件系统，XFS 请改用 `xfs_info` 和
> `xfs_db`。另外大量小文件场景建议直接选 XFS 或用更大 inode 密度格式化。

## 1. 一切皆文件

Linux 中"一切皆文件"，常见文件类型有：

- 普通文件（`-`）
- 目录（`d`）
- 块设备文件（`b`，如磁盘）
- 字符设备文件（`c`，如终端）
- 符号链接（`l`）
- 套接字文件（`s`，`.sock`）

## 2. 识别文件类型

`ls -l` 输出第一列即类型 + 权限：

```shell
ls -l
# -rw-r--r--   文件类型 属主权限 组权限 其他人权限
# 首字符: - 普通文件  d 目录  b 块设备  c 字符设备  l 链接文件
```

用 `file` 查看文件内容类型：

```shell
file hequan        # hequan: ASCII text   文本文件
file /bin/cat      # /bin/cat: ELF 64-bit LSB executable ...   二进制文件
```

目录本身属性与类型后缀标注：

```shell
ls -ld /etc
ls -F              # 目录加 / 、可执行文件加 * 、链接加 @(同 -p 类似)
ls -F /etc/ | grep "/$"   # 过滤出目录
```

## 3. 设备文件与套接字

查看块设备：

```shell
ll /dev/sda
```

手动创建一个字符设备（主设备号 5，次设备号 1）：

```shell
mknod hequanx c 5 1
```

`.sock` 是套接口文件，用于进程间通信（如 MySQL 的 `mysql.sock`）。

## 4. 符号链接

```shell
ln -s xx xxx       # 创建软链接 xxx 指向 xx
```

## 5. 常见文件扩展名

`.tar`、`.tar.gz`、`.tgz` 是打包/压缩格式；
`.sh`、`.pl`、`.py`、`.html`、`.conf`、`.rpm` 分别对应
shell 脚本、perl 脚本、python 脚本、网页、配置文件、RPM 安装包。

> 注意：Linux 不依赖扩展名判断文件类型，扩展名只是约定，实际类型以 `file` 命令为准。

## 6. inode 与 block

查看文件的 inode 与详细信息：

```shell
ls -lhi            # -i 显示 inode 编号, -h 人性化显示大小
stat xx            # 查看文件完整元数据
```

- **inode（索引节点）**：存放文件元数据——大小、属主、权限、时间戳，
  以及指向实际数据块的指针；**不保存文件名**（文件名存在目录的 block 里）。
- **block（块）**：存放文件的实际内容，一个文件至少占用 1 个 inode 和 1 个 block。

查看文件系统的 inode/block 参数：

```shell
df -ih                                   # 查看各分区 inode 使用情况
dumpe2fs /dev/sda1 | grep -i "Inode size"
# Inode size: 128
dumpe2fs /dev/sda1 | grep -i "Block size"
# Block size: 1024
dumpe2fs /dev/sda1 | grep -i "Block count"
# Block count: 512000
# Reserved block count: 25600
dumpe2fs /dev/sda1 | grep -i "Inode count"
# Inode count: 128016
```

格式化时可指定 block 大小与 inode 大小：

```shell
mkfs.ext4 -b 4096 -I 1024 /dev/sda
umount /mnt
```

## 7. 经典问题：100M 分区能写多少个小文件？

假设 block 大小为 4K：

- 写入 1K 的小文件：每个文件都要占 1 个 inode 和 1 个 block（即使不足 4K 也占整块），
  能写的数量取决于 **inode 数量与 block 数量谁先耗尽**，往往 inode 先满。
- 写入 1M 的文件：每个文件占 256 个 block，大约能写 100 个，此时瓶颈是 block（空间）。

一般情况下分区时 block 数量会大于 inode 数量；但小文件极多的场景
（如大量 session、日志碎文件）可能 inode 先用完。

## 8. 实验：inode 耗尽导致磁盘"写满"

```shell
for n in `seq 1000000`; do touch $n; done
# 报 No space left on device —— 实际是 inode 被占满了
# 此时 df -h 显示空间还有剩余, 但 df -ih 显示 IUse% = 100%
```

排查思路：磁盘报满时先看 `df -h`（block），再看 `df -ih`（inode），
inode 满需要找到并清理大量小文件（常见于 `/var/spool/clientmqueue`、
session 目录、临时文件目录）。
