> **内容介绍**
>
> 在 GORM 官方 Issues 发现有人反馈 SQLite 驱动依赖 CGO 的问题，作者顺藤摸瓜
> 找到了纯 Go 实现、不依赖 CGO 的 `glebarez/sqlite`，用它替换官方默认驱动，
> 即可编译出不依赖动态链接库的静态二进制文件；文末记录了这一替换的代价。

> **技术备注**
>
> `gorm.io/driver/sqlite` 底层是 `mattn/go-sqlite3`，基于 CGO，交叉编译时需要
> 目标平台的 C 工具链；`glebarez/sqlite` 基于 `modernc.org/sqlite`（SQLite 的
> 纯 Go 移植），无 CGO 依赖，代价是性能略低、二进制体积增大，与文中"代价"一致。

---

在 GORM 官方的 Issues 发现也有人反馈此类问题，于是顺藤摸瓜，找到了 `github.com/glebarez/sqlite` 这个库，该库使用纯 Go 实现，不依赖 CGO，地址是：[https://github.com/glebarez/sqlite](https://github.com/glebarez/sqlite)

于是将官方的驱动：

```go
import (
    "gorm.io/driver/sqlite"
    "gorm.io/gorm"
)
```

更换为：

```go
import (
    "github.com/glebarez/sqlite"
    "gorm.io/gorm"
)
```

这样就可以在不依赖 CGO 的情况下编译出静态二进制文件，从而解决跨平台依赖动态链接库的问题。

#### 代价

- `glebarez/sqlite` 性能不及官方驱动，但牺牲少部分性能来换取方便，个人觉得还是值得的，如果没有跨平台需求，使用官方默认驱动即可
- 静态编译打包后的文件体积明显增加
