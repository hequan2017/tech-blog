> **内容介绍**
>
> 让 GitLab 11.2.3 通过 LDAP 对接 FreeIPA 域账户登录：在 `gitlab.rb` 里配置 `gitlab_rails['ldap_servers']`，指定 host、bind_dn、base、属性映射后 reconfigure 生效。配套前面 FreeIPA 部署与 GitLab 安装两篇文章。

> **技术备注**
>
> GitLab 11.2.3 属 2018 年版本，现已严重过时且存在多个已知安全漏洞，建议升级到当前受支持版本；新版 GitLab 的 LDAP 配置格式与此基本一致，但生产环境应使用 `start_tls`/`simple_tls` 而非 `plain` 加密。配置键 `gitlab_rails` 请勿按原文写成 `gitlab _rails`（带空格，原文笔误，正文已修正）；同理命令应为 `gitlab-ctl`。

---

FreeIPA 和 Gitlab 的搭建，可以参考我之前的博客。

FreeIPA域名   （内部测试，修改一下gitlab的host文件  ip  FreeIPA域名 ）

```shell
vim /etc/gitlab/gitlab.rb
```

```ruby
gitlab_rails['ldap_enabled'] = true
gitlab_rails['ldap_servers'] = YAML.load <<-'EOS'
   main: # 'main' is the GitLab 'provider ID' of this LDAP server
     label: 'LDAP'
     host: '192.168.100.23'
     port: 389
     uid: 'uid'
     bind_dn: 'uid=admin,cn=users,cn=accounts,dc=zhuxu,dc=co'
     password: '123456'
     encryption: 'plain' # "start_tls" or "simple_tls" or "plain"
     verify_certificates: true
     active_directory: true
     allow_username_or_email_login: true
     lowercase_usernames: false
     block_auto_created_users: false
     base: 'dc=zhuxu,dc=co'
     user_filter: ''
     attributes:
       username: ['uid', 'userid', 'sAMAccountName']
       email:    ['mail', 'email', 'userPrincipalName']
       name:       'cn'
       first_name: 'givenName'
       last_name:  'sn'
     admin_group: 'cn=admins'
     sync_ssh_keys: true
EOS
```

```shell
gitlab-ctl reconfigure
gitlab-ctl restart
```
