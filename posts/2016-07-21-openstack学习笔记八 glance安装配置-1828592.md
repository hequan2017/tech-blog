> **内容介绍**
>
> 本文是 Glance 镜像服务的安装配置笔记：先介绍镜像的四种状态（active/saving/killed/queued），然后在 h4 节点上完成 glance 安装全流程——yum 安装、openstack-db 初始化数据库、向 keystone 注册用户/服务/endpoint、从模板拷贝并修改 glance-api.conf（数据库连接、RabbitMQ、keystone 认证），启动 api/registry/scrubber 三个服务。随后演示两种镜像后端切换：改为 Swift 对象存储、改为 Ceph RBD（含 ceph-deploy 在 h5/h6 上部署 MON/OSD/MDS、创建 glance 存储池、glance 节点配为 ceph 客户端）。最后讲 KVM 手工制作 qcow2 镜像的要点（装 cloud-init、删 MAC、grub 加串口参数、virt-sysprep 封装、qemu-img 压缩）。

> **技术备注**
>
> 文中 `keystone user-create`、`glance image-list` 等独立 CLI 早已废弃，需改用 `openstack user create`、`openstack image list` 等统一命令；glance-registry 服务在 Rocky 版弃用、Stein 版移除；`[keystone_authtoken]` 里的 auth_host/auth_port/admin_user 写法现为 auth_url/username/password。Ceph hammer 版本与 ceph-deploy 工具均已停止维护，现在用 cephadm 部署。镜像制作的思路（cloud-init + virt-sysprep + qemu-img）至今通用，也可直接用发行版官方 cloud image。

## 1. 镜像与状态

镜像就是安装过系统的虚拟硬盘，由 Glance 完成管理。

镜像的状态：

- **active**：镜像已经上传完成，并且是可用的
- **saving**：正在被上传，还没有完成
- **killed**：上传出错
- **queued**：并没有真的上传完成，但是被标记有这个镜像

## 2. 安装 Glance 并向 Keystone 注册

安装步骤：向 keystone 注册 glance 所需账户 → 创建 glance 服务 → 指定 endpoint → 安装软件：

```shell
[root@h4 ~]# yum -y install openstack-glance.noarch
[root@h4 ~]# openstack-db --init --service glance --password 123456 --rootpw 123456
[root@h4 ~(keystone_admin)]# keystone user-create --name glance --pass 123456
[root@h4 ~(keystone_admin)]# keystone user-role-add --user glance --tenant services --role admin
```

## 5. 修改镜像存储后端

### 5.1 Swift 做后端存储

```ini
#filesystem_store_datadir = /var/lib/glance/images/   # 先禁用本地存储
[glance_store]
default_store = swift              # 默认为 file，改为 swift
stores = file, http                # 默认不用动
swift_store_auth_version = 2       # 默认版本为 2
stores = glance.store.swift.Store,glance.store.filesystem.Store   # 此项一定要加上，不然无法上传
swift_store_auth_address = http://192.168.1.204:5000/v2.0/   # controller 的 keystone 认证
swift_store_user = service:swift   # 使用 swift 用户
swift_store_key = hequan           # 密码
swift_store_container = glance     # 将要被创建的容器
swift_store_create_container_on_put = True    # 上传时自动创建容器
swift_store_large_object_size = 5120         # 最大 5G 限制，但与 glance 结合后限制无效
swift_store_large_object_chunk_size = 200    # 分片大小 200MB
swift_enable_snet = False
```

```shell
[root@h4 glance(keystone_admin)]# systemctl restart openstack-glance-api.service openstack-glance-registry.service openstack-glance-scrubber.service
```

### 5.2 Ceph 共享存储

![手绘 Ceph 架构图：客户端经元数据服务连 OSD，含 MON 监视](assets/1828592/01_wKioL1eQyIXiJOY3AAExaGE5bbI635.png)

安装 epel 仓库并添加 ceph yum 仓库：

```shell
rpm -vih http://mirrors.sohu.com/fedora-epel/7/x86_64/e/epel-release-7-2.noarch.rpm
```

```ini
# vim /etc/yum.repos.d/ceph.repo
[ceph]
name=Ceph noarch packages
baseurl=http://mirrors.163.com/ceph/rpm-hammer/el7/x86_64/
enabled=1
gpgcheck=1
type=rpm-md
gpgkey=http://mirrors.163.com/ceph/keys/release.asc
```

安装 ceph-deploy 和 ceph（ceph 所有节点都安装，ceph-deploy 只需 admin 节点安装）：

```shell
yum -y update && yum -y install ceph ceph-deploy
```

**1）生成相关的 MON 信息**，监控服务器为 h5：

```shell
[root@h5 xx]# ceph-deploy new h5
[root@h5 xx]# ls
ceph.conf  ceph-deploy-ceph.log  ceph.mon.keyring
```

**2）根据自己的情况修改配置文件 ceph.conf：**

```ini
osd_pool_default_size = 2      # 几个副本，默认是 3
osd_pool_default_min_size = 1  # 最小值是 1
```

**3）生成 key**，当客户端要连接到 ceph 服务器，需要用户名和密码：

```shell
[root@h5 xx]# ceph-deploy mon create-initial
[root@h5 myceph]# ls
ceph.bootstrap-mds.keyring  ceph.client.admin.keyring  ceph.mon.keyring
ceph.bootstrap-osd.keyring  ceph.conf
ceph.bootstrap-rgw.keyring  ceph.log
```

**4）开始准备配置 OSD：**

```shell
mkdir /path1 /path2
[root@h5 xx]# ceph-deploy osd prepare h5:/path1 h6:/path2
[root@h5 xx]# ceph-deploy osd activate h5:/path1 h6:/path2    # 激活
[ceph_deploy.osd][DEBUG ] Host h5 is now ready for osd use.
```

**5）把 key 复制到各个节点上去：**

```shell
[root@h5 ceph]# ceph-deploy admin h5 h6
[root@h5 ceph]# ceph health    # 健康性检查
```

**6）创建存储池：**

```shell
[root@h5 ceph]# ceph-deploy mds create h5
[root@h5 ceph]# rados lspools
[root@h5 ceph]# rados mkpool glance
[root@h5 ceph]# rados rmpool glance glance --yes-i-really-really-mean-it   # 删除池
```

### 5.3 Glance 配置为 Ceph 客户端

在 glance 节点（h4）上安装 ceph 客户端并下发配置：

```shell
[root@h4 ceph(keystone_admin)]# ls
rbdmap
[root@h5 myceph]# ceph-deploy admin h4
[root@h4 ceph(keystone_admin)]# ls
ceph.client.admin.keyring  ceph.conf  rbdmap
```

修改 glance-api.conf：

```ini
[glance_store]
default_store = rbd
stores = rbd
rbd_store_pool = glance
rbd_store_user = admin
rbd_store_ceph_conf = /etc/ceph/ceph.conf
rbd_store_chunk_size = 8
```

```shell
systemctl restart openstack-glance-api.service openstack-glance-registry.service openstack-glance-scrubber.service
-rw------- 1 root root 63 7月 21 16:43 ceph.client.admin.keyring
setfacl -m u:glance:r-- ceph.client.admin.keyring    # 设置权限让 glance 用户能读 keyring
```

## 6. 制作镜像

```shell
yum -y groupinstall "Server with GUI"
yum install virt-manager python-virtinst qemu-kvm-tools qemu-kvm libvirt
```

在 KVM 中制作镜像的要点：

1. 创建存储卷 centos.qcow2，基本安装系统；
2. 配置网卡，删除 MAC 地址绑定（删除 ifcfg 里的 HWADDR 及 udev 规则）；
3. 安装基本组件 openssh-clients；
4. 安装 cloud-init（云初始化包）。

修改 grub 指定串口参数（方便 nova console-log 抓日志）：

```shell
[root@h4 ~]# vim /etc/default/grub
GRUB_CMDLINE_LINUX="net.ifnames=0 biosdevname=0 console=tty0 console=ttyS0,115200n8 rhgb quiet"
[root@h4 ~]# grub2-mkconfig -o /boot/grub2/grub.cfg
```

封装镜像（清理机器 ID、日志、SSH 主机密钥等个性化信息）：

```shell
[root@h5 ~]# yum whatprovides */virt-sysprep
[root@h5 ~]# yum -y install libguestfs-tools-c
[root@h4 ~]# virt-sysprep -d centos
[root@h4 ~]# cd /openstack-image/
[root@h4 openstack-image]# qemu-img info centos.qcow2
qemu-img convert -c -O qcow2 centos.qcow2 newcentos.qcow2   # 压缩镜像（原文 conver 为笔误）
```
