## 1. insert 插入

测试表:

```sql
create table test(
id int(4) not null AUTO_INCREMENT,
name char(20) not null,
primary key(id)
);
```

```sql
mysql> insert into test(id,name) value(1,'hequan');
mysql> select * from test;
mysql> insert into test(name) value('hequan');           -- id 是自增的,可以只插 name
mysql> insert into test value(3,'hequna'),(4,'hequan');  -- 不给列,直接按顺序插入
```

备份数据库,备份完用 grep 过滤注释检查一遍:

```shell
mysqldump -uroot -p123456 -B oldboy >/tmp/oldboy_bak.sql
grep -E -v "#|\/|^$|--" /tmp/oldboy_bak.sql
```

## 2. select 查询

基本套路:select ... from ... where

```sql
mysql> select id,name from test where name='hequan' and/or id=4;
mysql> select id,name from test limit 0,2;          -- 从第 0 行开始,查 2 行
mysql> select id,name from test where id>2 and id<4;
mysql> select id,name from test order by id asc/desc;
```

多表查询:

```sql
mysql> select student.Sno,student.Sname,course.Cname,SC.Grade from student,course,SC where student.Sno=SC.Sno and course.Cno=SC.Cno order by Sno;
```

用 explain 查看执行过程,判断有没有走索引:

```sql
mysql> explain select * from test where name='hequan'\G
```

```text
possible_keys: NULL
rows: 2
```

没有索引时 possible_keys 为 NULL。创建索引后再看:

```sql
mysql> create index index_name on test(name);
possible_keys: index_name
rows: 1
```

## 4. 增量恢复(binlog)

在 my.cnf 中打开:

```ini
log-bin=mysql-bin
```

binlog 文件位于 `/application/mysql/data/`,如 mysql-bin-hequan.000001。

```shell
mysqlbinlog mysql-bin-hequan.000001

mysqladmin -uroot -p123456 flush-log    # 切割日志,产生 mysql-bin-hequan.000002

mysqlbinlog -d oldboy mysql-bin-hequan.000001 > bin.sql
```

把 bin.sql 中错误的语句删除掉,再导入:

```shell
mysql -uroot -p123456 oldboy < bin.sql
```

binlog 只记录数据库的更改,不记录查询。

## 7. 乱码排查

统一字符集:改 /etc/my.cnf 共 3 处,重启服务。

系统环境:

```shell
cat /etc/sysconfig/i18n
LANG="zh_CN.UTF-8"
```

服务器端和客户端,vim /etc/my.cnf:

```ini
[client]
default-character-set=utf8

[mysqld]
character-set-server=utf8        # 5.5
# default-character-set=utf8    # 5.1 的写法

[mysql]
default-character-set=utf8
```

```sql
mysql> show variables like 'character_set%';
```

另外 SecureCRT 客户端也要更改为 utf8。

## 8. 数据库字符集

常用字符集:GBK、UTF-8、latin1。

```sql
mysql> show character set;
```

```text
+----------+-----------------------------+---------------------+--------+
| Charset  | Description                 | Default collation   | Maxlen |
+----------+-----------------------------+---------------------+--------+
| utf8     | UTF-8 Unicode               | utf8_general_ci     |      3 |
| gbk      | GBK Simplified Chinese      | gbk_chinese_ci      |      2 |
| latin1   | cp1252 West European        | latin1_swedish_ci   |      1 |
| utf8mb4  | UTF-8 Unicode               | utf8mb4_general_ci  |      4 |
+----------+-----------------------------+---------------------+--------+
```

字符集相关变量:

```sql
mysql> show variables like 'character_set%';
```

```text
+--------------------------+------------------------------------+
| Variable_name            | Value                              |
+--------------------------+------------------------------------+
| character_set_client     | utf8                    -- 客户端  |
| character_set_connection | utf8                    -- 链接    |

| character_set_filesystem | binary                              |

+--------------------------+------------------------------------+
```

临时生效:

```shell
mysql -uroot -p123456 --default-character-set=latin1
```

```sql
set names latin1;
```

## 9. 更改已有数据表的字符集,保留原有数据内容

环境:在应用开始阶段没有正确地设置字符集,在运行一段时间以后才发现存在不能满足需求需要调整,又不想丢弃这段时间的数据,那么就需要进行字符集的修改。字符集的修改不能直接通过 `alter database character set xxx` 或者 `alter table tablename character set xxx` 命令进行,这两个命令都没有更新已有记录的字符集,而只是对新创建的表或者记录生效。

那么已有记录的字符集调整,需要怎么操作呢?以下模拟的是将 latin1 字符集的数据库修改成 GBK 字符集的数据库的过程:

(1) 导出表结构:

```shell
mysqldump -uroot -p --default-character-set=gbk -d name > createdb.sql
```

其中 --default-character-set=gbk 表示设置以什么字符集连接,-d 表示只导出表结构,不导出数据。

(2) 手工修改 createdb.sql 中表结构定义中的字符集为新的字符集:

```shell
sed -i 's#latin1#gbk#g' createdb.sql
```

(3) 确保记录不再更新,导出所有记录:

```shell
mysqldump -uroot -p --quick --no-create-info --extended-insert --default-character-set=latin1 name > data.sql
```

- --quick:该选项用于转储大的表。它强制 mysqldump 从服务器一次一行地检索表中的行,而不是检索所有的行并在输出前将它缓存在内存中
- --extended-insert:使用包括几个 values 列表的多行 insert 语法,这样使转储文件更小,重载文件更快
- --no-create-info:不写重新创建每个转储表的 create table 语句
- --default-character-set=latin1:按照原有的字符集导出所有数据,这样导出的文件中,所有中文都是可见的,不会变成乱码

(4) 打开 data.sql,将 SET NAMES latin1 修改成 SET NAMES gbk。

(5) 使用新的字符集创建新的数据库:

```sql
create database newdatabasename default charset gbk;
```

(6) 创建表,执行 createdb.sql:

```shell
mysql -uroot -p newdatabasename < createdb.sql
```

(7) 导入数据,执行 data.sql:

```shell
mysql -uroot -p newdatabasename < data.sql
```

(8) 查看之前,确认本地环境是不是都改成了 gbk 模式,可以用临时更改来测试:

```sql
set names gbk;
```
