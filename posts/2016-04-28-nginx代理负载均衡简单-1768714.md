> **内容介绍**
>
> 本文演示用 Nginx 做反向代理负载均衡:源码编译安装 nginx 1.10.0(启用 stub_status、
> ssl 模块并软链到 /application/nginx),在 nginx.conf 的 http 段定义 upstream backend
> 指向两台后端(max_fails/fail_timeout 健康检查参数),server 段用 proxy_pass 转发,
> 并以 for 循环 curl 验证轮询效果与单机宕机后自动摘除;文末比较 ip_hash、session 复制、
> memcache 共享、cookie+session 四种会话保持思路。

> **技术备注**
>
> Nginx 配置在不同大版本间略有差异,建议以当前稳定版(1.24+/1.26+)官方文档为准。
> 补充:文中 1.10.0 版本已停止维护,现行稳定版 upstream/proxy_pass 语法仍兼容本文;
> ip_hash 在多机房、客户端走代理等场景下分布不均,更通用的做法是 sticky 会话或
> Redis 等集中共享 session。

## 1. 编译安装 nginx

```shell
wget http://nginx.org/download/nginx-1.10.0.tar.gz
tar xf nginx-1.10.0.tar.gz
cd nginx-1.10.0

./configure --user=nginx --group=nginx \
    --prefix=/application/nginx.1.10.0 \
    --with-http_stub_status_module \
    --with-http_ssl_module

make
make install

ln -s /application/nginx.1.10.0/ /application/nginx
useradd nginx -s /sbin/nologin -M

/application/nginx/sbin/nginx -t     # 检查语法
/application/nginx/sbin/nginx        # 启动

egrep -v "#|^$" nginx.conf.default > nginx.conf   # 去掉注释生成精简配置
```

## 2. 配置负载均衡

```nginx
# vim nginx.conf
http {
    upstream backend {
        ip_hash;    # 登陆后,始终在一台服务器
        server 192.168.10.11:80  max_fails=3 fail_timeout=30s;
        server 192.168.10.16:80  max_fails=3 fail_timeout=30s;
    }

    server {
        listen       80;
        server_name  ;
        index        index.html index.htm;

        location / {
            proxy_pass http://backend;
        }
    }
}
```

这个时候打开 192.168.10.10,就是**轮询(rr)**的方式,访问 11 和 16 了。

## 4. 会话保持的几种思路

每个服务器都把登陆信息写到本地,会影响到用户登陆,出现来回登陆的情况:

- **lb 层做会话保持**(小流量可以):加入 `ip_hash;`,登陆后始终在一台服务器
- **软件层 session 复制**
- **共享存储**,例如 memcache
- **cookies 配合 session**,把用户级会话信息缓存在用户本地
