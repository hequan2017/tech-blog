## 1. 备份与恢复基本命令

```shell
mysqldump -uroot -p123456 --default-character-set=utf8 quan > /opt/quan.sql    # 备份
grep -Ev "#|\/|--|^$" quan.sql    # 查看文件内容(过滤注释与空行)
```

备份文件中的关键语句:

```sql
DROP TABLE IF EXISTS `test`;    # 删除老的表
LOCK TABLES `test` WRITE;       # 锁
UNLOCK TABLES;                  # 解锁
```

```shell
mysql -uroot -p123456 quan < /opt/quan.sql    # 恢复
```

备份时加 -B 会多出下面两行(建库、进入库):

```sql
CREATE DATABASE /*!32312 IF NOT EXISTS*/ `quan` /*!40100 DEFAULT CHARACTER SET gbk */;
USE `quan`;
```

恢复时不用先建库,直接恢复就行:

```shell
mysql -uroot -p123456 < /opt/quan_B.sql
```

debug 调试可用 `--compact`:减少输出注释、优化备份大小、不添加锁。

## 2. 压缩备份与多库/多表备份

```shell
mysqldump -uroot -p123456 quan | gzip > /opt/quan.sql.gz    # 压缩备份
gunzip quan.sql.gz    # 解压,再恢复
```

--databases, -B:用于备份多个数据库。如果没有该选项,mysqldump 把第一个名字参数作为数据库名,后面的作为表名;使用该选项,mysqldump 把每个名字都当作数据库名。

```shell
mysqldump -uroot -p123456 -B quan he | gzip > /opt/quan.sql.gz       # 备份多个库
mysqldump -uroot -p123456 quan test test1 | gzip > /opt/quan.sql.gz  # 备份库里的表
```

## 3. 分库备份命令

先生成分库备份命令(打印不执行):

```shell
mysql -uroot -p123456 -e "show databases;" | grep -Evi "database|infor|perfor" | sed 's#^#mysqldump -uroot -p123456 -B #g'
```

加上 `| bash` 直接执行,每个库单独打包:

```shell
mysql -uroot -p123456 -e "show databases;" | grep -Evi "database|infor|perfor" | sed -r 's#^([a-z].*$)#mysqldump -uroot -p123456 -B \1 | gzip > /opt/\1.sql.gz#g' | bash
```

## 4. 脚本循环分库备份

```shell
#!/bin/bash
for name in `mysql -uroot -p123456 -e "show databases;" | grep -Evi "database|infor|perfor"`
do
mysqldump -uroot -p123456 --events --ignore-table=mysql.event -B $name | gzip > /opt/${name}.sql.gz
done
```

## 5. 表结构 / 数据 / 全库备份

```shell
mysqldump -uroot -p123456 -d quan > /opt/quan1.sql    # --no-data, -d:只导出表结构
mysqldump -uroot -p123456 -t quan > /opt/quan1.sql    # -t = --no-create-info,只备份数据
```

- 导出全部数据库:`--all-databases`, -A
- 导出全部表空间:`--all-tablespaces`, -Y

```shell
mysqldump -uroot -p123456 -A -B --events > /opt/quan1.sql    # 备份整个数据库
```

mysql 全量导出时碰到如下告警(默认是不备份事件表的,只有加了 --events 才不会警告):

```text
Warning: Skipping the data of table mysql.event. Specify the --events option explicitly
```

解决办法:`--events --ignore-table=mysql.event`。

## 6. binlog 相关

```ini
# vim /etc/my.cnf
#log-bin=mysql-bin    # 注释掉即关闭
```

binlog 文件位于数据目录,如 mysql/data/mysql-bin.000001。

- mysqldump `-F`:刷新 bin-log 日志
- `--master-data=2`/1:在备份文件中增加 binlog 的日志文件名及对应的位置点(2 为注释形式,1 为可执行形式)

先用时把 my.cnf [client] 段的 `default-character-set=utf8` 注释掉,再查看:

```shell
mysqlbinlog /application/mysql/data/mysql-bin.000001
```


## 8. 恢复方式与免密登录

方式一,登录后 source:

```sql
use quan;
mysql> source /root/quan.sql
```

方式二,标准输入重定向:

```shell
mysql -uroot -p123456 hequan < /opt/hequan.sql
```

设置免密登录,写入 `~/.my.cnf`:

```ini
[client]
user=root
host=localhost
password=123456
```

## 9. 批量恢复分库文件

```shell
for name in `ls *.sql | sed 's#.sql##g'`; do mysql -uroot -p123456 < ${name}.sql; done
```

## 10. ERROR 1046 排查

```text
ERROR 1046 (3D000) at line 22: No database selected
```

原因:恢复的 SQL 文件里没有指定库。解决办法:修改 .sql 文件,在第 22 行前面加上 `use 库名;`。
