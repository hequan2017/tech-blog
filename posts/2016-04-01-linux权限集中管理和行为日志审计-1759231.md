> **内容介绍**
>
> 本文围绕"服务器用户权限集中管理与操作行为日志审计"这一运维项目展开：先梳理 useradd/usermod/passwd/chage/sudo 等账号权限管理命令，再给出批量建用户的 shell 脚本与 sudoers 配置要点（别名、白名单、命令全路径），最后落地 sudo 操作日志记录（sudo logfile + rsyslog），并提到日志集中收集可选 scribe/Flume/Logstash/Kibana 等方案。

> **技术备注**
>
> 文中组件在 2026 年的现状：`passwd --stdin` 在 RHEL 8+/Rocky 9 中已被移除，改用 `chpasswd`；rsyslog 仍是主流但多数发行版默认日志已转向 systemd-journald；sudo 1.9+ 支持 `log_subcmds` 和集中式 `sudo_logsrvd` 日志服务；scribe/storm 方案早已淘汰，日志收集主流为 ELK/EFK（Elasticsearch+Fluent Bit+Kibana）或 Loki+Grafana。CentOS 6/7 均已 EOL。

## 1. 账号与权限管理命令速查

```shell
useradd  -g 主组 -u UID -c 注释 -s shell -d 家目录 -G 附加组 -M 不建家目录
useradd  -D          # 查看/改变默认属性
userdel  -r 用户名   # 删除用户并连同家目录一起删除
usermod              # 修改已有用户属性
groupadd / groupdel  # 添加/删除用户组

passwd --stdin       # 从标准输入读入密码（批量改密码用；注：RHEL 8+ 已移除该选项，改用 chpasswd）
chage -l 用户名      # 查看密码过期属性
chage -E 日期 用户名 # 设置账号过期时间

su - 用户名          # 切换用户并加载其环境变量
su - 用户名 -c "命令" # 以该用户身份执行命令后退回当前用户

newgrp 组名          # 切换当前有效组
id 用户名            # 查看用户 UID/GID/所属组
w / who / last / lastlog / whoami / finger   # 登录用户与历史行为审计
```

## 2. 批量创建用户脚本

```shell
for user in aaa bbb ccc
do
    useradd $user
    echo "123123" | passwd --stdin $user > /dev/null 2>&1   # 非交互设置初始密码
done
```

> 注：新版本系统请改写为 `echo "$user:123123" | chpasswd`。

## 3. sudo 权限集中管理

sudo 让普通用户在授权范围内获得 root 权限，配置文件必须通过 `visudo` 编辑（带语法检查）。

sudoers 书写要点：

- 命令必须写**绝对路径**（可用 `which` 查询）。
- 别名（Alias）名称**字母大写**，一行写不下用 `\` 换行。
- 授权格式：`用户 主机=(以谁的身份执行) 命令`，缺省身份为 root，`(ALL)` 表示任意身份。
- `%组名` 表示对用户组授权；`!命令` 表示禁止该命令（白名单机制）。
- 采用**白名单思路**：只放行确需的命令，而不是放行全部再黑名单排除（原文"白名单机智"为"机制"之笔误）。

```shell
sudo -l    # 查看当前用户被授权的 sudo 命令
```

## 4. sudo 操作日志审计

确认组件已安装：

```shell
rpm -aq | egrep "sudo|rsyslog"
# sudo-1.8.6p3-12.el6.x86_64
# rsyslog-5.8.10-8.el6.x86_64
```

方式一：让 sudo 自己写日志文件（原文 "suo命令日志" 为"sudo命令日志"之笔误）：

```shell
echo "Defaults  logfile=/var/log/sudo.log" >> /etc/sudoers
visudo -c          # 校验 sudoers 语法
# /etc/sudoers：解析正确
```

方式二：通过 rsyslog 收集 sudo 日志：

```shell
echo "local2.debug   /var/log/sudo.log" >> /etc/rsyslog.conf
/etc/init.d/rsyslog restart      # CentOS 6 写法；CentOS 7+ 用 systemctl restart rsyslog
ll /var/log/sudo.log
# -rw------- 1 root root 0 3月  27 20:45 /var/log/sudo.log
```

## 5. 日志集中收集方案

单机的日志可以用 `rsync + inotify` 实时同步到日志服务器，或直接由 rsyslog 远程转发。分布式日志收集可选：

- 早期方案：scribe、Flume、Storm（原文 "kibanan" 为 Kibana 笔误）——这些在 2026 年均已被淘汰或边缘化。
- 当前主流：Logstash/Fluent Bit + Elasticsearch + Kibana（ELK/EFK），或轻量的 Loki + Grafana。

## 6. 项目实施方法论（原文要点）

权限管理改造不是单纯敲命令，而是一个完整项目，核心思路是**最小化**：软件安装最小化、目录/文件权限最小化、用户权限最小化、程序运行权限最小化。

流程：提出问题 → 写好方案与规划文档 → 讨论可行性 → 汇总提交审核 → 确定方案 → 实施部署 → 总结维护，同时做好培训与文档沉淀，整个流程规范化管理。
